## 문제

옛 모델은 파티 능력 넷을 **저장**했고 그중 셋이 썩었다(부록 Z-4):

| 필드 | 상태 |
|---|---|
| `magicTorch` | 산다 |
| `walkOnWater` | **읽는 쪽만 산다** — 세우는 곳이 코드에도 cm2 에도 없어 값이 0 을 못 벗어난다 |
| `levitation` | 세우지만 규칙이 안 읽는다 |
| `walkOnSwamp` | 아무도 안 쓴다 |

저장했기 때문이다. 함수는 이렇게 썩지 않는다 — 부적을 지우면 다음 호출에서 답이 바뀐다.

## 무엇을 했나

**계산되는 것을 저장하지 않는다.** 네 가지가 전부 함수다.

| 무엇 | 어디서 | 무엇을 읽나 |
|---|---|---|
| 무기 종류 15 | `weaponKindFor(right:, left:)` | 두 손 |
| 최종 수치 20종 | `resolveStats` | 인물 + 착용 + 카탈로그 |
| 통행 능력 | `readAbilities` | 파티 전원의 착용 |
| 어둠 속 시야 | `lightInDarkness` | 횃불 든 사람 수 + 마법 |

### 백분율은 소계에 걸린다

더하기가 먼저 들어가고 백분율은 **그 소계**에 걸린다. 그래서 10% 부적 둘이 20% 이고
21% 가 아니며, **장착 순서가 답을 바꿀 수 없다.** 곱해 쌓으면 순서가 의미를 갖는데,
그것을 설명할 화면은 없다.

### 잠긴 손은 아무것도 내지 않는다

오른손이 양손 무기면 왼손에 무엇이 기록돼 있어도 계산에서 뺀다. 옛 세이브에서 그 상태가
올라올 수 있고, 그때 자격 규칙과 합성 규칙이 다른 말을 하면 안 된다.

### 겹치는 것은 불뿐이다

부적은 둘째부터 아무 일도 안 하고 횃불은 **든 사람 수만큼 밝아진다.**
그 비대칭이 횃불을 개인 결정으로, 부적을 파티 결정으로 만든다.

| 횃불 | 시야 | 먼 타일 |
|---|---|---|
| 0 | 1 | 검다 |
| 1 | 3 | 검다 |
| 2 | 4 | 흐리게 보인다 |
| 3 이상 | 5 | 흐리게 보인다 |

마법의 횃불은 **2** 다. 손을 안 쓰는 대신 그렇다. 둘 중 큰 값을 쓰고 더하지 않는다.

### 통행 능력이 파티 전체인 이유

**공통 부적이라서가 아니다.** 지도 위에서 파티는 말 하나이고, 한 사람만 물 위를
걷고 나머지는 못 걷는 상태를 그릴 방법이 없다. 그래서 `Capability.isPartyWide` 가
능력의 속성이고 슬롯의 속성이 아니다.

쓰러진 사람이 차고 있어도 유효하다. 호수 한가운데서 능력을 잃는 규칙은 두지 않는다.

## 완료 판정 기준

- [x] 인물에 파생 필드가 없다 (purity 테스트가 이름으로 확인)
- [x] 백분율 순서 무관, 10+10 = 20
- [x] 잠긴 손이 방어·차단·무기 종류에 기여하지 않는다
- [x] 밝기 표 0·1·2·3 → 1·3·4·5, 달빛은 2부터
- [x] 마법 < 실제 횃불 하나 (수치로)
- [x] 부적은 겹쳐도 같고 횃불은 다르다
