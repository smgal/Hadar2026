# W1-05 OpenAPI 표면과 마우스 화면

- **상태**: DONE (2026-09-08)
- **구간**: W1 ([_README](_README.md))
- **규모**: L
- **선행**: [W1-03](W1-03-derived-values.md)

## 문제

**터미널로는 장비를 시험할 수 없다.** 전투는 「1) 공격 2) 기술 …」처럼 한 번에 한
물음이라 콘솔이 맞았다. 장비는 부위 여덟이 동시에 보여야 하고(왼손을 채우면 오른손이
잠긴다), 고칠 때마다 최종 수치가 다시 계산되며, 후보가 스무 개를 넘는다.

## 무엇을 했나

`hd_world_lab` — `dart:io` HTTP 서버 하나에 두 클라이언트.

| 누가 | 어떻게 |
|---|---|
| 사람 | `GET /` 의 장비 화면. 마우스로 사람 → 부위 → 채울 것 |
| 스크립트 | `POST /api/command`. JSON |
| 에이전트 | `GET /api/guide` 를 먼저 읽고 같은 명령 |

**서버는 규칙을 하나도 갖지 않는다.** 모델이 이미 명령과 사실로 말하므로 해석해
넘기고 이벤트와 새 상태를 그대로 싣는다.

### 한 번의 왕복

`POST /api/command` 가 `events` · `refused` · **새 상태 전부**를 함께 준다.
바꾼 뒤 다시 읽을 필요가 없다.

### 거절도 200 이다

`kind: refused` 이벤트에 닫힌 열거 `reason` 이 실린다. **400 은 JSON 을 읽을 수
없을 때만**이고, 그때는 어느 칸이 틀렸는지와 **고를 수 있는 값**을 준다:

```json
{"error":"unknown value","field":"slot",
 "allowed":["rightHand","leftHand","body","head","legs",
            "commonAmulet","classAmulet1","classAmulet2"]}
```

묶음(`/api/commands`)은 **해석을 전부 먼저** 한다. 한 항목이라도 읽히지 않으면
아무것도 적용하지 않는다 — 반쯤 바뀐 세계를 만들지 않는다.

### 화면은 한국어를 갖지 않는다

`GET /api/text` 를 한 번 받아 전부 거기서 찾는다. 그래서 이름이 화면과 터미널에서
갈릴 수 없다 — `hd_battle_text` 가 전투에 대해 지키는 것과 같은 규칙이다.

### 규격과 안내를 따로 둔다

`tools/mapEditor` 가 이미 하던 것이다. `openapi.yaml` 은 필드를 말하고
`GET /api/guide` 는 **뜻**을 말한다 — 무엇을 눌러 보면 무엇이 보이는지까지.

## 왜 별도 FE 인가 (Flutter 실험실이 아니라)

전투 실험실은 `hadar2026_app` 안의 진입점이라 Flutter SDK 와 앱 전체를 끌고 온다.
장비는 앱을 하나도 필요로 하지 않으므로 그 의존을 만들 이유가 없다. **판정의 요점이
독립성**이라, 시험 도구가 앱을 요구하면 그 요점이 흐려진다.

## 그 뒤에 (2026-09-13)

이 이슈는 **닫힌 그대로 둔다.** 위 기록은 2026-09-08 에 무엇을 왜 했는지이고,
아래는 그 위에 무엇이 더 얹혔는지다.

### 화면이 글자에서 아이콘으로 바뀌었다

첫 판은 줄글이었다. 한 줄에 이름·보정·까닭을 적으니 부위 여덟이 세로로 길어져
**동시에 보여야 한다**는 이 이슈의 전제가 깨졌고, 무엇이 되고 무엇이 안 되는지는
눌러 봐야 알았다.

지금은 칸 하나가 물건 하나이고 **모양이 무엇인지를, 색이 지금 어떤지를** 말한다.
물건을 집으면 다섯 사람 × 부위 여덟이 초록·빨강으로 갈린다 — 그러려면
`checkEquip` 의 답이 마흔 칸 분량으로 미리 와 있어야 해서 `GET /api/eligibility`
가 생겼다. **빨강과 회색은 다른 색이다** — 이 이슈가 지키려던 구분(자리가 틀린
것과 직업이 틀린 것은 다른 문장이다)이 색까지 내려온 것이다.

### 탭이 다섯이 되었다

| 탭 | 더해진 것 |
|---|---|
| 장비 · 가방 | `GET /api/eligibility` · `POST /api/preview` · `/api/loadouts` |
| **전투** | `POST /api/battle/{start,command,settle,abandon}` · `GET /api/enemies` |
| **플래그** | `GET/POST /api/quest` · `lib/quest/` |
| 기록 | `GET /api/save` · `POST /api/load` |

- `POST /api/preview` — 사본에 굴려 차이만. 사본은 `saveWorld`→`loadWorld`
  왕복이다(저장 형식이 곧 복사가 실어야 할 것의 정의라 목록을 두 번 쓰지 않는다).
- 전투 탭은 격자이고 **y 축이 거리**다 — `거리 = 간격 + (내 열-1) + (상대 열-1)`
  을 그대로 그린다. 물음마다 멈추고 마우스로 답한다.
- 세이브에 **장비와 플래그가 같이** 간다(`hd_world` 저장 형식 + `quest` 한 칸).

### 플래그 표는 새 물건이다

`lib/quest/flag_registry.dart` — 번호에 **뜻**을 붙인다. 런타임이 아니라 저작
자료이고, `test/quest_registry_test.dart` 가 `flag4ep1.cm2` 와 출하 `*.cm2`
전량을 실제로 열어 맞춘다.

**그 표가 번호 충돌 셋을 찾아냈다(10 · 31 · 50)** — `lore_ep1.cm2` ·
`town2.cm2` · `menace.cm2` 가 `flag4ep1.cm2` 를 include 하지 않고 번호를 직접
쓴다. 이름이 아예 없는 칸도 여섯이다(32 · 51~55). **아직 고치지 않았다** —
겹침이 실제로 도달 가능한지 확인이 먼저고, 번호를 옮기면 기존 세이브가 깨진다.

### 곁들여 고친 것

`hd_bridge` 가 자기 계약을 어기고 있었다. `BattleSetup.weaponName` 은 규격이
「풀어 놓은 표시 이름」 이라고 적어 두었는데 참조가 그대로 가서 전투 메뉴가
`⚔ 공격 — weapon.sabre로` 로 나왔다. `toBattleSetup(itemName:)` 으로 해석
함수를 받게 했다 — 다리도 전투도 한국어를 가질 수 없으므로 아는 쪽이 넘긴다.

시험: `hd_world_lab` 65개(HTTP 47 + 플래그 표 18) · `hd_bridge` 21개.
