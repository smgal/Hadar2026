# W1-09 앱 교체 — 포트 뒤에서 옛 모델을 뺀다

- **상태**: DONE (2026-09-09)
- **구간**: W1 ([_README](_README.md))
- **규모**: L
- **선행**: W1-06 · W1-07 · W1-08

## 문제

두 모델이 공존하는 동안이 이 구간에서 가장 위험한 지점이다(10차 판정의 「틀릴 수 있는
지점」). 어느 쪽이 정본인지 흐려지고, 고칠 때 양쪽을 고쳐야 한다.

## 무엇을 할 것인가

`application/ports/` 뒤에서 갈아 끼운다. **`presentation/` 은 손대지 않는다** —
겉이 그대로 보여야 한다는 것이 판정의 조건이었다.

| 뺄 것 | 줄 |
|---|---|
| `domain/party/player.dart` | 735 |
| `domain/party/party.dart` (버프 부분) | 368 중 일부 |
| `domain/item/*` | 약 640 |
| `application/equipment_flow.dart` · 장비 화면 흐름 | 약 300 |

그리고 **장비 화면을 800×480 안에 다시 짠다.** 여덟 칸은 지금의 세 단계 메뉴
(인물 → 부위 → 후보)로는 좁다. 실험실 화면이 무엇이 필요한지 이미 보여 준다.

## 순서

1. 새 모델을 포트 뒤에 넣고 **읽기만** 시킨다 (상태 화면이 새 값을 보인다)
2. cm2 어댑터를 새 모델로 돌린다
3. 장비 화면을 교체한다
4. 옛 파일을 지운다 — **B4-03 이 `battle.dart` 에 한 것과 같은 마무리**

## 무엇을 했나

`presentation/` 의 결합이 **두 곳뿐**이었다 — 상태 패널(이름·체력·지수)과
마법 창(레벨). `HDPlayerSprite` 는 이름만 비슷한 다른 클래스였다. 그래서 겉을
거의 손대지 않고 안을 갈아 끼울 수 있었다.

### 감싸는 클래스를 만들지 않았다

`HDPlayer` 를 `Member` 위의 view 로 두는 길이 있었지만 **신원이 둘이 된다** —
이전 모델이 그렇게 해서 세이브와 갈렸다. 대신 `Member` 를 직접 쓰고 표시에
필요한 것만 앱 쪽 **확장**(`member_display.dart`)으로 붙였다.

### 지운 것

| | 줄 |
|---|---|
| `domain/party/player.dart` | 735 |
| `domain/item/*` (7 파일) | 약 640 |
| `application/equipment_flow.dart` | 약 130 |
| `application/battle_bridge/setup_assembly.dart` · `weapon_mapping.dart` | 약 280 |
| `application/battle.dart` · `domain/battle/enemy.dart` · `enemy_data.dart` (B4-03) | 809 |
| 옛 모델을 시험하던 테스트 12 파일 | 약 1,700 |

### 자리 번호가 곧 신원이다

빈 자리를 **뒤로 몰지 않는다.** 출하 스크립트가 여섯째 자리를 미리 손보므로
(`menace.cm2:45`) 몰면 cm2 가 가리키는 사람이 바뀐다. 내보낸 사람은 이름만
비고 자리에 남는다.

### 장비 화면이 여덟 칸이 되었다

부위마다 한 줄이고, 잠긴 칸은 **글자로 이유를 말한다** — 콘솔에서 회색으로 둘 수
없으므로. 거절 이유는 `hd_world_text` 의 문장이고 **자리 오류와 직업 오류가 다른
문장**이다.

가방은 `{물건: 개수}` 라 같은 것이 한 줄이다. 이전 모델은 20칸 배열이라 단도가
스무 줄 나올 수 있었다.

### 상태 화면이 「왜 되는지」를 말한다

통행 능력이 부적에서 오는지 마법에서 오는지 적는다. 숫자만 찍으면
`물위를 걸음 : 0` 이 「부적을 차고 있는데 0」 인지 알 수 없다.
