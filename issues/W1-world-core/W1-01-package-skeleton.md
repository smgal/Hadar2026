## 문제

전투를 다시 쓸 때 성공의 절반은 **`hd_battle` 이 아무것도 참조하지 않는다**는 규칙이었다.
그 규칙이 없으면 되붙이기가 다시 어려워지고, 규칙을 문서로만 두면 지켜지지 않는다.

## 무엇을 했나

패키지 셋 — 모델 · 이름표 · 실험실. 그리고 **막는 것을 코드로 두었다.**

`packages/hd_world/test/flow/purity_test.dart` 가 주석을 걷어내고 확인한다:

| 막는 것 | 왜 |
|---|---|
| `package:flutter` | 화면을 갈아끼울 수 있어야 한다 |
| 이 레포의 다른 패키지 전부 | 전투·앱·cm2 가 밖에서 이쪽에 맞춘다 |
| `dart:io` · `dart:isolate` · `dart:ffi` | 파일도 소켓도 만지지 않는다 |
| `DateTime.now` | 시계를 읽으면 재현이 안 된다 |
| `print` | 모델이 콘솔을 가정하면 안 된다 |
| 시드 없는 `Random()` | 재현 불가의 원인이었다 |
| 한국어 · emoji | 문장은 화면의 것이다 |
| 파생값을 인물에 저장하는 것 | 옛 `PartyBuffs` 가 썩은 방식이다 |

마지막 줄이 이 구간 특유의 것이다 — `member.dart` 에 `weaponKind` · `walkOnWater` ·
`magicTorch` 같은 **필드 이름이 다시 나타나면 실패**한다.

CI 에 `hd_world` job 을 더했다. import 만 보는 빠른 실패 grep + OpenAPI 파싱 확인.

## 왜 `dart:io` 까지 막았나

`hd_battle` 은 막지 않았다. 여기서 막은 이유는 실험실이 서버이기 때문이다 —
모델에 파일 읽기가 한 줄 들어가면 그 다음은 설정 파일이고, 그러면 테스트가
디스크를 필요로 하기 시작한다. 실험실 쪽(`hd_world_lab`)은 자유롭게 쓴다.
