# [S1-99] 저작 중 막힌 지점을 기록한다 (S2 의 유일한 입력)

- **상태**: TODO · **구간**: S1 · **규모**: S · **선행**: [S1-01](S1-01-quest-design.md)
- **설계 근거**: [MILESTONES §3](../MILESTONES.md) · [DECISION-LOG 2차 판정](../DECISION-LOG.md) ·
  [BOARD 의 P0 백로그 표](../BOARD.md)

## 문제

1차 판정은 **작동하는 사례를 찾아보지 않고** 결함 목록에서 "그래서 불가능하다" 를 연역했다
([DECISION-LOG](../DECISION-LOG.md) "내가 왜 틀렸나"). 레포에 2,441줄의 반례가 있었는데 읽지 않았다.
같은 실수를 반복하지 않는 유일한 방법은 **실제로 만들어 보고 걸린 것만 적는 것**이다.

이 파일은 [S2](../BOARD.md) 의 **유일한 입력**이다. 여기 적히지 않은 문제는 S2 에서 만들지 않는다.

## 왜 지금 해야 하는가

S2-01~04 네 이슈가 전부 `BLOCKED / 선행 = S1-99` 다([BOARD](../BOARD.md)). 이 표가 채워지기 전에는
S2 를 착수할 근거가 없다. 반대로 이 표가 채워지면 S2 의 범위가 **자동으로 확정**된다.

## 무엇을 할 것인가

### 1. 기록 양식 — 마찰이 생길 때마다 한 행을 추가한다

| # | 무엇을 하려다 | 무엇이 막았나 (관측된 증상) | 어떻게 우회했나 | 재발 빈도 | S2 후보 이슈 |
|---|---|---|---|---|---|
| 1 | | | | 1회 / 반복 / 상시 | |
| 2 | | | | | |
| 3 | | | | | |

**작성 규칙**

- **증상을 적는다. 원인 추정을 적지 않는다.** `NPC 가 초기 대사만 반복했다` (○) / `플래그가 꼬인 듯` (×).
- 우회에 걸린 **시간**과 **재발 빈도**를 반드시 적는다. S2 의 우선순위는 빈도로 정한다.
- 재발 빈도가 `1회` 이고 우회가 5분 안에 끝났으면 **S2 후보가 아니다.** 빈칸으로 둔다.
- 코드를 고쳐서 넘어간 항목이 있으면 **그것은 규칙 위반**이다. 되돌리고 데이터로 우회한 뒤 기록한다.
- 이미 `GROUND_TRUTH` 부록으로 검증된 것에 물렸으면 **부록 ID 를 적는다** — 새 발견이 아니라
  [BOARD 의 P0 백로그](../BOARD.md) 를 끌어올 신호다.

### 2. 예상 걸림돌 — **가설**이다. 확인란을 채운다

[MILESTONES §3](../MILESTONES.md) 이 예상한 4개를 그대로 옮긴다. **겪지 않았으면 S2 에서 지운다.**

| 가설 | 예상 증상 | S1 이 실제로 겪었나 | 근거 (이슈·행 번호) | 판정 |
|---|---|---|---|---|
| **H1 · 플래그 인덱스 수동 할당** — 256칸을 손으로 배분. AI 생성 시 충돌이 조용히 상태를 망친다 | 두 퀘스트가 같은 칸을 써서 한쪽 진행이 저절로 완료됨 | ☐ 예 ☐ 아니오 | | ☐ [S2-01](../S2-enablers/S2-01-flag-registry.md) 진행 ☐ 삭제 |
| **H2 · 한 맵에 퀘스트 여러 개** — cm2 는 맵당 1개. `include` 는 init 전용이라 per-tile 핸들러를 못 담는다 | 두 번째 퀘스트를 같은 맵에 넣을 자리가 없음 | ☐ 예 ☐ 아니오 | | ☐ [S2-02](../S2-enablers/S2-02-cm2-override-chain.md) 진행 ☐ 삭제 |

| **H4 · 좌표 ↔ NPC 배치** — `On(x,y)` 가 좌표 하드코딩. 맵을 고치면 깨진다 | 맵 에디터로 NPC 를 한 칸 옮겼더니 대사가 사라짐 | ☐ 예 ☐ 아니오 | | ☐ [S2-04](../S2-enablers/S2-04-map-editor-cm2-support.md) 진행 ☐ 삭제 |

- **H1 은 이미 물증이 하나 있다.** `hadar2026_app/assets/flag4ep1.cm2:42-43` 이
  `variable(GFD1_OPEN_DOWN_STAIRS)` 를 선언한 뒤 **다른 상수에 대입**한다(`GFD1_OPEN_ODD_WALL.assign(15)`).
  `packages/cm2_script/lib/src/cm2_script.dart:160` 이 미대입 변수를 **0** 으로 두므로 이 상수는
  `GFD0_IS_FIRST`(=0)와 **같은 칸**이고, `L1_ep1d1.cm2:176,349` 가 그 칸을 읽고 쓴다.
  이것은 **S1 이 만든 문제가 아니라 기존 데이터에 이미 있던 것**이다 — 그러므로 "S1 이 겪었나" 는
  **여전히 별도로 판정해야 한다**(가설의 증거이지 실측 마찰이 아니다).

## 완료 판정 기준

- [ ] §1 의 표가 채워졌다 (마찰이 0건이면 "0건" 을 명시하고 그 사실 자체를 기록한다)
- [ ] §2 의 가설 4개가 **각각** `예/아니오` 로 판정되었고, S2 이슈 4개의 상태가 각각
      **진행 또는 삭제로 확정**되었다 — [BOARD](../BOARD.md) 의 S2 표도 같은 값으로 갱신되었다
- [ ] §3 의 P0 6행이 전부 표시되었다
- [ ] §4 에 "겪지 않은 것" 이 최소 1건 적혀 있다 (전부 겪었다면 그 사실을 적는다)

## 하지 않을 것

- **S1 이 겪지 않은 문제를 S2 에서 만들지 않는다.** 이것이 이 파일의 존재 이유다.
- 원인 분석·설계·수리 방안 작성. S2 이슈가 할 일이다. 여기는 **증상과 빈도**만 담는다.
- 코드 변경. 문서 정정도 이 이슈에서는 하지 않는다(§5 는 후보 목록일 뿐이다).
