# B2-09 속성 상성이 작동한다

- **상태**: DONE
- **구간**: B2 — **잠정 항목** ([_README](_README.md))
- **성격**: **판단** (완료) — 원작에 속성 개념이 없다. **이식 원본이 없으므로 설계한다.**
- **규모**: L
- **선행**: B1 전체 · [B2-01](B2-01-magic-effects.md)
- **설계 근거**: [MILESTONES §7](../MILESTONES.md) · [DECISION-LOG 4차 판정](../DECISION-LOG.md)

## 문제

속성 개념이 **레포 전체에 없다.** `domain/item/item.dart` 의 `param` 은 `attaPow`·`ac`·`itemType`
뿐이고, `domain/battle/enemy_data.dart` 의 11개 필드에도 속성이 없다.
그래서 `초냉기`와 `열선 파동`이 어떤 적에게든 같게 작동한다.

## ⚠ 이 항목만 B3 의 작업량을 늘린다

전투가 자기 테이블을 가지므로 속성 추가 자체는 전투 내부에서 끝난다. 그런데 B3 에서
`RPG 아이템 → 전투 아이템` 변환이 **RPG 에 없는 정보를 채워야** 한다. 선택지는 둘이다.

| 갈래 | 결과 |
|---|---|
| RPG 아이템·적 정의에 속성을 추가한다 | 4차 판정이 말한 "RPG mode 도 확장" 이 실제로 이것이 된다 → [B3-03](../B3-battle-integrate/B3-03-rpg-attributes.md) |
| 변환 시 기본 속성으로 채운다 | 제대로 만든 상성이 붙으면서 반쪽만 살아남는다 |

**전자를 택했다**(4차 판정). B3-03 이 그 작업이다.

## 결과 (2026-09-05)

`packages/hd_battle/lib/src/rules/affinity.dart`.

**원작에 속성이 없다.** 그래서 설계했고, **얇게** 유지했다 — RPG 로 건너가야 하는 것이라
넓을수록 B3-03 이 커진다.

- 속성 7종 (`none` 포함). 마법 18종 중 **9종만** 속성을 갖는다 —
  이름이 분명한 것만 붙였다 (`초냉기` 는 냉기, `마법 화살` 은 무속성)
- 적 상성은 **손으로 21종만** 적었다. 나머지는 상성이 없다.
  생물이 무엇인지로 정했다 — 언데드는 독을 무시하고, 불로 된 것은 냉기를 싫어한다
- 약점 ×2, 저항 ÷2

표가 얇은 것이 정직한 것이다 — 얼마나 많은 부분이 창작인지 표 자체가 보여준다.

**B3-03 은 여전히 필요하다.** RPG 쪽 아이템·적 정의에 속성이 없으므로,
되붙일 때 그쪽에 심어야 한다. 그것이 4차 판정이 말한 "RPG mode 도 확장" 의 첫 항목이다.

## 완료 판정 기준

- [x] 아이템·적·마법이 속성을 갖고, 상성표가 피해량을 바꾼다
- [x] 같은 마법이 속성이 다른 적에게 다른 피해를 준다
- [x] 상성표가 데이터이고 코드에 흩어져 있지 않다
      → `packages/hd_battle/test/rules/affinity_test.dart`

## 하지 않을 것

RPG 쪽 속성 추가(B3-03) · 속성 저항 장비 · 상성 연출.
