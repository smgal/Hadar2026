# B2-02 치료 마법이 실제로 회복시킨다

- **상태**: DONE
- **구간**: B2 — **잠정 항목** ([_README](_README.md))
- **성격**: **판단** — 구조는 C++ 을 거의 그대로 받았고, 값 2곳을 고쳤다
  ([6차 판정](../DECISION-LOG.md): C++ 은 정본이 아니다)
- **규모**: M
- **선행**: B1 전체 · [B2-04](B2-04-unconscious-stage.md) · [B2-03](B2-03-status-effects.md)
- **설계 근거**: [`GROUND_TRUTH` 부록 R](../../blueprint/_meta/GROUND_TRUTH.md)

## 문제

치료가 **아무것도 회복시키지 않았다.** `battle.dart:148-155`:

```dart
if (cmd == 5) {
  // Heal
  await _host.addLog("… 시전했다!");
  // Simulate heal resolution
  await _host.addLog("아군의 상처가 치료되었다.");
}
```

19~32(한명/모두 × 치료·독제거·의식돌림·부활·복합) **14종 전부**가 이 한 갈래였다.

## 결과 (2026-09-05)

`packages/hd_battle/lib/src/rules/cure.dart`.

### 네 갈래의 조합이다

14종은 **네 가지 기본 동작의 조합**이었다([부록 R-1](../../blueprint/_meta/GROUND_TRUTH.md)) —
`heal` · `antidote` · `recoverConsciousness` · `revitalize`.
`cureStepsFor(magicId)` 가 그 표다.

### 조합 순서가 장식이 아니다

`m_healOne` 이 **독에 걸린 대상을 거부한다.** 죽거나 쓰러진 것만이 아니다.
그래서 `치료와 독제거`(21)는 **독을 먼저 지운 뒤** 회복해야 하고, 그것이 이 마법이
따로 존재하는 이유다. `독 제거` 도 쓰러진 대상에는 닿지 않으므로 24 의 순서
(의식돌림 → 독제거 → 회복)도 필연이다. 테스트가 이 불변식을 고정한다.

### 비용이 대상 상태를 읽는다

| 갈래 | 비용 | 효과 |
|---|---|---|
| heal | `2 × 시전자 마법레벨` | `비용 × 3/2` 회복, 최대치에서 멈춤 |
| antidote | 15 고정 | 독 제거 |
| recoverConsciousness | **`10 × 의식불명 누적값`** | 깨우고 hp 최소 1 |
| revitalize | 30 고정 | 되살리되 **의식불명 상태로** |

세 번째가 [B2-03](B2-03-status-effects.md) 의 누적값에 두 번째 용도를 준다 —
깊이 쓰러졌으면 깨우는 값이 비싸다. **부활은 의식불명으로 돌려놓으므로**
완전 회복에는 부활 + 의식 돌림이 둘 다 필요하다.

**치료는 SP 를 실제로 차감한다.** 공격 마법 쪽 미차감(부록 O-1)은 B2-01 이 갚는다.

### 선택 게이트가 절반마다 다르다

단일(19~25)은 `마법레벨/2 + 1`, 전체(26~32)는 `마법레벨/2 - 3` — 둘 다 7 상한이고
전체는 **마법 레벨 8** 이 필요하다. `castableCures` 가 그것이고, 치료 카테고리는
`castableSpells` 에서 이 경로로 빠진다.

## C++ 에서 고친 것 2건

| 무엇 | 왜 |
|---|---|
| **마법 레벨 0 인 시전자의 회복** | 비용 0, 회복 0 인데 게이트(`level/2+1`)가 레벨 0 에게도 한 칸을 열어 준다 → 아무 일 없이 성공을 보고한다. 이 레포 시작 파티에서 실제로 재현된다(유리가 마법 레벨 0). 거부하게 했다 |
| 전체 치료의 거부 조건 | C++ 이 `//@@ 원래는 < 0 이었음 검토 필요` 라고 스스로 표시해 뒀다. `< 0` 이면 0칸 메뉴가 열리므로 `<= 0` 쪽을 받았지만 **신뢰가 아니라 표시**다([부록 R-4](../../blueprint/_meta/GROUND_TRUTH.md)) |

## 우리가 정한 것 1건 — 단일 치료의 대상

원작은 `castCureSpell` 첫 화면에서 "누구에게" 를 물었다. Dart 전투는 그 질문을 없앴고
대상 필드를 아예 읽지 않았다. 새 질문 단계를 지금 만들지 않고 **가장 필요한 사람**에게 간다 —
사망 → 의식불명 → 중독 → 가장 다친 순. 명시적 아군 선택은 아이템 메뉴가 생기는
[B2-06](B2-06-battle-items.md) 에서 같이 넣는 것이 맞다.
