# B5-01 `rank` 와 `gap` — 위치의 뼈대

- **상태**: DONE
- **구간**: B5 ([_README](_README.md))
- **성격**: **판단** — 원작에 위치 개념이 없다
- **규모**: L
- **선행**: [B5-00](B5-00-five-member-fixtures.md)
- **설계 근거**: [8차 판정](../DECISION-LOG.md)
- **규격 영향**: **있음** — `CombatantSnapshot.rank` · `BattleSetup.initialGap`

## 문제

전투에 위치가 없다. `_aliveEnemyIndices()` 가 **살아 있는 적 전부를 같은 비용으로** 낸다.
고를 이유는 "HP 가 적은 놈" 하나뿐이라 그건 계산이지 결정이 아니다.

증거가 우리 코드에 있다 — 자동 방침이 `decision.enemyIndices.first` 로 항상 잘 돌아간다.
**아무거나 골라도 되는 메뉴**라는 뜻이다.

## 무엇을 할 것인가

### 상태는 정수 두 종류다

```
rank : 각자의 열, 자기 진영 안에서 1(앞) ~ 3(뒤)
gap  : 양측 공통의 간격, 0 ~ 2

거리(아군 a → 적 e) = gap + (a.rank - 1) + (e.rank - 1)
```

**좌표가 아니다.** 그래서 격자 게임이 되지 않는다.
"우리가 전진한다" 와 "적이 전진한다" 는 **같은 사건**이다 — `gap` 이 줄 뿐이다.

### 열은 인원 수와 무관하게 존재한다

2인이어도 "둘 다 3열에 설까, 하나를 앞에 세울까" 가 선택이다.
**아무도 1열에 없으면 적이 자유롭게 밀고 들어온다** — 그것이 값이다.

파티의 열은 **전투 밖에서 정한다**(DQ4·5 「대열」). 전투 중에는 행동의 결과로만 바뀐다.
적의 열은 조우 정의가 준다.

### 유한한 판 — 몰릴 수 있다

각 진영 깊이 3열, `gap` 상한 2. **뒤로 물러날 열이 없으면 못 물러난다 = 몰렸다.**
격자 없이 궁지가 생긴다.

### 초기 `gap` — 실측이 먼저다

실전이 **3~4 라운드**다(부록 W). 간격 2 에서 시작해 붙는 데 2라운드가 걸리면
**전투의 절반이 걸어다니는 시간**이다.

> **그래서 대부분의 조우는 `gap` 0~1 에서 시작해야 한다.** 2 는 "멀리서 먼저 발견했다" 는
> 특수 상황(기습의 반대)으로 아껴 둔다.

초기 `gap` 을 무엇이 정하는지는 **굴려 보고 정한다** — 민첩 차 · 레벨 차 · 기습 여부.
이 이슈의 첫 산출물은 **초기 간격 분포 실측표**다.

### 사거리 밖의 처리 — 불변식

> **벌점이지 무효가 아니다.** 명중이 깎이고 앞열의 적이 대신 맞을 뿐, 턴은 사라지지 않는다.

```
사거리가 닿으면      평소대로
1칸 모자라면         명중 -6,  앞열이 30% 확률로 대신 맞음
2칸 모자라면         명중 -14, 55% 확률로 대신 맞음
```

숫자는 잠정이다. **딱 잘라 막지 않는 이유**는 목록이 줄어들면 게임이 선택지를 뺏는 것으로
읽히기 때문이고, "빈틈을 노려 보스를 친다" 는 도박이 사라지기 때문이다.

## 결과 (2026-09-05)

`packages/hd_battle/lib/src/rules/position.dart`.

### 상태가 정수 두 종류로 끝난다

`CombatantSnapshot.rank` · `EnemyInstance.rank` · `Battle.gap` 뿐이다.
`distanceBetween` 한 함수가 거리를 계산하고, 좌표는 어디에도 없다.

`rank` 를 안 주면 **슬롯에서 떨어진다**(0-1 앞 · 2-3 중 · 4-5 뒤). 그래서 열을 모르는
RPG 가 넘겨도 말이 되는 진형이 나온다. 적은 `defaultEnemyRank` 가
**무엇인지에서** 읽는다 — 소환하는 지휘관은 맨 뒤, 시전자는 뒤, 팔이 있는 것은 앞.
75행에 손으로 진형을 적지 않아도 된다.

### 초기 간격을 양측에서 유도한다

`openingGap()` 이 민첩·레벨 평균 차이로 정하고, 조우가 `initialGap` 으로 덮어쓴다
(기습 0 · 원거리 발견 2). 실측은 [부록 X-1](../../blueprint/_meta/GROUND_TRUTH.md):

- **레벨 1 이면 100% 가 간격 0** — 초반에는 간격 놀이가 없다. 대열은 여전히 결정이다
- 레벨 20 이면 45% 가 간격 2 — 강해지면 거리가 생긴다
- **보스는 레벨과 무관하게 간격 0** — Archi-Mage 도 Neo-Necromancer 도 붙어서 시작한다

### 사거리 밖은 벌점이다 — 그리고 그것을 테스트가 지킨다

`AttackStrained` · `AttackIntercepted` 와 적 쪽 짝 두 개가 생겼다.
**가로채기 확률이 절대 100% 가 되지 않는다** — 반드시 남이 대신 맞는 공격은
이름만 바꾼 헛턴이다. 테스트가 이것을 못 박는다.

`fixtures/rules/reach.json` 이 규칙을 그대로 보여준다 — Archi-Mage 3열 · Orc 셋 1열 ·
간격 1 에서 전원이 보스를 노린다. 1열은 1칸, 2열은 2칸 모자라고 Orc 이 대신 맞는다.

### 부수적으로 얻은 것

fixture 방침에 **대상 지정 `@n`** 이 생겼다(`attack@3`). 뒷열의 보스를 일부러
노리는 시연을 만들려면 필요했다.

### 잠정으로 둔 것

**사거리가 아직 무기에 없다** — `provisionalReach = 2` 상수 하나다.
[B5-02](B5-02-weapon-reach.md) 가 무기별 하한~상한으로 교체한다. 값을 넉넉하게 둔 덕에
기존 fixture 17개가 그대로 돌고, 위치 기제만 먼저 들어갔다.
