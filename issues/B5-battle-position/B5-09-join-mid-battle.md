# B5-09 전투 중 합류 — 슬롯과 정원

- **상태**: DONE
- **구간**: B5 ([_README](_README.md))
- **성격**: **판단** — B2-10 의 처리를 뒤집는다
- **규모**: M
- **선행**: [B5-01](B5-01-rank-and-gap.md)
- **설계 근거**: [`GROUND_TRUTH` 부록 W-7](../../blueprint/_meta/GROUND_TRUTH.md)
- **규격 영향**: **있음** — `BattleSetup.partyCapacity`

## 문제 — 지금은 **판에서 지운다**

`model/battle.dart:920`, 독심술(마법 43)로 마음을 돌린 적:

```dart
_recruits.add(_snapshotOfEnemy(t));   // slot: -1
t.dead = 1; t.unconscious = 1; t.hp = 0; t.level = 0;
```

- 영입된 적은 **그 전투에서 싸우지 않는다.** 완전히 지워진다
- `slot: -1` 로 넘기고 **전투가 끝난 뒤 RPG 가 자리를 정한다**
- **정원 검사가 없다.** `BattleSetup` 은 `party`·`enemyKeys`·`seed`·`mode`·`consumables`
  뿐이라 **빈 슬롯이 몇 칸인지 모른다**

마지막이 결정적이다. **"이미 슬롯이 차 있으면 추가 소환은 안 된다" 는 전투가 정원을
알아야 성립한다.** 5명을 넘겨도 1칸 남은 건지 애초에 5칸짜리인지 구분이 안 된다.

## 무엇을 할 것인가

### 슬롯 점유자는 네 종류인데 **전투는 셋을 구별할 필요가 없다**

| | 출처 → 귀착 | 전투가 구별하나 |
|---|---|---|
| 본래 파티원 | RPG → RPG | |
| RPG 에서 따라다니는 소환수 | RPG → RPG | **아니다** |
| 잠시 합류한 사람 | RPG → RPG | **아니다** |
| **전투 중 소환 · 마음 돌린 적** | **전투 → RPG** | ✅ 새 처리 |

앞의 셋은 `CombatantSnapshot` 으로 들어와 `CombatantResult` 로 나간다.
소환수인지 게스트인지는 **RPG 의 관심사**다. 전투는 "N번 슬롯에 이런 능력치의 누군가가
있다" 만 알면 된다.

→ **규격에 `isSummon` 같은 칸이 필요 없다.** 죽으면 사라지는지, 전투 후 해제되는지도
전부 RPG 가 정한다. 전투는 `dead = 1` 로 돌려주기만 한다.

### 규격 변경은 **하나**

```dart
BattleSetup(
  party: [...],          // 실제로 앉아 있는 사람들
  partyCapacity: 6,      // ← 이것 하나
  ...
)
```

빈 칸 = `partyCapacity - 앉아 있는 사람`. `departedSlots`(끌려간 사람)로 자리가 비면
**정원이 동적으로 늘어난다.**

### 전투 중에 슬롯에 앉아 싸운다

`_snapshotOfEnemy` 의 `slot: -1` 과 적을 지우는 네 줄이 바뀌는 지점이다.

- **빈 슬롯 중 제일 앞**에 앉는다 → `slot` 이 "RPG 파티 슬롯" 이라는 정의가 유지된다
- `recruits` 는 그대로 쓰되 **실제 배정된 슬롯**을 싣는다
- 전투가 끝나면 남는다

### 저절로 풀리는 것 둘

- **합류한 라운드에는 행동하지 않는다.** 명령 수집(`_collectIx`)은 해결 단계 **전에** 끝나고
  행동 순서(`_order`)도 라운드 시작에 한 번 만들어진다. 다음 라운드부터 참여한다 —
  구현이 아니라 구조가 그렇다
- **경험치는 기존대로.** 승리 경험치를 의식 있는 전원에게 전액 준다(`settle.dart`).
  늦게 온 사람도 똑같이 받는다. **복잡하게 하지 않는다**

### 정원이 차면 **메뉴에서 뺀다**

정원이 차서 소환이 거절되면 그건 **헛턴**이고 불변식에 걸린다.

→ `pendingDecision` 이 애초에 안 내놓는다. **기존 구조가 이미 하는 일이다** —
`castableSpells` 가 못 쓰는 마법을 목록에서 빼는 자리와 같다. 새 기제가 아니다.

### 합류한 사람의 열

- **마음 돌린 적** → **원래 서 있던 열을 유지**한다. 적 1열의 놈을 뺏으면 우리 1열에 선다
- **소환수** → 소환수마다 등장 열이 다르면 **소환이 위치 도구가 된다**
  (고기방패는 앞, 지원은 뒤)

## 결과 (2026-09-05)

### 규격 변경은 `partyCapacity` 한 칸

빈 슬롯 = `partyCapacity - 앉아 있는 사람`. **매번 다시 센다** — 초자연 시전에
끌려간 사람(`departedSlots`)이 자리를 돌려준다.

### 영입된 적이 앉아서 싸운다

`_snapshotOfEnemy` 의 `slot: -1` 과 적을 지우던 네 줄이 바뀐 자리다.
빈 슬롯 중 제일 앞에 앉고 **원래 서 있던 열을 유지한다** — 적 1열의 놈을 뺏으면
우리 1열에 선다. `recruits` 는 **실제 배정된 슬롯**을 싣는다.

### 정원이 차면 메뉴에서 빠진다

독심술(43)이 목록에서 사라진다. **`castableSpells` 가 못 쓰는 마법을 빼는 자리와
같다** — 새 기제가 아니고, 헛턴이 메뉴를 통해 도달 불가능하다는 뜻이다.

### 저절로 된 것

**합류한 라운드에는 행동하지 않는다.** 명령 수집이 해결 단계 **전에** 끝나고 행동
순서도 라운드 시작에 한 번 만들어지므로, 구현이 아니라 구조가 그렇게 되어 있다.

### 건드리지 않은 것

**경험치.** 늦게 온 사람도 의식 있는 전원과 똑같이 전액 받는다. 복잡하게 하지 않기로 했다.

**소환수의 종류 구분.** 본래 파티원 · RPG 소환수 · 게스트는 전투 입장에서 완전히 같다 —
`CombatantSnapshot` 으로 들어와 `CombatantResult` 로 나간다. 죽으면 사라지는지도
RPG 가 정한다. 그래서 `isSummon` 같은 칸이 규격에 없다.
