## 2026-09-01 — 착수 판정: **조건부 진행**

**질문**: AI 로 시나리오·퀘스트를 자동 생성하는 것이 (a) 불가능한가 (b) 수동보다 비효율인가.

### (a) 불가능한가 → **아니다**

오프라인 배치 생성 + 스키마 강제 + 정적 검증 + 완주 증명은 검증된 방식이다.
런타임에 AI 를 두지 않으므로([D-01](../blueprint/_meta/DECISIONS.md)) 결정론·재현성도 확보 가능하다.
설계는 [`blueprint/`](../blueprint/00_README.md) 34개 장에 이미 완결되어 있다.

### (b) 수동보다 비효율인가 → **지금은 알 수 없다. 그리고 질문이 성립하지 않는 구간이 있다**

실측한 현재 콘텐츠:

| 항목 | 값 |
|---|---|
| cm2 `Talk` 호출 | 393개 (4,056줄) |
| 맵 JSON 이벤트 / 대사 | 76개 / 56줄 |
| **퀘스트** | **0개** |

핵심 발견: **지금 구조에서는 손으로도 퀘스트를 만들 수 없다.**
- 인벤토리가 `food`/`gold` 정수 2개뿐 → "가져오라" 를 표현할 수단이 없다
- `HDMapScript.isFlagSet` 이 빈 스텁(부록 A-3) → 네이티브 조건 분기가 한 번도 동작한 적 없다
- cm2 전역이 맵 전환마다 초기화(§9) → 진행 상태를 들고 다닐 수 없다
- JSON 티어는 좌표당 이벤트 1개·무조건 출력 → 조건부 대사 불가

즉 **병목은 "AI vs 수동" 이 아니라 "퀘스트라는 개념의 부재"** 다.
P0(기반 복구)과 P1(퀘스트 능력)은 **AI 여부와 무관하게 필요**하다.

### 판정

**진행한다. 단 AI 특화 구간(P2) 앞에 측정 게이트를 둔다.**

- P0·P1 은 무조건 진행 — 어느 쪽 길을 가도 필요한 작업이다.
- P2(콘텐츠 서버·MCP·솔버·퍼저·생성 하네스)는 **GATE-1 통과 시에만** 착수한다.
- GATE-1 은 P1 후 **퀘스트 5개를 손으로 만들어 실측**한다. 판정 규칙은 착수 전에 못박았다
  ([MILESTONES.md §4](MILESTONES.md)) — 결과를 보고 기준을 바꾸지 않기 위해서다.

### 이 판정이 틀릴 수 있는 지점

- **목표 물량이 작으면 P1 조차 과하다.** 퀘스트를 5개만 원한다면 cm2 + 네이티브 Dart 로
  임시 대응하는 것이 더 싸다. 물량 목표를 정하는 것이 P0 착수보다 먼저다 — [ISSUE-000](#) 참조.
- **P0 이 예상보다 크면** 전체가 흔들린다. 부록 A~K 는 21건 이상이고 세이브 포맷 변경을 포함한다.
- **1인 개발이면 P2 는 거의 확실히 과하다.** 파이프라인 자체가 게임보다 커지는 위험은
  [BP-52](../blueprint/52_risks.md) 가 리스크로 등재했다.

## 2026-09-01 (2차) — **1차 판정 정정**: 퀘스트는 이미 저작 가능하다

### 무엇이 틀렸나

1차 판정은 "지금 구조에서는 **손으로도 퀘스트를 만들 수 없다**" 를 전제로 P0→P1→GATE→P2 를 짰다.
**이 전제는 거짓이다.** 레포 안에 작동하는 퀘스트 콘텐츠가 **2,441줄** 있다(`assets/L1_ep1d0~d5_1.cm2`).

원작의 퀘스트 시스템은 `assets/flag4ep1.cm2` 다 — **이름 붙인 플래그 상수 + cm2 조건 분기**:

```cm2
GFD0_GET_WALL_REMOVER.assign(1)    # 벽 허무는 도구 획득
GFD0_GET_KEY_FOR_D1.assign(2)      # 열쇠 획득
GFD0_CHECKED_BY_GUARD.assign(3)    # 경비병 검문 통과
```

그리고 `L1_ep1d0.cm2` 의 실제 로직:

```cm2
if (Equal(ScriptMode(), FLAG_TALK))
    if (On(14,30))                              # 좌표로 NPC 식별
        if (Not(Flag::IsSet(GFD0_RENT_ROOM)))   # 조건부 분기
            Select::Init() / Add / Run          # 선택지
            Map::ChangeTile(18,36,30)           # 월드 변화
            Flag::Set(GFD0_RENT_ROOM)           # 진행 기록
```

복합 조건도 동작한다: `And(And(Not(Flag::IsSet(A)), Flag::IsSet(B)), Flag::IsSet(C))`.

### 내가 왜 틀렸나 (같은 실수를 반복하지 않기 위해)

| 1차 판정의 근거 | 실제 |
|---|---|
| 인벤토리가 없어 "가져오라" 를 표현 못 한다 | **원작은 플래그로 표현한다.** `GFD0_GET_KEY_FOR_D1` 이 곧 "열쇠 소지" 다. 인벤토리는 애초에 없었고 필요도 없었다 |
| `HDMapScript.isFlagSet` 이 빈 스텁이라 조건 분기가 전무하다(부록 A-3) | 그건 **네이티브 Dart 경로**다. cm2 의 `Flag::IsSet` 은 `HDGameOption.flags`(256칸, **세이브에 저장됨**)를 정상 참조한다 |
| cm2 전역이 맵 전환마다 소실된다 | 소실되는 것은 **엔진의 변수**(상수 이름 바인딩)이고, 매 로드 시 `include("const.cm2")` 가 다시 만든다. **실제 플래그는 세션 상태라 살아남는다** |

**공통 원인**: 결함 목록을 보고 "그래서 불가능하다" 를 **연역**했고, **작동하는 사례를 찾아보지 않았다.**
레포에 2,441줄의 반례가 있었는데 읽지 않았다.

### 맵과 등장인물 추가도 코드 변경 없이 된다

작동하는 패턴(`LORE_EP` = `Map002.json` + `Map002.cm2` 가 실증):

| 필요한 것 | 방법 |
|---|---|
| 새 맵 | `MapInfos.json` 에 `{"id": 16, "name": "..."}` 추가 (다음 빈 id 는 **16**) + `assets/maps/Map016.json` |
| 새 등장인물 | 맵 JSON 의 objUpper 에 TALK 오브젝트(B 128~143) + cm2 의 `On(x,y)` 핸들러 |
| 퀘스트 로직 | `assets/Map016.cm2` — `include("const.cm2")` + `ScriptMode()` 분기 |
| JSON 폴백 억제 | `Event::Override()` — `Map002.cm2` 에 이미 데모가 있다 |

**즉 샘플 퀘스트 = 파일 2개 + MapInfos 한 줄. 코드 변경 0.**

### 정정된 판정

**"검증부터" 를 버리고 "생성부터" 로 바꾼다. 그리고 top-down 을 버리고 sample-first 로 바꾼다.**

- **S1**: 샘플 퀘스트 1개를 **현재 방식으로 손으로** 만든다(새 맵 + NPC 포함). 이것이 생성의 **정답지**다.
- **S2**: 그 과정에서 **실제로 걸린 것만** 고친다. 미리 짐작해 만들지 않는다.
- **S3**: AI 가 **같은 산출물**(map JSON + cm2 + MapInfos 항목 + 플래그 정의)을 만들게 한다.

**인벤토리·장비·저널·선언적 콘텐츠 팩은 전부 보류**한다. 원작이 플래그로 하던 것을 플래그로 한다.
결과가 원작과 맞으면 되고, 구조 개선은 자동화가 실제로 막힐 때 그 지점에서 한다.

`blueprint/` 34개 장은 폐기하지 않는다 — **그 길이 필요해지는 시점의 설계**로 남긴다.
[deferred/](deferred/) 가 그 경계를 기록한다.

## 2026-09-01 (3차) — 순서 재조정: **게임 시스템 완성이 자동화보다 먼저**

### 무엇이 바뀌었나

2차 판정은 "인벤토리는 보류하고 플래그로 대체" 했다. **두 가지 이유로 뒤집는다.**

1. **재미** — 플래그는 퀘스트 기록은 되지만 **장비할 수도, 팔 수도, 가방에서 볼 수도 없다.**
   게임이 미완성인 상태에서 퀘스트만 늘려도 재미가 늘지 않는다.
2. **부채** — **플래그로 만든 퀘스트 20개는 나중에 인벤토리가 생기면 전부 다시 써야 한다.**
   임시 표현 위에 쌓은 콘텐츠는 부채다. 자동화로 물량을 늘린 뒤라면 더 크다.

### 실측이 판단을 굳혔다

| 사실 | 확인 |
|---|---|
| **원작에 완성된 아이템 시스템이 있다** | `REF_UNITY_LoreEp1/src_as_cs/ObjItem.cs` **877줄** · `GameEventEquipment.cs` **448줄** |
| 아이템 모델 | `Item { res_id, name, param{atta_pow, ac, item_type}, annex }` |
| **원작은 부위 개념을 갖는다** | `ITEM_TYPE`: `WIELD/CHOP/STAB/HIT/SHOOT/SUMMON_*` · `SHIELD` · `ARMOR/HEAD/LEG` · `ORNAMENT` |
| 현재 Dart | `weapon`/`shield`/`armor` **정수 3칸**뿐 → 부위가 늘어나면 또 어긋난다 |
| `books.json` | 무기 5·방어구 3. 앱과 참조본이 **동일** → 샘플이고 실데이터는 원작 바이너리에 있다 |
| 플레이어에게 보이는 미완성 | `"무기1"` 이 전투 로그 2곳(`battle.dart:285,453`) + 상태 메뉴 2곳(`menu_flows.dart:275,277`)에 노출 중 |
| 마법 | 선택 UI·이름만 있고 **효과는 레벨 기반 일반 공식 2개로 뭉쳐 있다**(`battle.dart:155,174`). 45종 개별 효과 없음 |

**즉 인벤토리는 "설계할 것" 이 아니라 "이식할 것" 이다.** 2차 판정이 이를 몰랐다.

### 정정된 순서

```
G1 아이템·장비 이식 ─▶ G2 전투 정합 ─▶ S1 샘플 퀘스트 ─▶ S2 걸림돌 제거 ─▶ S3 AI 생성
(재미 + 부채 방지)      (퀘스트 전투 전제)   (진짜 아이템 사용)
```

- **G1·G2 는 자동화와 무관하게 게임을 위해 필요한 작업**이다. 동시에 자동화의 표현 기반을 안정시킨다.
- **S1 이 G1 뒤로 간다** — 그래야 "기름을 구해 오라" 를 플래그가 아니라 **실제 아이템**으로 쓰고,
  나중에 다시 쓰지 않는다.
- 마법 효과 구현은 **별 트랙**이다. 재미에는 크지만 퀘스트 자동화의 전제는 아니다.

### 2차 판정에서 유지되는 것

- 퀘스트 저작은 원작 방식(플래그 + cm2)으로 **이미 가능**하다 — 그 사실은 변하지 않는다.
- 새 맵·등장인물 추가는 **코드 변경 0**.
- cm2 중첩 `include` 로 퀘스트 파일 분리가 가능하다(부록 L).
- 선언적 콘텐츠 팩·저널·솔버·MCP 는 계속 **보류**다. G1 은 그 노선이 아니라 **원작 이식**이다.
