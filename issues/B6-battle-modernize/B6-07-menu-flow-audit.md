# B6-07 메뉴 흐름 감사 — 묻는 순서 · 취소 · 한 답짜리 물음 · 치료 대상

- **상태**: DONE (2026-09-06)
- **구간**: B6
- **규모**: M
- **선행**: B6-01 ~ B6-06

## 계기

B6 를 실제로 눌러 보고 나온 두 지적. "거리와 관련된 것이 직관적이지 않다 —
slot 순서로만 보인다" 와 "이런 식으로 불합리한 메뉴가 더 있는지 보라".
전투 메뉴의 물음 여섯 가지를 처음부터 끝까지 다시 밟았다.

## 찾은 것 넷과 고친 것

### 1. 묻는 순서가 화면과 어긋났다 → **리더 → 1열 → 2열 → 3열**

슬롯 순으로 물었다. 시작 시엔 슬롯 순 = 열 순(`rankOf` 가 슬롯에서 열을 만든다)이라
티가 안 나지만, 돌격·넉백으로 열이 바뀐 뒤엔 화면 위아래와 묻는 순서가 다르다.

- **행동 순서(민첩 선제, B2-05)는 그대로다.** 바뀐 것은 *묻는* 순서뿐 — 둘은 별개다.
- 리더가 먼저인 것은 대열 명령 때문이다. 리더가 뒷열이어도 먼저 묻는다.
- 화면도 같은 순서로 늘어놓는다: 일행은 리더 → 앞열부터, 적은 앞열부터.
  **슬롯 번호·적 번호는 그대로 적는다** — 명령과 콘솔 방침(`0=item`)은 그것으로 간다.
- 적 대상 목록도 **가까운 열부터**(`_aliveEnemyIndices`).
- `_askOrder` 는 라운드 시작에 만든다. 합류(B5-09)는 해결 단계에 일어나므로 다음 라운드부터.

### 2. 하위 물음에서 취소하면 턴을 잃었다 → **한 단계 위로**

원작이 그랬다(`battle.dart:349`). 기술 목록을 잘못 열고 0 을 누르면 그 사람의 턴이
사라졌다 — 메뉴를 잘못 연 것이 벌점이었다. 이제 취소는 행동 메뉴로 돌아간다.
행동 메뉴 자체에서 0 은 여전히 "이 턴을 넘긴다" — 글도 그렇게 바꿨다(`cancelTopLabel`).

**헤드리스 안전장치**: 한 라운드에 같은 사람이 행동 메뉴로 8번 넘게 돌아오면 턴을
넘긴다(`_maxReturns`). 사람은 절대 안 닿고, 취소만 하는 방침은 영원히 돌지 않는다.

### 3. 답이 하나인 물음을 물었다 → **묻지 않는다**

적이 하나인데 "공격할 적을 선택하십시오". 아군이 하나인데 "누구에게". 한 답짜리
물음은 건너뛴다(`_askEnemyTarget` · `_askAllyTarget`). 적 하나짜리 전투에서 5인
파티가 라운드마다 다섯 번 누르던 것이 없어진다.

### 4. 치료 마법이 대상을 묻지 않았다 → **아이템처럼 묻는다, 필요한 사람부터**

원작은 물었고(`castCureSpell` 의 "to whom"), Dart 이식이 떨어뜨렸다. B2-02 가 "가장
필요한 사람" 으로 메꿨는데, 물건(B2-06)은 묻고 마법은 안 묻는 것이 어긋났다.
이제 19~25 도 `AllyTargetDecision` 을 낸다. 목록은 **필요한 순**(사망 → 의식불명 → 중독
→ 부상 → 멀쩡, 같으면 슬롯)이라 1번을 누르면 옛 기본값 그대로다.

### 덧: 부족한 기술을 고르면 턴을 잃었다 → 말해 주고 돌아온다

B6-01 은 못 쓰는 기술을 목록에 남기되 고르면 `NotEnoughSpellPoints` 로 거절했다 — 그리고
턴을 넘겼다. 이제 거절하고 행동 메뉴로 돌아온다.
