# Hadar2026 — 로컬 이슈 트래커

> 이 디렉토리는 **원격 트래커 없이 레포 안에서 굴리는 이슈 보드**다.
> 설계 근거는 전부 [`blueprint/`](../blueprint/00_README.md) 에 있고, 여기는 **실행 단위**만 담는다.

## 왜 별도 디렉토리인가

`blueprint/` 는 **왜·무엇을**(설계 SSoT), `issues/` 는 **누가·언제·무엇부터**(실행 상태)를 담는다.
설계가 바뀌면 `blueprint/` 를 고치고, 이슈는 그것을 **인용**한다. 이슈 안에서 설계를 재정의하지 않는다.

## 파일 지도

| 파일 | 역할 |
|---|---|
| [MILESTONES.md](MILESTONES.md) | **구간 정의 · 완료 기준 · 의사결정 게이트.** 먼저 읽을 것 |
| [BOARD.md](BOARD.md) | 전체 이슈 인덱스 (상태 한눈에) |
| [DECISION-LOG.md](DECISION-LOG.md) | 진행/중지 판정과 그 근거 |
| `S1-sample-quest/` | 샘플 퀘스트 — 손으로, 코드 변경 0 |
| `S2-enablers/` | S1 이 증명한 걸림돌만 제거 |
| `S3-generation/` | AI 생성 |
| `P0-foundation/` | 실재 버그 백로그 (선행 구간 아님) |
| `deferred/` | **보류** — 선언적 콘텐츠 팩·무거운 생성 파이프라인 노선 (26건) |
| `templates/ISSUE.md` | 새 이슈 서식 |

## 처음 읽는 사람 (대화 세션을 새로 시작한 경우)

**이 순서로 읽으면 맥락 없이도 바로 일할 수 있다.**

1. [DECISION-LOG.md](DECISION-LOG.md) — **먼저 읽을 것.** 왜 이 노선인지, 그리고 **1차 판정이 왜 폐기됐는지**.
   1차 판정(P0→P1→GATE→P2)을 따르면 잘못된 일을 하게 된다.
2. [MILESTONES.md](MILESTONES.md) §0~§1 — 현재 노선(S1→S2→S3)과 전제
3. [BOARD.md](BOARD.md) — 착수 가능한 이슈(`TODO` 이고 선행이 `DONE`)
4. 고른 이슈 파일 — **완료 판정 기준을 먼저** 읽는다

**설계 근거가 필요할 때만** [`blueprint/`](../blueprint/00_README.md) 를 본다(34개 장, 43,000줄).
단 `blueprint/` 의 **로드맵·경영요약(BP-01·BP-50)은 1차 노선 기준**이라 이 디렉토리가 우선한다.
`blueprint/_meta/GROUND_TRUTH.md`(코드 실측)와 `_meta/DECISIONS.md`(설계 결정)는 **여전히 정본**이다.

## 이슈 상태 규약

| 상태 | 뜻 |
|---|---|
| `TODO` | 착수 안 함 |
| `WIP` | 진행 중 |
| `BLOCKED` | 선행 이슈 대기 (무엇을 기다리는지 반드시 적을 것) |
| `REVIEW` | 구현 끝, 검증 대기 |
| `DONE` | 완료 판정 기준 충족 |
| `DROPPED` | 하지 않기로 결정 (이유를 반드시 남길 것) |
| `GATED` | 의사결정 게이트 이후로 보류 |

## 워크플로

1. [MILESTONES.md](MILESTONES.md) 의 현재 구간을 확인한다.
2. [BOARD.md](BOARD.md) 에서 `TODO` 이고 선행이 `DONE` 인 이슈를 고른다.
3. 이슈 파일의 **완료 판정 기준**을 먼저 읽는다. 기준이 애매하면 코드를 만지기 전에 기준을 먼저 고친다.
4. 작업 후 상태를 갱신하고, `BOARD.md` 의 해당 행도 갱신한다.
5. 설계와 어긋나는 사실을 발견하면 **`blueprint/_meta/GROUND_TRUTH.md` 를 먼저 고친다.** 이슈만 고치면 안 된다.

## 이슈를 쓸 때의 규칙

- **코드 위치는 `파일:줄` 로 적고, 쓸 때 실제로 열어 확인한다.** 이 프로젝트에서 줄 번호 추측은 실제로 사고를 냈다.
- **완료 판정 기준은 관측 가능해야 한다.** "안정적으로 동작한다" 는 기준이 아니다.
- 설계 근거는 `blueprint/` 문서와 `GROUND_TRUTH` 부록 ID 로 **링크**한다. 내용을 복사하지 않는다.
- 이슈 하나가 여러 파일을 건드려도 좋지만, **완료 판정이 하나여야 한다.** 판정이 둘이면 이슈를 쪼갠다.
