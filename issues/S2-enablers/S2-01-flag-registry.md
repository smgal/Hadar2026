# S2-01 플래그 인덱스 레지스트리 — 충돌을 기계가 막는다

- **상태**: BLOCKED (S1-99 대기)
- **구간**: S2
- **규모**: M
- **선행**: [S1-99](../S1-sample-quest/S1-99-friction-log.md)
- **설계 근거**: [MILESTONES §3](../MILESTONES.md) · [`GROUND_TRUTH` §8 상태 3중 분열 · 부록 F-1](../../blueprint/_meta/GROUND_TRUTH.md) · [P0-14](../P0-foundation/P0-14-silent-out-of-range.md)

## 착수 조건

[S1-99 마찰 기록](../S1-sample-quest/S1-99-friction-log.md) 이 이 문제를 **실제로 겪었다고 확인**해야 한다.
겪지 않았으면 이 이슈는 `DROPPED` 다.

구체적으로 다음 중 하나가 기록되어 있어야 한다.
- 빈 플래그 인덱스를 찾기 위해 기존 cm2 를 손으로 훑었다
- 어느 인덱스를 썼는지 몰라 겹칠까 봐 넉넉히 띄웠다
- 플래그가 예상과 다르게 켜져 있어 원인을 찾는 데 시간을 썼다

## S1 이 겪지 않았다면

**퀘스트가 1개뿐이면 충돌이 일어날 수 없다.** S1 은 새 대역(예: 60~69)을 통째로 잡아 쓰면 되고,
그때 "빈 칸 찾기" 는 `grep` 한 번이다. 즉 S1 은 이 문제를 **구조적으로 겪지 못한다.**

그래도 버리면 안 되는 반례가 하나 있다 — **레포에 이미 충돌이 박혀 있다**(아래 §문제).
S1 에서 걸리지 않았다는 이유만으로 버리려면, S3(AI 생성)이 인덱스를 **직접 고르지 않는다**는 것이
[S3-02](../S3-generation/S3-02-generation-prompt.md) 의 금칙으로 보장되고, 그 값을 **사람이 준다**는 흐름이
확정되어 있어야 한다. 그 조건이면 이 이슈는 `DROPPED` 가 타당하다.

## 문제

cm2 의 플래그는 `HDGameOption.flags: List<bool>(256)` 의 **정수 인덱스**다(`hd_config.dart:45` `maxFlags = 256`).
이름은 `flag4ep1.cm2` 가 `variable` + `.assign` 으로 붙인 **스크립트 관용**일 뿐, 엔진이 아는 것은 정수다.

### 생 숫자 사용 전수 확인 (`assets/*.cm2` 17개 전체)

```bash
grep -rn "Flag::\(IsSet\|Set\|Reset\)( *[0-9]" hadar2026_app/assets/*.cm2
```

| 파일 | 건수 | 사용 인덱스 |
|---|---|---|
| `lore_ep1.cm2` | **19** | 31, 32, 50, 51, 52, 53, 54, 55 |
| `town2.cm2` | **19** | 31, 32, 50, 51, 52, 53, 54, 55 (`lore_ep1` 과 거의 동일 사본) |
| `menace.cm2` | **2** | 10 (`:58` `Flag::Set(10)`, `:83` `Flag::IsSet(10)`) |
| 나머지 14개 | 0 | — |

`L1_ep1*` 7개 파일은 **전부 이름을 쓴다**(생 숫자 0건). 즉 생 숫자는 **총 40건, 3개 파일**에 있다.
`Variable::` 쪽도 같다 — `lore_ep1.cm2:163,206,212,213,217,219,231,233,243,245` 와 `town2.cm2` 동일 줄이 **생 숫자 10번**을 쓴다.

### 이미 발생한 충돌 3건

| 인덱스 | 한쪽 | 다른 쪽 |
|---|---|---|
| **10** | `flag4ep1.cm2:27-28` `GFD1_WALL_REMOVER_USED` | `town1.cm2:7,16` 의 `flag_battle.assign(10)` · `menace.cm2:58,83` 의 생 숫자 10 |
| **31** | `flag4ep1.cm2:80-81` `GFD3_OPEN_WEST_DOOR` | `lore_ep1.cm2:160,185,511` · `town2.cm2:160,185,507` |
| **50** | `flag4ep1.cm2:109-110` `GFD5_PUSH_BIG_STONE` | `lore_ep1.cm2:68,80` · `town2.cm2:68,80` |

### 이름을 붙여도 안전하지 않다 — 실제 오타 1건

`hadar2026_app/assets/flag4ep1.cm2:42-43`:

```cm2
variable(GFD1_OPEN_DOWN_STAIRS)
GFD1_OPEN_ODD_WALL.assign(15)      # ← 왼쪽 이름이 틀렸다
```

`packages/cm2_script/lib/src/cm2_script.dart:159-160` 이 `variable(X)` 를 **0으로 초기화**한다.
따라서 `GFD1_OPEN_DOWN_STAIRS` 는 영원히 **0** 이고, `flag4ep1.cm2:36-37` 에서 13을 받았던
`GFD1_OPEN_ODD_WALL` 은 15로 **덮어써진다**(13은 아무도 안 쓴다).

결과: `L1_ep1d1.cm2:176` 의 `Flag::Set(GFD1_OPEN_DOWN_STAIRS)` 는 **플래그 0** 을 켠다.
플래그 0 은 `GFD0_IS_FIRST` 이고 `L1_ep1d0.cm2:576` 이 그것으로 첫 방문을 판정한다.
**d1 의 아래층 문을 여는 것이 d0 의 "첫 방문 완료" 를 켠다.** 아무 로그도 없다.

`cm2_script.dart:140` 이 미등록 변수 대입에 경고를 찍지만, 이 오타는 **등록된 이름**이므로 경고조차 없다.
부록 F-1(범위 밖 침묵)보다 더 조용하다 — **범위 안이라 침묵이 아니라 오작동**이다.

## 왜 지금 고쳐야 하는가

- [S3-02](../S3-generation/S3-02-generation-prompt.md) 는 AI 에게 인덱스를 **주어야** 한다. 줄 값을 만들 곳이 없다.
- [S3-04](../S3-generation/S3-04-minimal-validation.md) 의 "플래그 충돌 0" 판정에는 **정본 목록**이 필요하다.
- 위 오타 1건이 증명하듯 이것은 가설이 아니다. **셋 다 이미 일어난 일**이다.

## 해법 선택지

| 안 | 방식 | 장점 | 단점 |
|---|---|---|---|
| **(a) 단일 정본 + 할당 CLI** | `assets/flag_registry.json` 을 정본으로 두고, `dart run tools/flag_alloc.dart --quest Q1 --count 6` 이 다음 빈 대역을 잡아 등록 + `flag4<quest>.cm2` 를 생성 | 정본이 하나 · AI 에 줄 값이 명확 · CI 에서 diff 검사 가능 | 정본과 실제 cm2 가 어긋날 수 있음(사람이 cm2 만 고치면) |
| **(b) 파일 스캔 자동 수집** | 도구가 `assets/*.cm2` 를 파싱해 사용 중 인덱스를 매번 계산하고 다음 빈 칸을 내준다. 정본 파일 없음 | 정본-현실 불일치가 원리적으로 불가능 · 기존 생 숫자 40건도 자동 포착 | 스캔이 곧 사실이라 **의도를 기록할 곳이 없다**(예약·폐기·재사용 금지) · 오타 이름은 값이 0이므로 "0 사용 중" 으로만 보인다 |
| **(c) 대역 예약** | 에피소드/퀘스트별 블록을 문서로 못박는다(ep1 0~59, 신규 퀘스트 60~69 …) | 도구 0줄 · 즉시 적용 | 사람이 지키는 규율 · 기계 검사 없음 · 이미 (10/31/50)이 예약을 위반한 상태 |

### 권고: **(a) + (b) 의 결합** — 정본은 (a), 검사는 (b)

- `assets/flag_registry.json` 이 **정본**이다: `{index, name, owner, since, status}`. 의도(예약·폐기)를 담을 수 있어야 하므로 (b) 단독은 탈락.
- **CLI 는 할당 시 (b) 의 스캔을 돌려 정본과 실물을 대조**한다. 불일치·충돌·생 숫자 발견이면 종료 코드 1.
  이 대조가 (a) 의 유일한 약점을 덮는다.
- (c) 는 **정본의 초기 내용**으로만 쓴다 — 대역 정책을 `flag_registry.json` 의 주석 필드로 옮기고, 규율이 아니라 데이터로 만든다.
- 스캔·대조 로직은 [S2-03](S2-03-cm2-linter.md) 린터와 **같은 코드**여야 한다. 두 번 구현하면 두 개가 어긋난다.

## 256칸 고갈 시점 추정

측정 기준(실측): `flag4ep1.cm2` 는 이름 **34개**를 선언하고 실제 인덱스 **33개**를 쓴다(13번은 오타로 사장).
이것이 에피소드 1(던전 d0~d5, 콘텐츠 2,441줄) 전체 분량이다.

| 가정 | 퀘스트당 플래그 | 200칸(현재 여유)으로 가능한 퀘스트 |
|---|---|---|
| 3단계 심부름 최소형 (수락·획득·전달·완료) | 4 | **50개** |
| 조건부 대사 · NPC 상태 변화 포함 | 6~8 | **25~33개** |
| 분기·실패 경로 포함 | 10~12 | **16~20개** |

현재 사용 중 최고 인덱스는 **55**, 사용 중 개수는 42개(이름 33 + 생 숫자 9)이므로 **여유는 약 200칸**이다.

→ **목표 퀘스트 수가 20개 이하면 256칸은 넉넉하다. 30개를 넘기면 대역 설계가 필요해지고,
50개를 넘기면 고갈이 실제 문제가 된다.** 목표 물량은 [P0-00](../P0-foundation/P0-00-content-volume-target.md) 이 확정한다.
고갈은 [MILESTONES §5](../MILESTONES.md) 의 "꺼내야 하는 신호" 1번이므로, **레지스트리가 남은 칸 수를 항상 출력**해야 한다.

## 무엇을 할 것인가

1. `hadar2026_app/assets/flag_registry.json` — 정본. 현재 사용 중 42개(이름 33 + 생 숫자 9)를 전부 등재.
   `flag4ep1.cm2:42-43` 오타는 **고치지 않고 `status: "typo_alias"` 로 기록**한다(고치면 기존 세이브 해석이 바뀐다).
2. `tools/flag_alloc/` — Dart CLI. `list` / `alloc --quest <id> --count <n>` / `check`.
   `check` 는 정본 ↔ `assets/*.cm2` 스캔 대조. 충돌·생 숫자·미등록 이름을 종료 코드 1로 보고.
3. `alloc` 은 `assets/flag4<quest>.cm2` 를 `flag4ep1.cm2` 형식으로 생성한다(`variable(X)` + `X.assign(n)` 쌍).
4. CI 에 `flag_alloc check` 추가 — 신규 충돌이 머지되지 않게.

## 하지 않을 것

- **기존 충돌 3건과 오타 1건을 고치지 않는다.** 등재하고 표시만 한다. 값을 바꾸면 기존 세이브의 플래그 해석이 바뀐다.
- 플래그를 이름 있는 키로 바꾸는 것(문자열 상태 키) — [deferred/P1-03](../deferred/P1-03-worldstate-unification.md) 소관이다.
- 256칸 확장 · 세이브 포맷 변경.
- `HDNativeScriptRunner.flags`(저장 안 되는 별개 공간, §8) 통합. 이 이슈는 **cm2 가 쓰는 `HDGameOption.flags` 만** 본다.
- 런타임 검사. 이것은 **저작 시점 도구**다. 런타임 침묵은 [P0-14](../P0-foundation/P0-14-silent-out-of-range.md) 소관.
