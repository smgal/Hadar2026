## 문제

**(1) 솔버·시뮬레이터·퍼저가 사람이 기억할 때만 돈다.** 현행 `.github/workflows/ci.yml`(101줄)은
잡 2개뿐이다 — `app`(analyze `:45` / test `:48` / 계층 grep `:50-75`)과 `cm2_script`(`:97-101`).
콘텐츠 검증·완주 증명·퍼징을 돌리는 잡이 없으므로, PR 에서 콘텐츠가 깨져도 머지된다.

**(2) 이벤트 발행 지점 레지스트리를 만드는 주체가 없다.** P2-05 의 축 2(`SUPPORTED`/`UNSUPPORTED`)는
`content.index.json#eventPublishers` 를 대조해 판정하는데, 그 생성은 **빌드 소관**(BP-35 §1.5.1)이고
아직 없다. 이것이 없으면 솔버는 D-26 이 금지한 "하나로 접은 판정" 으로 되돌아간다.

**(3) 에디터가 앵커를 모른다.** 사람이 `tools/mapEditor` 에서 지형을 고칠 때 그 칸에 앵커가 있는지
보이지 않는다. 또 부록 K 의 게이트 비대칭 — 같은 앵커가 **확인키로는 발화하고 벽에 부딪혀서는
발화하지 않는다** — 을 모르면 "왜 어떤 때는 되고 어떤 때는 안 되나" 를 콘텐츠·좌표 문제로 오진한다.

**(4) `MapInfos.json` 기존 엔트리를 고칠 경로가 없다.** 부록 H-4: `ai_api.ts:592` 가 신규 등록 시
이미 `json: file` 을 넣으므로 **신규 맵은 올바르게 등록된다.** 수리 대상은 **기존 15개 엔트리뿐**이고,
그것을 진단·수정 제안하는 엔드포인트가 없다.

## 무엇을 할 것인가

잡 지도와 잡별 스텝은 [BP-35 §4](../../blueprint/35_ci_and_build.md), 에디터 UI 는
[BP-36](../../blueprint/36_map_editor_extension.md) 에 있다.

### CI

기존 `check()` 헬퍼(`ci.yml:54-65`)의 구조를 **그대로 쓴다** — `local label="$1"; shift` 후
`grep -rn "$@" lib/application/ lib/domain/`, 히트가 있으면 `::error::` + `fail=1`.
**인자만 늘려 넣는다.** 새 헬퍼를 만들지 않는다.

> **ERE lookahead 금지.** `grep -E` 는 `(?=…)`/`(?!…)` 를 지원하지 않는다. 기존 2종이
> `-E "^import .*(presentation/|hd_game_main\.dart)"` 처럼 순수 ERE 로만 쓰여 있으므로 추가분도
> 같은 제약을 지킨다. 부정 조건이 필요하면 `grep -v` 를 파이프로 잇거나 `if [ -d … ]` 블록으로 뺀다
> (BP-35 §4.3 의 `lib/domain/content/` 배럴 검사가 그 형태다).

| 잡 | 트리거 | 예산 | 게이트 |
|---|---|---|---|
| `content-solve` | 콘텐츠 변경 PR | 3분 | Hard(`REFUTED`) / Soft(`UNKNOWN`) |
| `content-sim-golden` | 콘텐츠 **또는 런타임** 변경 PR | 4분 | Hard(엔진 회귀), 콘텐츠 변경은 승인 필요 |
| `content-fuzz-smoke` | 모든 PR | 2분 | Hard(크래시·데드락·계약 위반) |
| `content-fuzz-full` | 야간 · 릴리스 전 | 20분 | 리포트만 |

- PR 총 예산 10분. 기존 `app`·`cm2_script` 잡과 **병렬**로 돈다.
- 종료 코드 규약(BP-34 §8.5): `1` 하드 실패 · `2` 미확정(경고 + `needs-review`, 머지 차단 안 함) ·
  `3` 도구 내부 오류 · `4` 사용법 · `5` 골든 승인 필요.
- **`eventPublishers` 생성**을 빌드 단계에 추가한다(BP-35 §1.5.1). 이벤트 **12종** 각각에 현행
  빌드의 발행 지점이 있는지 표시하고, 없으면 `unpublished`. P2-05 가 이것을 소비한다.
- 번들 크기는 **증가분만** 본다. 실측 기준선은 45MB(canvaskit 31MB + 자산 9.7MB + NOTICES 1.3MB +
  나머지 ~3MB, 부록 B-5). 절대 목표치는 무의미하다 — 45MB 중 400KB 는 0.9% 다. `web_smoke` 가
  매 PR 에서 총량을 찍고 이전 태그 대비 증가분을 릴리스 빌드가 비교한다.
- **부록 B-4 는 정정판이다.** "웹 빌드가 깨진다" 를 어떤 잡의 근거로도 쓰지 않는다 — 실빌드가
  성공한다. 유효한 것은 **CI 미검증**(웹 빌드 스모크가 없다, P0-17)과 **B-4-4 웹 런타임 미확인**
  (빌드는 되지만 웹에서 종료 메뉴를 눌렀을 때의 동작이 확인되지 않았다)이다.

### 에디터

| # | 접합점 | 내용 |
|---|---|---|
| 1 | 앵커 오버레이 | **읽기 전용 의사 레이어**. 앵커를 놓거나 옮겨도 `anchors/<MAP>.json` 만 바뀌고 **맵 파일 `rev` 는 변하지 않는다**(D-27 · BP-36 R-36-21) |
| 2 | 앵커 인스펙터 | `확인키 ✅ / 부딪힘 ❌` 를 나란히 표시. **경고(⚠)가 아니라 정보(ⓘ)** 다(R-36-23b). 서버 응답의 `bump_gate_asymmetry` 유무로 판단하고 **에디터에 하드코딩하지 않는다** — 게이트가 제거되면(P0-18) 표시가 사라져야 한다(R-36-23c) |
| 3 | 도달 가능성 경고 | **WARN**, ERROR 아님. 앵커-타일 정합은 런타임 요구가 아니라 저작 품질 규칙이다(D-27) |
| 4 | `GET /api/ai/mapinfos` | 등록 15개 진단 — `resolved` / `resolvedExists` / `sameNameFile` / `verdict` / `suggest` / `hint` |
| 5 | 수정 제안 적용 | 기존 엔트리에 `json` 필드를 채운다. **신규 등록 경로는 손대지 않는다**(부록 H-4: `ai_api.ts:592` 는 이미 옳다) |
| 6 | `preview.png` 확장 | 앵커·퀘스트 오버레이 옵션 |
| 7 | 팩 없는 환경 | 앵커 레이어와 경고가 **통째로 숨는다.** `validateMap` 을 확장하지 않으므로 팩 없는 사용자에게는 서버 응답이 **바이트 단위로 동일**하다(BP-36 R-36-23) |

**region 기반 기능은 만들지 않는다.** D-28 이 BP-26 T1(로더 승격)을 최종 기각했고,
`map_loader.dart` 는 수정하지 않는다. `[권장 타일 놓기]` 버튼은 `trigger`·`battle(step_on)` 앵커에
**표시하지 않는다** — 놓을 타일이 없고 서버도 no-op 이다(R-36-22a).

## 착수 조건

GATE-1 통과 + P2-05 완료(+ `content-sim-golden`·`content-fuzz-smoke` 는 P2-04·P2-06).

**왜 그 전에는 안 되는가**: CI 잡은 **돌릴 커맨드가 있어야** 만든다. 솔버가 없는데 `content-solve`
잡을 넣으면 main 이 빨개진 채 방치되거나(BP-35 §4.3 이 같은 함정을 명시), `|| true` 로 무력화된
잡이 남아 신뢰를 잃는다. 에디터 확장도 앵커 스키마(P1-10)와 콘텐츠 API(P2-01)가 확정된 뒤라야
표시할 대상이 있다. 그리고 GATE-1 이 보류로 나오면 게이트할 파이프라인 자체가 없다.

## GATE-1 이 보류/취소로 판정되면

- **버려지는 것**: `content-solve` · `content-sim-golden` · `content-fuzz-full` 잡, 골든 트레이스
  승인 흐름, 앵커 오버레이의 대량 표시(수백 개 앵커를 전제한 렌더 최적화).
- **그래도 남는 값 — 이 이슈는 잔여 가치가 큰 쪽이다**:
  - **`GET /api/ai/mapinfos` 진단과 수정 제안**은 AI 와 무관하다. 부록 D-1(등록 15개 중 7개가
    존재하지 않는 파일로 해석)은 **지금 실존하는 파손**이고, P0-01 이 데이터를 고친 뒤에도
    재발 방지 도구가 필요하다. 취소 시 이것만 P0 쪽으로 이관해 남긴다.
  - **부록 K 게이트 비대칭 표시**(2번)도 손 저작에 그대로 필요하다 — 사람이 앵커를 놓을 때
    오진을 막는 정보다.
  - **번들 증가분 감시**와 `web_smoke` 는 P0-17 이 이미 들고 있는 항목과 같은 성질이며 유효하다.
  - `check()` 에 인자를 늘리는 방식 자체는 P0-17 이 먼저 쓰므로 여기서 새로 생기는 값은 없다.
