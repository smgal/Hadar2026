# P2-07 8단계 생성 파이프라인

> **[보류 — DEFERRED]** 이 이슈는 **무거운 생성 파이프라인 노선**(콘텐츠 서버·MCP·솔버·퍼저·8단계 하네스)에 속한다.
> 2026-09-01 2차 판정([DECISION-LOG](../DECISION-LOG.md))이 노선을 **sample-first + cm2** 로 바꾸면서 보류되었다.
> 경량 대체는 [S3-generation/](../S3-generation/) 이다 — 생성 타깃이 선언적 콘텐츠 팩이 아니라 **cm2 + 맵 JSON** 이다.
> 설계는 [`blueprint/`](../../blueprint/00_README.md) 에 그대로 유효하게 남아 있다.

- **상태**: GATED
- **구간**: P2
- **규모**: L
- **선행**: P2-01 · P2-05
- **설계 근거**: [BP-32](../../blueprint/32_generation_harness.md) · [BP-30 §3](../../blueprint/30_toolchain_overview.md) · [D-14 · D-01 · D-12 · D-15](../../blueprint/_meta/DECISIONS.md)

## 문제

부품(서버·솔버·시뮬레이터·검증)이 다 있어도 **그것을 순서대로 굴리고 실패를 어디로 되돌릴지
정하는 것**이 없으면 생성은 성립하지 않는다. 지금은 그 오케스트레이터가 없다.

없으면 생기는 일:
- 실패가 **어느 단계의 실패인지** 구분되지 않는다. 스키마 위반과 완주 불가와 문체 미달이 같은
  "실패" 로 뭉치면 재시도 대상을 고를 수 없다.
- 재개가 불가능하다. 8단계 중 6단계에서 죽으면 처음부터 다시 돌린다 — LLM 호출 비용이 그대로 반복된다.
- LLM 이 어느 단계에 관여하는지 경계가 없으면 **결정론이 무너진다.** D-01 은 런타임에 LLM 을 두지
  않기로 했고, 그 보증은 파이프라인이 LLM 을 특정 단계에 격리해야만 성립한다.

## 무엇을 할 것인가

8단계 각각의 입력/출력/주체/성공 판정/실패 행동/재개/비용 7항목은
[BP-32 §32.3](../../blueprint/32_generation_harness.md) 에, 컨텍스트 팩 조립 규칙은 §32.5,
결정론·manifest 는 §32.7 에 있다.

```
1 context → 2 outline → 3 draft → 4 bind → 5 lint → 6 sim → 7 critic → 8 commit
```

**LLM 은 2·3·7 단계에만 있다** (D-14). 1·4·5·6·8 은 **결정론적 프로그램**이다.
이 경계가 이 이슈의 핵심 불변식이고, 흐리면 재빌드 해시 일치(하드 게이트)가 성립하지 않는다.

| 단계 | 주체 | 접합점 |
|---|---|---|
| 1 context | 프로그램 | `hadar_content context`. BP-31 의 `GET /api/content/context` 와 **같은 코드** |
| 2 outline | **LLM** (Planner) | 출력은 `QuestOutline` 하나뿐. 콘텐츠 파일을 쓰지 않는다 |
| 3 draft | **LLM** (Writer, 2패스) | 패스 A=구조(모든 표시 문자열이 키), 패스 B=문장. 서로의 산출물을 고치지 않는다 |
| 4 bind | 프로그램 | 앵커 배치·맵 편집·참조 해소. **P2-01 의 서버를 통해서만** 쓴다(D-12 원칙 4) |
| 5 lint | 프로그램 | 스키마·참조·도달성·길이·인라인 한국어. P1-12 의 L1~L3 를 재사용 |
| 6 sim | 프로그램 | P2-04 시뮬레이터 + P2-05 솔버. 골든 비교 |
| 7 critic | **LLM** (Critic) | 소프트 축만 채점 — 아래 |
| 8 commit | 프로그램 | 통과분만 팩에 반영, `content.lock` 갱신, 변경 요약 |

**단계별 산출물은 파일이고 재개 가능해야 한다.** 실패는 그 단계에서 멈추고 다음으로 넘어가지 않는다.
디렉토리는 `content_gen/runs/<runId>/01_context/ … 08_commit/`.

**Critic 은 하드 게이트 판정 권한이 없다** (BP-32/37 이 정한 경계)
- 하드 게이트(스키마·미해결 참조 0·도달 불가 노드 0·사이클 0·문자열 키 누락 0·인라인 한국어 0·
  길이 상한·앵커-통행 충돌 0·솔버 완주 증명·재빌드 해시 일치·지식 범위)는 **5·6·8단계 프로그램이
  판정**한다. Critic 이 이 항목을 지적하면 하네스는 그 finding 을 **폐기하고 로그에 남긴다**.
- 반대로 **소프트 축(세계관 정합·인물 목소리·서사 구조·목표 명료성·문체·중복·통합성)은 기계가
  판정하지 않는다.** 이중 판정을 만들지 않는다 — 같은 항목을 프로그램과 Critic 이 각각 막으면
  통과 조건이 예측 불가능해지고, 어느 쪽을 고쳐야 하는지 알 수 없게 된다.
- Critic 이 통과라 해도 하드 게이트가 막으면 실패이며, 그 반대도 같다.

**격리와 배치**(BP-32 §32.3.2·§32.6): 스키마·참조 실패는 **최대 2회 재시도**(총 3회 호출),
3회 실패 시 그 퀘스트를 `quarantine/` 으로 격리하고 **다음 퀘스트로 진행**한다 — 배치 전체를 멈추지 않는다.

## 착수 조건

GATE-1 통과 + P2-01 완료 + P2-05 완료(+ 실질적으로 P2-04·P2-06 도 6단계가 소비한다).

**왜 그 전에는 안 되는가**: 파이프라인은 **부품의 배선**이다. 4단계는 서버 없이는 쓸 곳이 없고,
6단계는 솔버·시뮬레이터 없이는 판정할 수단이 없다. 배선을 먼저 만들면 실패 처리·재개 지점을
존재하지 않는 부품의 추정 동작에 맞춰 정하게 되고, 부품이 실제로 오면 전부 다시 정해야 한다.
그리고 이것이 GATE-1 이 직접 겨누는 대상이다 — "AI 가 줄일 수 있는 것이 병목인가" 의 답이
아니오라면, 8단계 오케스트레이터는 만들 이유가 없는 유일한 이슈다.

## GATE-1 이 보류/취소로 판정되면

- **버려지는 것**: 2·3·7단계(LLM 3종)와 그 재시도·격리 로직, `content_gen/runs/` 산출물 구조,
  manifest 의 모델·프롬프트 해시 기록, 배치 생성 전략, 컨텍스트 팩 예산 관리. **이 이슈에서
  버려지는 비율이 P2 중 가장 높다** — 8단계 중 3단계가 LLM 전용이고 나머지도 그것을 위한 배선이다.
- **그래도 남는 값**:
  - **1·4·5·6·8 의 결정론 파이프라인**은 손 저작에도 쓰인다: 사람이 쓴 초안을 `bind → lint → sim →
    commit` 으로 통과시키는 것이 곧 "저장 전 검증" 이다. 취소 시 이 5단계를 `hadar_content publish`
    같은 단일 커맨드로 축소해 남긴다.
  - **단계별 파일 산출 + 재개** 규약은 손 저작에서도 값이 있다 — 어디까지 통과했는지가 파일로 남는다.
  - **하드/소프트 게이트의 분리 원칙**은 문서상 값으로 남는다. 사람이 검수할 때도 "기계가 판정하는
    것" 과 "사람이 보는 것" 을 섞지 않는 규율은 그대로 유효하다.

## 완료 판정 기준

**[잠정 — GATE-1 통과 시 확정]**

- [ ] 8단계가 각각 `content_gen/runs/<runId>/0N_*/` 에 파일을 남기고, 중간 단계부터 **재개**된다
- [ ] LLM 호출이 **2·3·7 단계에서만** 발생한다(호출 로그로 확인)
- [ ] 1·4·5·6·8 단계를 같은 입력으로 두 번 돌리면 산출물 해시가 같다
- [ ] Critic 이 하드 항목을 지적하면 그 finding 이 폐기되고 로그에 남는다
- [ ] Critic `pass` + 하드 게이트 실패 → 커밋되지 않는다. 그 반대(Critic `revise` + 하드 전량 통과)도 커밋되지 않는다
- [ ] 4단계가 파일을 **직접 쓰지 않고** P2-01 서버를 경유한다(파일 쓰기 감시로 확인)
- [ ] 3회 실패한 퀘스트가 `quarantine/` 으로 가고 배치가 계속 진행된다
- [ ] `PROVEN + UNSUPPORTED` 인 팩이 커밋되되 "미활성" 으로 표시된다(D-26)

## 하지 않을 것

- 프롬프트 본문 작성·루브릭 운용 — P2-08.
- CI 배선 — P2-09.
- 런타임에 LLM 을 두는 어떤 것도(D-01). 파이프라인은 **오프라인 배치**다.
- Critic 에게 하드 게이트 권한을 주는 것. 반대로 소프트 축을 기계가 판정하게 하는 것도.
- 사람 승인 지점(HG-1~3) 자동화. 승인은 사람이 한다(BP-32 §32.8).
