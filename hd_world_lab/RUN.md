# hd_world 실험실 — 실행 참고

게임을 켜지 않고 **규칙을 만져 보는 곳**이다. 왜 이렇게 만들었는지는
[README.md](README.md), 규격은 [web/openapi.yaml](web/openapi.yaml).

## 준비 (한 번만)

```bash
cd hd_world_lab
dart pub get
```

**Flutter SDK 는 필요 없다.** 순수 Dart 라 `dart` 만 있으면 된다.

## 띄운다

```bash
dart run bin/serve.dart          # 5330 번
dart run bin/serve.dart 5331     # 다른 번호로
```

| 어디 | 무엇 |
|---|---|
| `http://127.0.0.1:5330/` | **화면.** 탭 다섯 |
| `/api/guide` | 도메인 안내 (markdown). 스크립트·에이전트가 먼저 읽을 것 |
| `/openapi.yaml` | 규격 전문 |

| 탭 | 무엇을 |
|---|---|
| **장비** | 사람 다섯에게 입히고 들린다. 집어서 부위 칸에 놓는다 |
| **가방** | 물건 도감 전량. 안 가진 것은 검은 칸으로 남는다 |
| **전투** | 격자에서 한 판. 물음마다 멈춰 서고 마우스로 고른다 |
| **플래그** | 시나리오. 켜고 끄고, 단계를 옮긴다 |
| **기록** | 앞의 넷을 한 장으로. **읽는 탭이다** — 고치는 단추가 없다 |

앞의 넷이 고치는 곳이고 마지막이 읽는 곳이다. 같은 것을 두 자리에서
고칠 수 있으면 어느 쪽이 진짜인지 헷갈린다.

**오른쪽 기둥도 탭을 따라간다.** 물건 설명과 「바꾸면 뭐가 달라지나」는
장비·가방에서만 열리고, 색 범례는 탭마다 다른 것을 말한다 — 파랑이
장비에서는 「차고 있다」이고 플래그에서는 「끝난 단계」다. 「일어난 일」만
어디서나 보인다.

**단추는 그것이 바꾸는 것 옆에 둔다.** 「마법의 횃불」이 머리글이 아니라
파티 요약 줄에 있는 것은 그 줄에 있는 셋(어둠 속 시야 · 횃불 든 사람 ·
달빛)이 바로 그것이 바꾸는 값이기 때문이다. 켜고 그 자리에서 시야가
1 → 2 로 오르는 것을 본다.

**인증이 없다.** 메모리 안의 세계 하나를 읽고 쓰는 1인 개발 서버라
localhost 밖으로 낼 것을 전제로 만들지 않았다.

# 장비 · 가방 탭

## 화면 읽는 법

칸 하나가 물건 하나다. **모양이 그것이 무엇인지를, 색이 지금 어떤지를**
말한다. 둘을 한 칸에 겹쳐 칠하지 않는 것이 이 화면의 전부다.

| 색 | 뜻 |
|---|---|
| 검정 | 없다 — 빈 부위이거나 가지고 있지 않은 것. 부위 칸에는 무엇이 들어가는지 유령으로 비친다 |
| 파랑 | 고른 사람이 차고 있다 |
| 보라 | 다른 사람이 차고 있다 |
| 초록 | **여기 채울 수 있다** |
| 빨강 | 채울 수 없다 — 칸에 마우스를 대면 까닭이 나온다 |
| 회색 | 잠겼거나 차는 것이 아니다 (양손 무기에 막힌 왼손, 소비품) |

**빨강과 회색을 가르는 선이 요점이다.** 못 채우는 것은 빨강이고,
물을 수조차 없는 칸은 회색이다.

무기 글리프는 갈래(베다·찍다)가 아니라 **생김새**(날·도끼·활)로 고른다.
갈래는 묶음 머리글의 점과 검색어가 말한다.

## 손이 하는 일

| 어디에 | 무엇을 | 무슨 일 |
|---|---|---|
| 가방 칸 | 누른다 | 집는다. 그 순간 부위 칸 마흔이 초록·빨강으로 물든다 |
| 부위 칸 | 누른다 | 집은 것을 채운다. 안 집었으면 그 칸을 고른다 |
| 부위 칸 | 오른쪽 단추 | 벗긴다 |
| 가방 칸 | 끌어다 부위 칸에 | 채운다. 남의 손에 있던 것은 가방을 거쳐 간다 |
| 가방 칸 | Shift · Alt | 하나 넣는다 · 하나 뺀다 |
| 요약 줄 | 「마법의 횃불」 | 손을 안 쓰는 대신 시야가 2 밖에 안 된다 |
| 어디서나 | `/` · `Esc` | 검색으로 · 집은 것을 놓는다 |

탭을 옮기면 집은 것을 놓는다. 장비에서 집은 물건을 든 채로 플래그 탭에
가 있으면 돌아왔을 때 왜 칸이 물들어 있는지 모른다.

**가리키기만 해도 오른쪽에 「바꾸면 뭐가 달라지나」 가 나온다.** 끼워 보고
되돌릴 필요가 없다 — 사본에 굴려 차이만 가져온다.

## 검색

`/` 를 누르고 친다. DIM 의 질의어를 이 도메인으로 옮긴 것이다.

| 친다 | 나온다 |
|---|---|
| `활` | 이름·갈래·생김새에 그 글자가 있는 것 |
| `is:착용` | 지금 누군가 차고 있는 것 |
| `is:겹침` | 가방에 둘 이상 있는 것 |
| `is:맞는것` | **지금 고른 사람의 고른 부위에 들어가는 것** |
| `is:양손` `-is:양손` | 양손 무기 · 양손이 아닌 것 |
| `kind:slash` `갈래:베는` | 갈래로 |
| `slot:leftHand` `부위:왼손` | 그 부위에 들어갈 수 있는 것 |
| `power>40` | 공격력으로 |

## 해 볼 것

| 해 볼 것 | 무엇이 보이나 |
|---|---|
| 장검을 **집기만** 한다 | 아트리아 왼손이 빨강이 된다. 대면 `양손 무기는 왼손에 들 수 없다` |
| 그대로 오른손 칸에 **댄다** | 오른쪽에 방패가 빠지고 방어 4→2, 무기 종류가 `대검`이 될 것이라고 나온다 |
| 눌러서 채운다 | 왼손이 **회색**으로 잠긴다. 잠긴 칸에는 자물쇠가 그려진다 |
| 그 옆에 **단검** | 샤벨과 짝이 되어 `쌍수`. 도포 칸이 2 로 오른다 |
| 대신 **소형 도끼** | `같은 갈래의 무기여야 짝이 된다` — 빨강 |
| **물의 부적**을 집는다 | 다섯 사람 공통 부적 칸이 다 초록. 대면 파티가 `물위를 걸음` 을 얻는다고 나온다 |
| 수하일에게 **서약의 문장** | `이 사람의 직업이 찰 수 있는 것이 아니다` |
| 같은 것을 **공통 부적** 칸에 | `그 부위에 채우는 것이 아니다` — **다른 문장이다** |

마지막 두 줄이 요점이다. 자리가 틀린 것과 직업이 틀린 것은 다른 답이어야 한다.

## 구성을 담아 두고 견준다

오른쪽 **「지금 것을 담아 둔다」** 가 지금 입고 든 것 전부를 이름 붙여
기록하고, **「입힌다」** 가 그대로 되돌린다. 횃불 파티와 쌍수 파티를 오가며
같은 싸움을 굴려 보는 것이 이 실험실을 여는 이유다.

입히는 것은 **보통의 명령 묶음**이다. 그래서 손으로 갈 수 없는 상태에는
이것으로도 못 가고, 못 채운 것은 조용히 빠지는 대신 기록창에 남는다.

> 전원을 벗겼다 다시 입히므로 가방 종류 한도에 걸려 거절이 날 수 있다.
> 그때 물건은 원래 팔에 남아 결과는 맞는다. **「제자리에 갔나」와
> 「거절이 있었나」는 다른 물음**이고 화면은 앞엣것을 말한다.

# 전투 탭 — 격자가 규칙이다

위치는 좌표가 아니다. **각자의 열(1~3) 과 양측 공통의 간격(0~2)** 이고
거리는 이렇게 난다.

```
거리 = 간격 + (내 열 - 1) + (상대 열 - 1)
```

식을 읽게 하는 대신 그렸다. **y 축이 거리다.**

```
아트리아 기준 — 1열 · 사거리 1. 아래 거리는 전부 이 사람에게서 잰 것이다.

 적 3열            ───────────────────── (비어 있음)
 적 2열            ───────────────────── (비어 있음)
 적 1열   거리 1 |  👤 Orc#1   👤 Orc#2   🐺 Wolf      [닿는다]
 간격 1           ┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄┄
 아군 1열         |  아트리아 240/240 ←묻는중   안카라
 아군 2열         |  머큐리   수하일
 아군 3열         |  유리
```

세 가지를 화면이 지킨다.

- **거리는 「누구에게서인지」가 있어야 뜻이 된다.** 격자 맨 위에 기준이
  되는 사람과 그 사람의 열·사거리가 적힌다. 뒷열 사람 차례에는 같은 적
  1열이 「거리 3」 으로 나오는데, 그것을 앞열 줄을 보며 읽으면 1열 대
  1열이 3인 줄 안다.
- **판정은 줄 단위다.** 「왜 못 때리지」 의 답은 칸 하나가 아니라 줄
  하나다 — 같은 열은 전부 같은 거리다. 닿는 줄은 초록빛, 못 닿는 줄은
  붉은빛에 `2칸 부족` 배지가 붙는다.
- **비어 있는 열은 실선 하나로 접는다.** 거리를 줄마다 숫자로 적으므로
  줄을 셀 필요가 없고, 빈 줄이 땅처럼 읽히지도 않는다.

대열을 당기면 간격 줄이 빠지고 모두가 한꺼번에 가까워진다. 「우리가
나아간다」 와 「그들이 다가온다」 가 같은 사건인 것이 그래서 보인다.

## 1열 대 1열의 거리는 간격 그 자체다

열은 아무것도 더하지 않는다 — `간격 + (1-1) + (1-1)`.

| 간격 | 아트리아(1열 · 사거리 1) → 적 1열 | |
|---|---|---|
| 0 | 거리 **0** | 닿는다 |
| 1 | 거리 **1** | 닿는다 |
| 2 | 거리 **2** | 1칸 부족 |

**뒷열은 원래 안 닿는다.** 유리(3열)에게 단검(사거리 1)을 쥐어 주면 간격
0에서도 거리 2라 못 닿는다. 고장이 아니라 요점이다 — 붙거나(charge) 대열을
당기라(⚙지시 → 앞으로)는 뜻이다.

**사거리 밖도 누를 수 있다.** 불변식 하나가 「사거리 밖은 벌점이지 무효가
아니다」 라서, 멀리 있는 적을 못 누르게 만들면 그 불변식이 화면에서
깨진다. 대신 판정이 붙는다.

```
1칸 부족 · 명중 -6 · 앞열이 대신 30%
3칸 부족 · 명중 -14 · 앞열이 대신 55%
```

## 적 아이콘 — 모양 24 × 고유색

적이 75 종이고 칸은 44 픽셀이다. 그 크기에 알아볼 수 있는 선화는 스물
남짓이라 **모양과 색을 곱했다.**

| 무엇이 | 말하는 것 |
|---|---|
| 모양 24 | 무엇에 가까운가 — 사람꼴 · 짐승 · 뱀 · 벌레 · 뼈 · 혼 · 용 · 돌 · 기계 … |
| 색 | 그 **종류**의 것. 붉은 용과 푸른 용은 같은 모양 다른 것 |
| 왼쪽 위 번호 | **같은 종류가 둘 이상일 때만.** 오크 둘은 1 · 2 |

75 종 전부 모양+색 조합이 유일하다(`test/server_test.dart` 가 표를
지킨다). 적이 늘면 `web/foes.js` 에 줄을 더한다 — 빠뜨리면 화면이 켜질
때 기록창에 「아이콘이 없는 적」 이라고 나온다.

**적 아이콘의 색만 상태가 아니다.** 칸 테두리는 장비 탭과 같은 말을
한다: 초록이면 누를 수 있고, 파랑이면 지금 묻고 있는 사람이고, 흐리면
쓰러진 것이다.

## 손이 하는 일

| 물음 | 어떻게 답하나 |
|---|---|
| 무엇을 할까 | 여섯 줄에서 고른다 (⚔공격 ✨기술 🎒물건 🛡버팀 🏃도망 ⚙지시) |
| **누구를 칠까** | **격자에서 초록 테두리가 난 적을 누른다** |
| 누구에게 | 아래쪽 아군 중 초록을 누른다 |
| 어떤 기술을 | 한 목록이다. 글자가 범위를 말한다 (🎯한 명 💥전체 💚치료) |

**답해도 판이 바로 굴러가지 않는다.** 라운드 시작에 전원 명령 → 일괄
해결이라, 대열을 당기라고 해도 나머지가 다 답한 뒤에 움직인다. 드래곤
퀘스트의 박자다.

## 판을 짠다

적 75 종에서 눌러 담고(최대 여덟), 간격과 씨앗을 정하고 **「싸운다」**.
씨앗이 같으면 결과도 같다.

간격은 **0 으로 연다** — 0 이 붙어서 시작하는 보통의 조우이고, 1 로 열면
사거리 1 짜리가 겨우 닿는 자리에서 시작해 무엇이 규칙이고 무엇이
우연인지 가려진다. 2 는 먼저 발견했을 때다.

**「자동으로 끝까지」** 는 전부 「가장 가까운 것을 친다」 로 답하고 끝을
본다 — 장비가 낸 숫자만 보고 싶을 때 쓴다.

```
1라운드, 이겼다. (3마리, 씨앗 7)
  아트리아 검과 방패(사거리 1) 체력 240→240 · 경험치 +86
  안카라 창과 방패(사거리 2) 체력 190→186 (−4) · 경험치 +76
  머큐리 대검(사거리 2) 체력 195→195 · 경험치 +66
  수하일 장봉(사거리 2) 체력 68→68 · 경험치 +66
  유리 활(사거리 3) 체력 165→165 · 경험치 +76
```

끝나면 **「결과를 파티에 얹는다」** 가 체력·경험치·쓴 물건을 세계에
반영한다. 한 번만 얹는다.

## 장비가 싸움에서 값을 내는지

장비 화면은 활이 3열까지 닿는다고 말하지만, 그것이 싸움에서 무슨 차이를
만드는지는 한 판 굴려야 보인다.

| 해 볼 것 | 무엇이 보이나 |
|---|---|
| 유리의 활을 빼고 **단검** | 사거리 3 → 1. 3열에서는 아무것도 못 친다 |
| 아트리아에게 **장검** | `대검`, 사거리 2. 방패가 빠져 방어가 내려간다 |
| 샤벨 옆에 **단검** | `쌍수`. 한 행동에 **두 번** 친다 |
| 왼손에 **횃불** | 손이 차서 회피 +4 와 선제 +5 가 사라진다 |

# 플래그 탭 — 시나리오

플래그를 켜고 끄고, 단계를 옮긴다. 칸마다 **날값과 사람 말이 같이** 나온다.

```
┌ D4-041 ────────────────── 물의 정령과 합류했다 ──── [켜짐] ┐
│ Flag::IsSet(41) = 1    GFD4_JOINNED_SOUL_OF_WATER          │
│ 불을 끄고 (12,16) 에 서면 스스로 빛을 내는 것이 보인다.    │
│ 호의를 보이면 물의 정령이 일행에 들어온다 …                │
│ [LORE 지하 4층 (12,16)] [L1_ep1d4.cm2]                     │
│ ⚠ 불을 켜 두면 일어나지 않는다.                            │
└────────────────────────────────────────────────────────────┘
```

숫자만 보면 고칠 수는 있어도 뜻을 모르고, 문장만 보면 무엇을 고치는지
모른다. 그래서 둘 다 늘 보인다.

## 갈래가 둘이다 — 원작이 그렇기 때문이다

| 갈래 | cm2 | 답하는 것 |
|---|---|---|
| **켜짐/꺼짐** | `Flag::Set` · `Reset` · `IsSet` | 했나 안 했나 |
| **단계** | `Variable::Set` · `Add` · `Get` | 어디까지 왔나 |

단계는 값 하나가 **여러 사실**을 담는다. `W-010` 이 3이면 0·1·2 는 끝났고
3을 하는 중이다 — 화면이 그 셋을 다른 색으로 갈라 준다(파랑 끝남 ·
초록 하는 중 · 검정 아직). 켜짐 셋으로 쪼개지 않는 것은 단계를 건너뛸 수
없다는 사실을 값 하나가 스스로 지키기 때문이다.

```
W-010  Lord Ahn 의 이야기            Variable::Get(10) = 3    3 / 5
  0  아직 성주를 만나지 않았다…                      ← 파랑 (끝남)
  1  이름을 들었다 — 「나는 Lord Ahn 이오」           ← 파랑
  2  세계의 내력을 들었다 — 푸른 번개, Necromancer   ← 파랑
  3  MENACE 탐사를 의뢰받았다                        ← 초록 (하는 중)
  4  MENACE 를 탐사하는 중                           ← 검정 (아직)
  5  탐사가 끝난 뒤. 아직 안 만들었다                ← 검정
```

줄을 누르면 그 단계로 옮긴다.

## 시나리오가 활동 반경을 넓힌다

플래그가 파티의 **통행 능력**을 열 수 있다. 물 위를 걷는 것은 이제 출처가
셋이다.

| 출처 | 언제까지 |
|---|---|
| 부적 | 차고 있는 동안 |
| 마법 | 남은 칸 수만큼 |
| **시나리오** | **한 번 배우면 영영.** 쉬어도 안 줄고 꺼지지 않는다 |

`W-060` 을 켜 보면 위쪽 파티 줄에 **★ 물위를 걸음** 이 붙는다. ★ 가
시나리오에서 온 것이라는 표시다 — 왜 안 꺼지는지를 묻게 되는 자리라
출처를 남긴다.

`hd_world` 는 플래그를 모르고 **몰라야 한다.** 아는 순간 모델이 시나리오에
매인다. 둘을 합치는 것은 읽는 쪽의 일이다.

## 이 표가 찾아낸 것

`flag4ep1.cm2` 를 include 하지 않고 번호를 직접 쓰는 스크립트가 셋 있다
(`lore_ep1.cm2` · `town2.cm2` · `menace.cm2`). 그래서 **번호 셋이
겹친다.**

| 번호 | 한쪽 | 다른 쪽 |
|---|---|---|
| 10 | `GFD1_WALL_REMOVER_USED` (지하 1층) | `menace.cm2` |
| 31 | `GFD3_OPEN_WEST_DOOR` (지하 3층) | `lore_ep1.cm2` 수련장 |
| 50 | `GFD5_PUSH_BIG_STONE` (지하 5층) | `lore_ep1.cm2` 유골 안치소 |

게임이 아는 것은 번호뿐이라 **저장된 파일에는 한 칸**이다. 플래그 탭 위쪽이
이것을 경고로 띄운다.

그리고 이름이 아예 없는 칸이 여섯이다 (32 · 51~55). 플래그 탭에서 빨간
왼쪽 선으로 나온다.

**고칠지는 아직 정하지 않았다.** 겹침이 실제로 도달 가능한지 확인이
먼저고, 번호를 옮기면 기존 세이브가 깨진다.

## 검색

장비 탭의 검색이 여기서도 돈다.

| 친다 | 나온다 |
|---|---|
| `물의` | 이름·설명·장소·스크립트에 그 글자가 있는 칸 |
| `is:켜짐` `is:꺼짐` | 값으로 |
| `is:단계` | 단계로 세는 칸만 |
| `is:이름없음` | cm2 가 번호로만 쓰는 칸 |
| `is:미구현` | 아직 어느 스크립트도 안 쓰는 칸 |

## 새 플래그를 더하려면

1. `lib/quest/flag_registry.dart` 에 `FlagDef` 한 줄
2. 스크립트에 넣을 것이면 `hadar2026_app/assets/flag4ep1.cm2` 에 상수도
3. `dart test test/quest_registry_test.dart`

셋째가 요점이다. 그 시험이 `flag4ep1.cm2` 와 출하 스크립트 전량을 **실제로
읽어** 맞춰 본다 — 이름을 빠뜨리거나 번호를 틀리거나 스크립트가 쓰는데
설명을 안 적으면 거기서 걸린다.

# 기록 탭 · 세이브

기록 탭이 세계 · 일행 · 시나리오 · 담아 둔 구성을 한 장으로 보인다. **고치는
단추는 없다** — 무엇을 바꾸든 그것을 하는 자리가 따로 있다.

머리글의 **내려받기 / 불러오기**. `hd_world` 의 저장 형식에 `quest` 를
하나 더 얹은 것이라 **장비와 플래그가 한 파일에 같이** 간다. 다시 계산할
수 있는 것은 하나도 안 들어간다 — 무기 종류도 최종 수치도 통행 능력도
읽을 때 계산된다.

이 빌드에 없는 물건을 가리키는 칸은 **조용히 빠지지 않는다.** 비워지고
기록창에 남는다. 설명이 없는 플래그도 플래그 탭에 드러난다.

게임 쪽 세이브(`hadar_save_N`)의 `gameOption` 을 `POST /api/load` 의
`quest` 칸에 그대로 넣으면 읽는다(256칸 배열 꼴도 읽는다).

# 명령으로 굴린다

화면 없이 같은 것을 한다. 한 번의 왕복에 이벤트와 새 상태가 함께 온다.

```bash
curl -s localhost:5330/api/state | jq '.members[] | {name, weaponKind, attackPower}'

curl -s -X POST localhost:5330/api/command \
  -H 'content-type: application/json' \
  -d '{"command":{"kind":"equip","member":"knight","slot":"rightHand","item":"weapon.long_sword"}}' \
  | jq '.events'

curl -s 'localhost:5330/api/candidates?member=paladin&slot=leftHand' | jq

# 판 전체 — 사람마다, 물건마다, 부위 여덟이 true 또는 거절 이유
curl -s localhost:5330/api/eligibility \
  | jq '.members.knight["weapon.long_sword"]'

# 적용하지 않고 차이만 본다
curl -s -X POST localhost:5330/api/preview \
  -H 'content-type: application/json' \
  -d '{"command":{"kind":"equip","member":"knight","slot":"rightHand","item":"weapon.long_sword"}}' \
  | jq '.changes.members[0].changes'

# 담고 · 입힌다
curl -s -X POST localhost:5330/api/loadouts \
  -H 'content-type: application/json' -d '{"op":"capture","name":"base"}' > /dev/null
curl -s -X POST localhost:5330/api/loadouts \
  -H 'content-type: application/json' -d '{"op":"apply","name":"base"}' \
  | jq '{landed, mismatch}'

# 사람이 두는 한 판 — 물음마다 멈춘다
curl -s localhost:5330/api/enemies | jq '.enemies | length'

curl -s -X POST localhost:5330/api/battle/start \
  -H 'content-type: application/json' \
  -d '{"enemyKeys":["orc","wolf","dragon"],"enemyRanks":[1,1,3],"initialGap":0,"seed":11}' \
  | jq '{round, gap, enemies: [.enemies[] | {name, rank, distance, reachVerdict}]}'

curl -s -X POST localhost:5330/api/battle/command \
  -H 'content-type: application/json' \
  -d '{"command":{"type":"action","slot":0,"action":"attack"}}' \
  | jq '.decision'

curl -s -X POST localhost:5330/api/battle/settle | jq '{result, members}'

# 자동으로 한 판. 씨앗이 같으면 결과도 같다
curl -s -X POST localhost:5330/api/battle \
  -H 'content-type: application/json' \
  -d '{"enemyKeys":["orc","orc","wolf"],"seed":7}' \
  | jq '{result, rounds, members: [.members[] | {name, weaponKind, reach}]}'

# 플래그 — 날값과 뜻이 같이 온다
curl -s localhost:5330/api/quest | jq '.flags[] | select(.id=="D4-041")'
curl -s localhost:5330/api/quest | jq '{summary, granted, collisions}'

# 켠다 · 단계를 옮긴다 · 전부 끈다
curl -s -X POST localhost:5330/api/quest \
  -H 'content-type: application/json' -d '{"id":"W-060","on":true}' \
  | jq '.granted'
curl -s -X POST localhost:5330/api/quest \
  -H 'content-type: application/json' -d '{"id":"W-010","kind":"step","value":3}' \
  | jq '.flags[] | select(.id=="W-010") | {raw, stepStates}'
curl -s -X POST localhost:5330/api/quest \
  -H 'content-type: application/json' -d '{"op":"reset"}' > /dev/null

# 세이브를 내보내고 다시 넣는다 — 장비와 플래그가 같이 간다
curl -s localhost:5330/api/save > /tmp/world.json
curl -s -X POST localhost:5330/api/load \
  -H 'content-type: application/json' -d @/tmp/world.json | jq '.issues'

curl -s -X POST localhost:5330/api/reset > /dev/null
```

**거절도 200 이다.** `kind: refused` 이벤트에 `reason` 이 실리고 세계는 그대로다.
읽을 수 없는 JSON 만 400 이고, 그때는 어느 칸이 틀렸는지와 **고를 수 있는 값**을 준다.

# 아직 여기 없는 것

- **지도 · 위치 · 소지금** — 게임 쪽 세이브에 있고 아직 안 온다.
- **인물의 레벨 · 능력치 · 직업** — 고치는 명령이 `hd_world` 에 없다.
  장비 · 가방 · 지시만 고칠 수 있다.
- **되돌리기** — 모든 변경이 이미 값이라 쌓기만 하면 된다.
- **대열 바꾸기** — API 에는 있고 화면에 없다. 자리 번호가 곧 신원이라
  cm2 가 손보는 사람이 옮겨진다.
- **전투 fixture 를 실험실에서 만드는 것** — `hd_battle_console` 의
  fixture 와 이쪽 판이 아직 오가지 않는다.
