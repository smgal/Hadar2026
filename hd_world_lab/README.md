# hd_world 실험실 — 왜 이렇게 만들었나

게임을 켜지 않고 **규칙을 만져 보는 곳**이다. 장비를 갈아 끼우고, 그
장비로 한 판 싸우고, 시나리오 플래그를 켜고 끈다. 실행 방법은
[RUN.md](RUN.md), 규격은 [web/openapi.yaml](web/openapi.yaml).

## 왜 콘솔이 아닌가

`hd_battle_console` 이 전투에 한 일을 여기서도 하지만, **터미널이 아니다.**

전투는 「1) 공격 2) 기술 …」 처럼 **한 번에 한 물음**이라 터미널이 잘
맞았다. 장비와 시나리오는 그렇지 않다.

- 부위가 여덟이고 **동시에 보여야** 한다 — 왼손을 채우면 오른손이 잠긴다
- 고칠 때마다 **최종 수치가 다시 계산**되고, 그 차이를 보려고 만지는 것이다
- 후보가 예순을 넘는다. 번호를 외워 누르는 일이 아니다
- 플래그가 마흔이 넘고 서로 얽힌다. 목록을 스크롤하며 켜는 일이 아니다

그래서 화면 하나와 API 하나를 둔다. **모델이 이미 명령과 사실로 말하기
때문에** 둘이 같은 문을 쓴다.

| 누가 | 어떻게 |
|---|---|
| 사람 | `GET /` 의 화면. 마우스 |
| 스크립트 | `POST /api/command` 류. JSON |
| 에이전트 | `GET /api/guide` 를 먼저 읽고 같은 명령을 쓴다 |

## 탭 다섯

| 탭 | 무엇을 | 무엇을 기대는가 |
|---|---|---|
| **장비** | 다섯에게 입히고 들린다 | `hd_world` |
| **가방** | 물건 도감 전량 | `hd_world` |
| **전투** | 격자에서 한 판, 물음마다 멈춘다 | `hd_battle` + `hd_bridge` |
| **플래그** | 시나리오를 켜고 끄고 단계를 옮긴다 | 이 패키지의 `lib/quest/` |
| **기록** | 앞의 넷을 한 장으로. **읽는 탭** | — |

앞의 넷이 고치는 곳이고 마지막이 읽는 곳이다. 같은 것을 두 자리에서
고칠 수 있으면 어느 쪽이 진짜인지 헷갈린다.

## 1. 왜 글자가 아니라 아이콘인가

첫 판은 줄글이었다. 한 줄에 이름과 보정과 까닭을 적으니 부위 여덟이
세로로 길어져 **동시에 보여야 한다**는 조건이 깨졌고, 무엇이 되고 무엇이
안 되는지는 눌러 봐야 알았다.

지금은 칸 하나가 물건 하나다. 그리고 두 가지를 **나눠서** 말한다.

| 칸의 | 말하는 것 |
|---|---|
| 모양 | 그것이 무엇인가 — 날 · 도끼 · 활 · 방패 |
| 색 | 지금 그것이 어떤가 — 없다 · 찼다 · 된다 · 안 된다 · 잠겼다 |

한 칸에 둘을 겹쳐 칠하면 둘 다 안 읽힌다. 그래서 글리프는 선으로만
그리고 칠하지 않는다(`web/index.html` 의 sprite, `web/icons.js` 의 표).

가장 값이 나가는 것은 **집으면 판 전체가 물드는 것**이다. 물건 하나를
집는 순간 다섯 사람 × 부위 여덟이 초록과 빨강으로 갈린다 — 어디에 쓸 수
있는 물건인지를 한 번에 본다. 그렇게 하려면 `checkEquip` 의 답이 마흔 칸
분량으로 미리 와 있어야 하고, 그것이 `GET /api/eligibility` 다.

**빨강과 회색은 다른 색이다.** 못 채우는 것은 빨강이고 물을 수조차 없는
칸은 회색이다 — 이 화면이 처음부터 지키려던 구분(자리가 틀린 것과 직업이
틀린 것은 다른 문장이다)이 색까지 내려온 것이다.

## 2. 바꾸기 전에 답한다

이 화면을 여는 이유는 하나다. **바꾸면 뭐가 달라지나.** 그것을 알려고
끼워 보고, 읽고, 되돌리는 것은 한 물음을 세 동작으로 만들고 그 사이에
바꾸기 전의 그림을 잃는다.

`POST /api/preview` 가 사본에 굴려 차이만 돌려준다. 사본은 `saveWorld` →
`loadWorld` 왕복이다 — 저장 형식이 이미 "다시 계산할 수 없는 것 전부" 로
정의돼 있고 그것이 곧 복사가 실어야 할 것의 정의이기 때문이다. 손으로 쓴
복사는 그 목록을 한 벌 더 만드는 일이고, 두 목록은 언젠가 갈라진다.

## 3. 격자가 전투 규칙이다

`hd_battle` 의 위치는 좌표가 아니다. 각자가 **열**(1 앞 ~ 3 뒤)을 갖고,
양측이 **간격** 하나(0~2)를 나눠 갖는다.

```
거리 = 간격 + (내 열 - 1) + (상대 열 - 1)
```

식을 읽게 하는 대신 그렸다. **y 축이 거리다** — 위가 적, 아래가 아군,
가운데 점선이 간격. 대열을 당기면 점선 줄이 빠지고 모두가 한꺼번에
가까워진다. 「우리가 나아간다」 와 「그들이 다가온다」 가 같은 사건인 것이
그래서 보인다.

세 가지를 화면이 지킨다.

- **거리는 「누구에게서인지」가 있어야 뜻이 된다.** 격자 위에 기준이 되는
  사람과 그 사람의 열·사거리를 못박는다. 없으면 뒷열 사람 차례에 적
  1열이 「거리 3」 으로 나오고, 그것을 앞열 줄을 보며 읽으면 1열 대 1열이
  3인 줄 안다.
- **판정은 줄 단위다.** 「왜 못 때리지」 의 답은 칸 하나가 아니라 줄
  하나다 — 같은 열은 전부 같은 거리다.
- **사거리 밖도 누를 수 있다.** B5 의 불변식이 「사거리 밖은 벌점이지
  무효가 아니다」 이므로, 멀리 있는 적을 못 누르게 만들면 그 불변식이
  화면에서 깨진다.

비어 있는 열 줄은 실선 하나로 접고 거리를 숫자로 적는다. 줄을 세게 하면
적이 전부 앞열에 있어도 위의 빈 두 줄이 거리처럼 읽힌다.

### 적 75 종 — 모양 24 × 고유색

칸이 44 픽셀이다. 그 크기에 알아볼 수 있는 선화는 스물 남짓이라 75 개를
다 다르게 그리면 절반이 서로 구별되지 않는 낙서가 된다. 그래서 **곱했다**
(`web/foes.js`).

| 무엇이 | 말하는 것 |
|---|---|
| 모양 24 | 무엇에 가까운가 — 사람꼴 · 짐승 · 뱀 · 벌레 · 뼈 · 혼 · 용 · 돌 · 기계 … |
| 색 | 그 **종류**의 것. 붉은 용과 푸른 용은 같은 모양 다른 것 |
| 왼쪽 위 번호 | **같은 종류가 둘 이상일 때만** |

75 종 전부 모양+색 조합이 유일하다. 혼자 있는 적에게 번호를 안 붙이는
것은 읽을 것이 하나 늘 뿐이기 때문이다. 번호를 매기는 것은 서버다 —
같은 판에 몇이 있는지는 서버가 안다.

**적 아이콘의 색만 상태가 아니다.** 칸 테두리는 장비 탭과 같은 말을
한다: 초록이면 누를 수 있고, 파랑이면 지금 묻고 있는 사람이다.

## 4. 플래그에 뜻을 붙인다

게임이 아는 것은 번호뿐이다. `Flag::Set(41)` 은 41번을 켤 뿐이고, 그것이
무엇을 뜻하는지는 그 줄 옆의 주석과 사람의 기억에만 있다.
`assets/flag4ep1.cm2` 가 이름을 붙이지만 이름도
`GFD4_JOINNED_SOUL_OF_WATER` 까지다 — **언제 켜지는지 · 켜지면 무엇이
열리는지 · 지금 켜져 있는 것이 정상인지**는 아무 데도 없다.

그래서 `lib/quest/flag_registry.dart` 가 그 셋을 적는다. 칸마다 **날값과
사람 말이 같이** 나온다.

```
D4-041  물의 정령과 합류했다                          [스위치]
Flag::IsSet(41) = 1    GFD4_JOINNED_SOUL_OF_WATER
불을 끄고 (12,16) 에 서면 스스로 빛을 내는 것이 보인다 …
[LORE 지하 4층 (12,16)] [L1_ep1d4.cm2]
⚠ 불을 켜 두면 일어나지 않는다.
```

숫자만 보면 고칠 수는 있어도 뜻을 모르고, 문장만 보면 무엇을 고치는지
모른다.

### 갈래가 둘인 것은 원작이 그렇기 때문이다

| 갈래 | cm2 | 답하는 것 |
|---|---|---|
| 켜짐/꺼짐 | `Flag::Set` · `Reset` · `IsSet` | 했나 안 했나 |
| 단계 | `Variable::Set` · `Add` · `Get` | 어디까지 왔나 |

단계는 값 하나가 **여러 사실**을 담는다. 3이면 1과 2는 끝났고 3을 하는
중이다. 켜짐 셋으로 쪼개지 않는 것은 단계를 건너뛸 수 없다는 사실을 값
하나가 스스로 지키기 때문이다.

### 저작 자료이지 런타임이 아니다

게임은 이 표를 읽지 않는다. cm2 는 지금처럼 번호로 돈다. 그러므로 표는
**어긋날 수 있고**, 어긋나지 않게 하는 것은
`test/quest_registry_test.dart` 다 — `flag4ep1.cm2` 와 출하 `*.cm2`
전량을 **실제로 열어** 맞춰 본다. 스크립트가 쓰는데 설명이 없는 번호가
있으면 거기서 걸린다.

### 시나리오가 활동 반경을 넓힌다

플래그가 파티의 통행 능력을 열 수 있다(`grants`). 물 위를 걷는 것은 이제
출처가 셋이다 — **부적**(차고 있는 동안) · **마법**(남은 칸 수) ·
**시나리오**(한 번 배우면 영영).

`hd_world` 는 플래그를 모르고 **몰라야 한다.** 아는 순간 모델이
시나리오에 매인다. 합치는 것은 읽는 쪽의 일이고 `GET /api/quest` 의
`granted` 가 그 자리다 — 게임에서는 `HDParty.canWalkOnWater` 가 이미 같은
일을 한다.

### 이 표가 찾아낸 것

`lore_ep1.cm2` · `town2.cm2` · `menace.cm2` 가 `flag4ep1.cm2` 를 include
하지 않고 번호를 직접 쓴다. 그래서 **번호 셋이 겹친다**(10 · 31 · 50).
게임이 아는 것은 번호뿐이라 저장된 파일에는 한 칸이다. 그리고 이름이
아예 없는 칸이 여섯이다(32 · 51~55).

`collisions` 가 그것을 찾아 화면 위쪽에 띄운다. 고칠지는 아직 정하지
않았다 — 겹침이 실제로 도달 가능한지 확인이 먼저고, 번호를 옮기면 기존
세이브가 깨진다.

## 무엇이 안에 없나

- **규칙** — 장비는 `packages/hd_world`, 전투는 `packages/hd_battle`.
  **화면에도 없다**: 무엇이 어디에 들어가는지를 브라우저가 다시 판단하면
  모델과 갈라지는 날이 오고, 그 갈라짐은 색으로만 보여서 아무도 눈치채지
  못한다.
- **한국어** — 도메인 어휘는 `packages/hd_world_text` 와
  `packages/hd_battle_text` 다. 화면이 제 이름표를 갖지 않는다.
  탭 이름 같은 화면 자체의 글자만 여기 있다.
- **저장** — 메모리 안의 세계 하나다. `POST /api/reset` 이 처음으로
  돌리고, `GET /api/save` · `POST /api/load` 가 파일로 오간다.
  **장비와 플래그가 한 파일에 같이** 간다.
- **인증** — 없다. 로컬 개발 서버다.
- **게임의 세이브** — 지도 · 위치 · 소지금은 `hadar_save_N` 에 있고 아직
  안 온다. 플래그와 변수는 온다(`gameOption` 을 그대로 넣으면 읽는다).

| 파일 | 무엇 |
|---|---|
| `lib/server.dart` | HTTP 표면. 규칙을 하나도 갖지 않는다 |
| `lib/eligibility_view.dart` | 누가 · 무엇을 · 어디에 = true 또는 거절 이유 |
| `lib/preview.dart` | 사본에 굴려 차이만 |
| `lib/loadouts.dart` | 담아 둔 장비 한 벌. 입히는 것은 보통의 명령 묶음 |
| `lib/battle_session.dart` | 물음마다 멈추는 한 판 |
| `lib/battle_run.dart` | 끝까지 스스로 굴리는 한 판 |
| `lib/quest/` | 플래그의 정의와 값 |
| `web/index.html` | 뼈대 + 아이콘 sprite (물건 22 · 표식 3 · 적 24) |
| `web/icons.js` · `web/foes.js` | 물건 → 글리프 · 적 → 글리프+색 |
| `web/app.js` | 화면 전부 |
