## 1. 질문과 답

### Q1. 현재 구조가 AI 로 시나리오·퀘스트를 자동으로 불려 나갈 수 있는 구조인가?

**아니다.** 부분적으로도 아니다. 세 층위에서 각각 막혀 있다.

| 층위 | 막힌 이유 | 근거 |
|---|---|---|
| **표현** | 퀘스트·목표·저널 개념이 코드에 **0건**이다. 아이템은 `food:int`+`gold:int` 둘뿐이라 "무엇을 구해 오라" 를 표현할 수 없다. NPC 는 정체성이 없고 좌표에 묶인 대사 덩어리다 | [BP-11](11_gap_analysis.md) |
| **생성** | AI 가 쓸 대상이 없다. cm2 는 미등록 함수가 **조용히 0을 반환해 오분기**하고 범위 밖 인자를 침묵으로 무시한다. 스키마가 없어 생성물을 기계로 검사할 수 없다 | GT §9, 부록 F-1 |
| **검증** | 헤드리스 구동이 안 되고(부록 B-3) 재현도 불가능하다(C-4) — **사실이다.** 다만 **자동 검증은 생성의 전제가 아니다**. 사람이 플레이해 확인하는 규모에서는 없어도 된다 | 부록 B-3, C-4 |

1차 판정은 세 번째를 가장 무겁게 봤다. **2차 판정은 이를 뒤집었다** —
검증은 물량이 커진 뒤의 문제이고, **먼저 생성이 되어야 한다.** 순서가 거꾸로였다.

### Q1-보. 게다가 지금 게임은 이미 조용히 망가져 있다

기획 과정에서 코드를 실측하다 **잠복 결함이 다수 나왔다**([`_meta/GROUND_TRUTH.md`](_meta/GROUND_TRUTH.md) 부록 A~K, 36개 항목).
전부 직접 코드를 열어 확인한 것이며, 대부분이 코드/데이터 문제이고 일부는 이 기획서 자신의 서술 정정이다. 특히 심각한 것:

| 결함 | 증상 |
|---|---|
| 부록 D-1 | `MapInfos.json` 등록 이름 **15개 중 7개가 로드 불가**. 게다가 `TOWN1`·`GROUND1`·`DEN1`·`DEN2` 는 동명 파일이 실제로 있어서, **인덱스에 등록한 행위 자체가 폴백을 죽였다.** 미등록인 `ORIGIN` 만 정상 로드된다(F-4) |
| 부록 A-1·A-2·D-2 | 그 로드 실패가 **성공(`true`)으로 보고**되고, cm2 로드 실패가 `clearRuntimeState()` 를 건너뛰어 **직전 맵 스크립트가 잔존**한다. 맵이 안 바뀐 채 스크립트만 얹힌다 |
| 부록 C-1 | `MapModel.toJson()` 이 `events` 를 빼먹어 **세이브를 로드하면 JSON 대사 티어가 통째로 사망**한다 |
| 부록 A-3 | `HDMapScript.isFlagSet` 가 빈 스텁이라 **네이티브 맵의 모든 조건 분기가 한 번도 동작한 적이 없다** |
| 부록 H-1 | `powOfShield`/`powOfArmor` 는 **전투식이 읽지 않는 죽은 필드**다. 방어는 `ac` 하나뿐 (단 `powOfWeapon` 은 `battle.dart:439` 가 실제로 읽는다 — 초판이 3개 모두 죽었다고 쓴 것은 오류였고 정정했다) |
| 부록 B-2·F-3 | 전투 결과 코드가 cm2 상수와 **정반대**이고, `Battle::Result()` 는 **전투를 안 해도 승리를 반환**한다 |

이것들은 AI 와 무관하게 지금 존재하는 문제다. 그러나 **AI 파이프라인은 이 위에 못 얹는다** —
맵을 이름으로 못 부르는데 앵커를 배치할 수 없고, 세이브가 콘텐츠를 지우는데 퀘스트 진행을 저장할 수 없다.

### Q2. 어떻게 구조가 바뀌어야 하는가

**세 가지 분리**로 요약된다.

**① 시간 축 분리 — Authoring / Build / Runtime**
AI 는 오프라인 저작 구획에만 존재한다. 빌드는 결정론적으로 검증·링크하고, 런타임은 구워진 데이터를 해석만 한다.
런타임에 LLM·네트워크·비결정 난수가 없다. ([BP-20](20_target_architecture.md))

**② 표현 축 분리 — 콘텐츠는 코드가 아니라 데이터다**
AI 의 생성 타깃은 cm2 스크립트도 Dart 클래스도 아닌 **선언적 JSON** 이다.
조건과 효과는 닫힌 연산 집합으로 표현한다 — 그래야 정적으로 검사하고 솔버로 탐색할 수 있다.
cm2 와 네이티브 Dart 는 버리지 않고 **4티어 디스패치**로 공존시킨다. ([BP-21](21_content_pack_spec.md), [BP-28](28_migration_and_coexistence.md))

**③ 정체성 축 분리 — 의미와 좌표를 뗀다**
지금은 대사가 맵 JSON 좌표에 박혀 있어 맵을 편집하면 대사가 깨진다.
앞으로 맵은 **지형**만, 콘텐츠 팩은 **의미**만 갖고, **앵커**가 둘을 잇는다. ([BP-26](26_entity_registry_and_anchors.md))

여기에 상태 통합이 따라온다. 지금 플래그는 **3중으로 갈라져** 있고(그중 하나는 저장조차 안 되고 하나는 맵 전환 시 소실),
전부 이름 없는 정수다. 이름 있는 키 하나로 합치고 세이브 v2 로 올린다. ([BP-25](25_world_state_and_save.md))

### Q3. 어떤 툴과 하네스가 필요한가

| 층 | 무엇 | 왜 |
|---|---|---|
| **저작** | 콘텐츠 서버 (`/api/content/*`) + MCP | AI 가 **파일을 직접 쓰지 않고** API 로 쓰게 해서 스키마 정규화·검증·되돌리기를 강제. 기존 맵 에디터와 같은 프로세스·같은 규약 ([BP-31](31_content_server_api.md)) |
| **생성** | 8단계 파이프라인 + 에이전트 6종 | `context → outline → draft → bind → lint → sim → critic → commit`. LLM 은 2·3·7 단계에만. 나머지는 결정론 ([BP-32](32_generation_harness.md)) |
| **검증** | 5계층 린트 (규칙 카탈로그) | 스키마 → 참조 무결성 → 그래프 구조 → 세계관 → 시뮬레이션 ([BP-33](33_validation_and_lint.md)) |
| **증명** | 헤드리스 시뮬레이터 + 퀘스트 솔버 | **"이 퀘스트가 클리어 가능한가" 를 사람이 플레이하지 않고 증명한다.** 이게 대량 생성의 신뢰 근거 ([BP-34](34_headless_sim_and_solver.md)) |
| **공유 코어** | `packages/hadar_content` (순수 Dart) | 검증기와 런타임이 **같은 평가기를 import** 한다. 저작 시맨틱과 실행 시맨틱이 갈라지지 않게 하는 장치 ([BP-30](30_toolchain_overview.md)) |

**하네스의 진짜 장벽은 포트가 아니라 위치였다.** `UiHost`/`AssetSource`/`HDHosts` 포트는 이미 있고
`test/application/map_navigation_test.dart` 가 헤드리스 구동 선례를 만들어 뒀다. 그러나 **이동과 상호작용 자체가
`presentation/` 의 Bonfire 스프라이트 폴링 안에** 있어서, 페이크 포트를 꽂아도 게임을 굴릴 수 없다(부록 B-3).
이 추출이 시뮬레이터의 선결 과제다.

### Q4. 게임 진행 방식에서 무엇이 바뀌어야 하는가

퀘스트를 성립시키는 **최소 집합 6가지**다. 하나라도 빠지면 표현 못 하는 목표가 생긴다.

| 변경 | 없으면 불가능해지는 것 |
|---|---|
| 퀘스트 저널 UI | 플레이어가 목표를 알 수 없음 |
| **인벤토리·아이템** | `acquire`/`deliver`/`has_item`/`give_item` 전부 표현 불가 |
| 조건부 대화 | 같은 NPC 가 상태에 따라 다른 말을 못 함 (현재 JSON 티어는 무조건 동일 출력) |
| 이름 있는 전역 상태 | 퀘스트 진행을 저장·판정할 수 없음 |
| NPC 정체성 | 맵을 고치면 대사가 깨짐 |
| 월드 이벤트 버스 | 전투 승리·아이템 획득이 목표를 자동 진행시킬 수 없음 |

**의도적으로 안 하는 것**도 정했다: 실시간 AI, 다국어(구조만 열어둠), 음성/이미지 생성,
기존 cm2 콘텐츠 전면 재작성. ([BP-40](40_gameplay_changes.md), [BP-52](52_risks.md) 감수 리스크 13건)

원작 감성과의 긴장은 실재한다 — 저널과 인벤토리는 1990년대 RPG 에 없던 요소다.
[BP-40](40_gameplay_changes.md) 이 이를 회피하지 않고 완화 방안과 함께 다룬다.

## 2. 순서 — 이것이 이 기획서의 가장 실용적인 결론

로드맵은 **"AI 파이프라인 구축" 으로 시작하지 않는다.**

```
M0 기반 복구  →  M1 콘텐츠 코어  →  M2 검증  →  M3 게임 시스템  →  M4 저작 도구  →  M5 파일럿  →  M6 확대
   (부록 A~K)      (데이터+런타임)    (린트·시뮬)    (인벤토리·저널)    (서버·CLI·MCP)   (퀘스트 1개)
```

순서를 바꾸면 안 되는 이유가 각각 있다:

- **M0 가 먼저인 이유** — 맵을 이름으로 못 부르고(부록 D), 세이브가 콘텐츠를 지우고(C-1), 재현이 불가능한(C-4)
  상태에서는 그 위에 무엇을 얹어도 검증할 수 없다.
- **검증(M2)이 저작(M4)보다 먼저인 이유** — 검증 없이 저작 도구를 주면 AI 가 **검사되지 않은 콘텐츠를 대량 생산**한다.
  손으로 만들 때보다 나쁜 상태가 된다.
- **게임 시스템(M3)이 저작보다 먼저인 이유** — `item_gained` 를 소비하는 목표를 만들 수 있는데
  그 이벤트를 **발행할 코드가 없으면**, 린트는 통과하고 게임은 안 돌아간다.
  이 함정이 실제로 드러났고([BP-91](91_appendix_worked_example.md) W-10), 솔버가 `PROVEN` 을 냈다.
  그래서 **D-26** 으로 솔버 판정을 2축(모델 증명 × 실행 가능)으로 바꿨다.

규모: 마일스톤 7개, 태스크 **156개**, 임계 경로 24태스크. ([BP-50](50_roadmap.md), [BP-51](51_task_breakdown.md))

## 3. 무엇을 믿고 무엇을 믿지 말아야 하는가

이 기획서는 **추측과 실측을 구분해서** 썼다.

**믿어도 되는 것**
- [`_meta/GROUND_TRUTH.md`](_meta/GROUND_TRUTH.md) 부록 A~K — 전부 코드를 직접 열어 확인했다. 틀린 것이 발견되면 정정판으로 표시했다(H-1·H-2·B-4 가 그 예다).
- 웹 빌드는 **실제로 성공한다** — `flutter build web --release` 를 돌려 확인했다(16.5초, 산출물 45MB).
- 텍스트 길이 제약 수치 — 실제 `hd_config.dart` 상수와 `splitToLines` 구현에서 유도했다.

**아직 믿으면 안 되는 것**
- 웹 런타임에서 `exit(0)` 가 어떻게 동작하는지 — 빌드는 되지만 **브라우저에서 실제로 눌러보지 않았다**(부록 B-4-4).
- [BP-12](12_reference_designs.md) 의 외부 게임 사실 중 `[미확인]` 표기가 붙은 것들.
- [BP-90](90_appendix_schemas.md) 의 불일치 목록 `I-01~I-20` 과 [BP-91](91_appendix_worked_example.md) 의 `W-01~W-13`
  중 아직 소유 장이 반영하지 않은 것.

**정정된 것** — 초판이 틀렸고 나중에 고친 것들이다. 같은 실수를 반복하지 않도록 남겨 둔다.
- 부록 B-4: "`dart:io` 때문에 웹 빌드가 깨져 있을 것" → **실빌드로 반증**. 계층 위반과 헤드리스 파괴만 유효.
- 부록 E-1: "RPG Maker code 101 = 텍스트 헤더" → **오류**. 실제로는 대화창 표시 설정.
- 부록 E-3: "cm2 는 튜링 완전이라 검증 불가" → **오류**. cm2 엔 루프도 함수도 없다. 결론은 유지, 근거는 교체.
- D-20a / D-21a / D-25: **조정자 자신이** 소유 장의 스키마를 옮겨 적다 낸 오류. 그래서 "결정 문서는 스키마를 전재하지 않는다" 를 규칙으로 만들었다.

## 4. 한 문단 요약

> **[2차 판정이 이 문단을 대체한다]** 아래는 1차 판정의 요약으로 보존한다.
> 정본 요약은 [`issues/MILESTONES.md`](../issues/MILESTONES.md) §0 이다.

**2차 판정 요약**: Hadar2026 은 **퀘스트를 이미 저작할 수 있다.** 원작이 플래그와 cm2 로 그렇게 하고 있고
2,441줄이 돌아간다. 새 맵과 등장인물 추가도 **코드 변경 0** 으로 된다(`MapInfos.json` 항목 + `Map0NN.json` + `Map0NN.cm2`).
따라서 할 일은 "만들 수 있게 만드는 것" 이 아니라 **샘플 퀘스트를 손으로 하나 만들어 걸림돌을 찾아내고,
