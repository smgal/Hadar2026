### F-02 cm2 에 "튜링 완전 언어의 일반 성질" 을 근거로 [확인됨] 등급을 부여 — 논증 자체가 성립 안 함
- **위치**: `12_reference_designs.md:~816`(12.9.1 마지막 불릿), `~825`(12.9.2 표 "정적 검증 | 불가 | **불가**")
- **문서 주장**: "정적 분석이 사실상 불가능하다. '이 퀘스트를 끝까지 진행할 수 있는가' 를 코드로 증명할 수 없다. **[확인됨 — 튜링 완전 언어의 일반 성질]**" → 그리고 12.9.2 표가 같은 "불가" 판정을 cm2 에 그대로 적용한다.

- **왜 치명인가**: 12.9 절은 이 장이 스스로 "D-02 의 근거 보강"(12.18 확정한 것 #3)이라 선언한 절이다.

- **중요 — 결정은 유지**: D-02(cm2 를 AI 생성 타깃에서 제외) 자체는 **다른 근거로 충분히 성립한다**:
  침묵 실패(미등록 함수 → 0 반환, `cm2_script.dart:335-336` 실측), 맵 전환 시 전역 소거,
  `run()` 의 `.assign` 재실행, 툴 부재, 스키마 강제 출력이 불가능한 저작 표면. **이 5개로 논거를 갈아끼우면 된다.**
- **요구 조치**:
  - 12.9.1 의 `[확인됨 — 튜링 완전 언어의 일반 성질]` 딱지를 **Papyrus 에만** 한정하도록 문장을 분리.
  - 12.9.2 표의 cm2 "정적 검증: 불가" 행을 **"원리적으로는 가능하나(루프·함수 부재) 실무적으로 무의미 — 검사기를 만들어도 침묵 실패·전역 소거·상태 3중 분열은 언어 밖 문제"** 로 정정.
  - 12.9.3 표의 첫 행 반박 문구도 같은 취지로 재작성.

### F-03 cm2 개선 노선 기각의 반박이 미검증 비용 등식에 기대고 있음 (반대 심문 결과)
- **위치**: 12.9.3 표 3행 — "cm2 정적 타입 검사기 작성 | 검사기 작성 비용 ≈ 새 데이터 스키마 + 검증기 작성 비용. 그런데 산출물의 검증 강도는 훨씬 낮음"
- **반대 심문**:
  1. 좌변은 `packages/cm2_script`(파서 164줄 + 인터프리터 340줄, GROUND_TRUTH §1)에 검사기를 얹는 비용이다.
  2. 우변은 **D-03 팩 포맷 + D-05 DSL + D-11 런타임 12파일 + D-12 서버·CLI·MCP + D-13 하네스·솔버 + D-14 8단계 + D-15 게이트** 전체다.
  3. 두 값이 "≈" 라는 주장은 **1인 개발 규모라는 이 프로젝트의 실제 제약을 고려하면 오히려 우변이 압도적으로 크다.**
- **그럼에도 기각이 옳은 이유**(문서가 말했어야 하는 것): 비용이 아니라 **저자가 LLM 이라는 사실**이다.
  cm2 는 (a) 스키마 강제 출력이 불가능하고, (b) 부분 재생성 단위가 없고, (c) 텍스트와 부작용이 한 파일에 섞이고,
  (d) 침묵 실패가 런타임까지 살아남는다. 이 4가지는 검사기를 아무리 잘 만들어도 남는다.
- **요구 조치**: "비용 ≈" 등식을 삭제하고 위 (a)~(d) 로 논거 교체. 비용 비교를 유지하려면 BP-50/BP-51 의 실제 추정과 연결할 것.

### F-04 Bethesda 의 Objective 구조를 뒤집어 서술하고, D-06 과의 차이를 표시하지 않음
- **위치**: 12.3.1 3번째 불릿("Stage 에 Objective 와 저널 항목이 붙는다"), 12.3.4-2("**Objective 를 Stage 에서 분리**")
- **실제**:
  - Creation Kit 에서 **Objective 는 Quest 레벨의 독립 목록**이고, Stage 는 fragment 로 그 Objective 를 표시/완료시킨다. "Stage 에 붙는다" 가 아니다.
  - 반대로 **D-06 은 `Stage { objectives: [Objective] }` 로 Stage 안에 nest** 한다.
  - 즉 문서는 원본 구조를 우리 구조에 맞춰 서술한 뒤, 차용 항목에서는 정반대로 "Stage 에서 분리" 라고 쓴다. 두 문장이 서로도 어긋난다.
- **왜 중요한가**: 이 장의 임무는 "계보 명시" 다. 원본 구조를 잘못 적으면 BP-23 이 "Radiant 를 따랐다" 고 믿으면서 다른 구조를 만든다.
  특히 **여러 Stage 가 같은 Objective 를 공유하는 패턴**(Radiant 의 기본형)이 D-06 nest 구조에서는 불가능하다는 사실이 드러나지 않는다.
- **요구 조치**: 12.3.1 을 "Objective 는 Quest 가 소유하고 Stage 가 표시 상태를 바꾼다" 로 정정.
  12.3.4-2 를 "Objective 를 **별개 레코드 타입**으로 두되, 우리는 원본과 달리 **Stage 하위에 nest** 한다(D-06). 차이: 스테이지 간 목표 공유 불가" 로 재작성.

### F-05 MV 페이지 선택 규칙이 우리 규칙과 **정반대**라는 사실을 놓침 — 이관 시 의미 역전 위험
- **위치**: 12.2.5-2("MV 는 조건 만족 페이지 중 하나를 규칙대로 고른다. 우리는 '배열 위에서부터 첫 true' 로 규칙을 더 단순·명시적으로 못 박는다. **애매함 없음**"), 12.2.2("`event.pages[]` → `Dialogue.entry[]`"), 12.16.3(D-07 ← "12.2 pages→entry")
- **검증 결과(V-r)**: MV 는 **가장 번호가 큰 만족 페이지**를 고른다. 결정론적이며 애매하지 않다. 문서가 말한 "애매함" 은 MV 의 성질이 아니라 **집필 시점의 미확인 상태**였다.
- **진짜 문제**: 두 규칙은 **순서가 반대**다.
  - MV: 배열 **아래에서부터** 첫 만족 (마지막 우선)
  - 우리: 배열 **위에서부터** 첫 true (R-12-1)
  → `pages[]` 를 `Dialogue.entry[]` 로 "직역" 하면서 배열 순서를 보존하면 **분기 의미가 통째로 뒤집힌다.**
  현재 레포에 다중 페이지 이벤트가 0건(V-q)이라 당장 사고는 없지만, 맵 에디터가 이벤트 CRUD 를 지원하므로(GROUND_TRUTH §11) 언제든 생길 수 있다.
- **요구 조치**:
  - 12.2.5-2 의 "애매함 없음" 서술을 "MV 도 결정론적이나 **순서가 우리와 반대**" 로 정정.
  - 12.2.2 의 `pages[] → entry[]` 행에 **"이관 시 배열 역순 필요"** 경고 추가.
  - 이 사실을 **BP-28(이관)** 과 **BP-24(대화 모델)** 로 명시 인계. 현재 12.18 인계 표에 이 항목이 없다.

### F-07 GROUND_TRUTH 부록 A(선행 버그 4건)를 이 장이 전혀 참조하지 않음
- **위치**: 문서 전체 — `grep "부록 A|A-1|A-2|A-3|A-4"` 결과 **0건**
