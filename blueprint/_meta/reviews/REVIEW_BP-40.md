- 실제 (직접 grep):

### F-05 `time_of_day` 경계를 "`sight_calculator` 와 같은 식" 으로 규정했으나 그 파일에 경계가 **둘** 있다

- 위치: `40_gameplay_changes.md:736-754` (§40.5.1), `:1080` (Q-40-4)
- 문서 주장: `day` = `hour ∈ [7,17)`, 근거 `sight_calculator.dart:46`. "경계값은 `sight_calculator.dart` 와 **반드시 같은 식**을 쓴다."
- 실제 (`lib/domain/lighting/sight_calculator.dart` 전문 확인):
  ```dart
  :20  int time = gameSystem.hour * 100 + gameSystem.min;
  :23  if (time < 600)  sightRange = 1;          // 06:00 이전 = 완전 야간
  :31  else if (time < 1800) sightRange = 5;     // 06:00~18:00 = 주간 시야
  :37  else if (time < 1900) sightRange = 2;
  ...
  :46  final inDark = isDen || !(gameSystem.hour >= 7 && gameSystem.hour < 17);
  ```
  **같은 파일 안에 낮/밤 경계가 두 개 있다.** 시야 거리 램프는 06:00~19:00 을 낮으로 다루고, `inDark`(횃불 발동 조건)는 07:00~17:00 을 낮으로 다룬다. 문서가 고른 것은 후자다.
- 왜 중요한가: §40.5.1 의 규범은 "두 곳에 복제하지 말고 `domain/system/` 에 `bool get isDaytime` 을 두고 양쪽이 참조한다" 인데, **"양쪽" 이 실은 세 곳**이고 그중 둘이 이미 다르다. 그대로 `isDaytime` 을 만들면 "화면은 아직 밝은데 조건은 밤(17:00~19:00)" 이 발생한다 — 문서가 피하려던 바로 그 증상이다.
- 요구 조치: Q-40-4 를 "sight_calculator 안의 두 경계 중 어느 쪽을 `isDaytime` 으로 승격할 것인가, 나머지 하나는 별도 이름(`sightRamp`)으로 남길 것인가" 로 다시 쓰고, §40.5.1 의 "반드시 같은 식" 문장을 그 결정에 종속시킬 것.

### S-02 §40.2.1 "메뉴 항목 7 → 8" · "↓×6" 이 최종안과 어긋난다
- `40_gameplay_changes.md:124`, `:127`. §40.4.2 의 최종 메뉴는 **9항목**이고 `임무를 확인한다` 는 **8번**이다.
  커서는 1에서 시작하므로 실제 조작은 `↓×7`(또는 `moveCursor` 순환을 이용해 `↑×2`)이다.
- 저널 단독 관점의 표라는 것은 이해되나, 숫자가 §40.4.2 와 어긋나 읽는 사람이 멈춘다. "항목 수 7 → 9(저널 1 + 소지품 1)" 로 통일 권고.
