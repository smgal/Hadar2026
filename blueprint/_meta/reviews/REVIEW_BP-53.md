§53.0 의 소유권 선언(R-53-1 "이 장이 단독으로 소유하는 것은 수치 목표와 층위 배정뿐")과
§53.3.1 의 경계 재확인(R-53-12)은 D-18/D-25 를 모범적으로 지킨다.

**그럼에도 반려한다. D-26 때문이다.**

D-26 은 "게이트 반영은 **BP-53**" 으로 이 장에 소유를 명시적으로 지정했다.
그런데 이 장은 D-26 을 **한 글자도 반영하지 않았다.** §53.0 은 여전히 폐기 대상인 4값 판정
(`PROVEN`/`UNREACHABLE`/`MISSABLE`/`INCONCLUSIVE`)을 인용하고, H-5·N-24~N-27·S-9·S-10 이
전부 그 위에 서 있다. 소유 장이 자기가 소유하기로 한 결정을 이행하지 않은 것은 축 B 의 정의상 2점이다.

수치 목표는 **73개가 실재한다**(N-01~N-73, 결번·중복 0 — 기계 검증).
그중 **[BP-53] 신규 7 + §53.4.6 의 6 = 13개**가 이 장 소유이며, §53.8.1 의 집계와 정확히 맞는다.

     실제로 BP-50·BP-51·BP-52 전부 D-26 을 0건 인용한다 — 즉 D-26 은 **기획서 어디에도 착지하지 않았다.**

     "커밋은 허용, **릴리스에서 차단**" 인데, R-53-9~R-53-11 은 `--strict` · 야간 전량 · 사람 완주 기록만 요구한다.

     `acquire`/`deliver` 목표를 쓰는 픽스처 퀘스트는 `PROVEN + UNSUPPORTED` 가 된다.
     현행 H-5 는 `UNREACHABLE` 만 차단하므로 **그대로 통과한다.**
- 요구 조치:
  1. §53.0 의 판정 이름 인용을 **2축**으로 교체(BP-34 가 갱신된 뒤 인용).
  2. **H-5 를 2축으로 재정의** — "모델 증명 축에서 `REFUTED` 는 커밋 차단.

### F-04 번들 크기 목표가 부록 B-5 의 실측(45MB)과 대조되지 않았다 — 최적화 대상이 잘못 지정될 수 있다
- 위치: 53_acceptance_criteria.md:285-289(N-59~N-63), :359(M1 `[HC-7]`), :449(M6 `[G6-5]`)
- 문서 주장: N-63 "웹 배포 페이로드 **증가분** ≤ +600 KB (하드 +1.5 MB)",

  근거는 BP-20 §8.2 이며 그 행의 비고는 "**소스 폴더 미등록(§5.6) 전제**".
- 실제(부록 B-5, 2026-08-30 실측): `flutter build web --release` 산출물 **총 45MB** —
  `canvaskit/` **31MB**, `assets/assets/` **9.7MB**(맵 1.2MB + 이미지 1.3MB + cm2 등),
  `assets/NOTICES` 1.3MB, 나머지 ~3MB.
  B-5 는 명시적으로 지시했다 — "**BP-35 의 번들 크기 목표는 이 실측치를 기준선으로 잡아야 한다.**
  콘텐츠 팩이 추가하는 용량은 현행 자산 9.7MB 대비 상대적으로 평가할 것.
  부록 A-4 와 함께 보면, `assets/content/` 의 **소스 JSON 을 웹 페이로드에서 빼는 선택이
  실질적 이득인지 여부도 이 수치로 판단해야 한다**(소스가 수 MB 가 아니라면 이득이 작다)."
- 검증: `grep -c "B-5\|45MB\|canvaskit\|9.7" 53_acceptance_criteria.md` → **전부 0**.
- 왜 치명적인가:
  1. **N-63(+600KB)은 45MB 기준선에서 1.3% 다.** 그 수치를 하드 게이트로 두는 것은 정당할 수도 있지만,
     **기준선 없이는 정당한지 알 수 없다.** 이 장은 "수치 목표를 소유한다" 고 선언했으므로
     기준선 대조는 이 장의 책임이다.
  2. **HC-7("소스 폴더를 싣지 않는다")은 B-5 가 "이득이 작을 수 있다" 고 경고한 바로 그 선택**이다.
     그 선택을 **하드 게이트**(머지 거부)로 만들면서 이득을 계산하지 않았다.
     소스 팩이 수백 KB 라면 이 게이트는 개발 편의(데스크톱 파일 폴백 없이도 소스 확인)를
     아무 이득 없이 희생시킨다.
  3. **BP-52 RK-30 의 잔여 리스크("중 규모 팩이 나오는 시점까지 실측이 없다")도 부분적으로 낡았다** —
     전체 페이로드는 이미 실측되었다.
- 요구 조치:
  - §53.4.5 서두에 **"기준선: 현행 웹 산출물 45MB(부록 B-5) — canvaskit 31MB · 게임 자산 9.7MB"** 를 명시.
  - N-63 의 근거 열에 "9.7MB 자산 대비 +6% 이내" 같은 **상대 표현**을 병기.
  - HC-7 을 하드로 유지할지, 소스 팩 실측 후 재판정할지 **Q-53-7 로 열어** M1 에서 닫을 것.
  - 참고로 canvaskit 31MB 는 콘텐츠와 무관하므로, **"콘텐츠 팩이 통제할 수 있는 표면은 9.7MB 쪽"**
    이라는 사실을 명시하면 최적화 노력의 방향이 분명해진다.

## 개선 제안 (선택)

### S-01 §53.4.3 커버리지 표에 출처 열이 없다

  이 표만 규약에서 벗어난다. 출처 열을 추가할 것.

### S-02 `A-1`~`A-8`(판정하지 않는 것)이 부록 A-1~A-4 와 ID 가 겹친다

  `[G3-5]` "**부록 A-3** 해소" 와 `[A-3]` "**원작 감성**의 대리 명제 3종" 이 **연속된 두 줄**에 나온다.
  독자가 혼동할 여지가 크다. `NJ-1`~`NJ-8`(Not Judged) 같은 접두사로 개명할 것.
  (F-02 의 `S-` 충돌과 같은 계열 문제다.)

### S-03 §53.5 체크리스트 항목 수 "97개" 를 검증할 수 없다
- §53.8.1 말미가 "마일스톤 M0~M6 수용 체크리스트 **총 97개 항목**" 이라고 확정했다.
  §53.5 의 `- [ ]` 항목을 세면 M0 13 + M1 14 + M2 18 + M3 14 + M4 7 + M5 13 + M6 16 = **95** 다
  (범위 표기 `[N-59~N-63]` 을 1항목으로 셀 때). 세는 방식이 명시되지 않아 검산이 불가능하다.
  "범위 표기는 1항목으로 센다" 같은 규약을 붙이거나 수치를 재확인할 것.

### S-04 BP-32 의 `callsPerQuest ≤ 8` 이 수치 목표에 없다
- BP-32 §32.10.1 은 **호출 효율 `callsPerQuest` ≤ 8**(커밋 퀘스트당)을 지표로 둔다.
  BP-53 은 N-11(호출 **상한** 15회)만 가져왔다. 상한과 효율 목표는 다른 지표다 —
  전자는 강제 중단선, 후자는 품질 신호다. N-74 로 추가할 것.

## 잘된 점

- **인용 충실도가 탁월하다.** [인용] 표기 수치 중 20개 이상을 원 장에서 직접 대조했고
  **불일치가 0건**이었다. 특히 BP-35 §5.2 의 6행(6/12/8/3/15/40분),
  BP-20 §8.2 의 6행(400KB/120KB/60KB/250KB/+600KB/40ms·150ms),
  BP-34 §10.1/10.2 와 §6.3 의 8행 커버리지 — 전부 원문 그대로다.
  "옮겨 적는 행위가 오류원" 이라는 D-25 의 경고에도 불구하고 이 장은 옮겨 적기를 정확히 해냈다.
- **§53.0 의 소유권 선언이 D-18 을 가장 엄격하게 적용한 사례다.**
  R-53-1 "이 장이 단독으로 소유하는 것은 **수치 목표와 층위 배정뿐**이며,
  원 장과 어긋나면 **원 장이 이긴다**" — 비소유 장이 취해야 할 정확한 자세다.
- **§53.3.1 R-53-12 가 하드/소프트 경계를 정확히 재확인한다.**
  나는 BP-32 R-32-38·BP-37 R-37-14/15 와 대조했고 **경계 침범이 없음**을 확인했다 —
  ① Critic 은 Hard gate 판정 권한 없음(지적 시 finding 폐기 + 로그만),
  ② Soft 축은 기계가 판정하지 않음(경고와 수치만),
  ③ 양방향 독립. §53.3.2 의 13행 표가 "판정 주체 / 기계가 하는 일 / 사람·Critic 이 하는 일" 로
  나뉘어 있어 경계가 행마다 눈에 보인다. **BP-33/34/35 가 정의한 게이트를 재정의하지 않고 인용만 했다.**
- **§53.6 "완료의 정의가 애매한 것들" 8종은 이 문서의 백미다.**
  "**판정하지 않기로 하는 것도 결정이므로 명시한다**" 는 태도, 그리고 R-53-14
  "A-2(재미)에 대해 **어떤 하드/소프트 게이트도 만들지 않는다** … 게이트를 만들면 반드시 대리 지표로
  대체되어 착시만 남는다" 는 RK-23 의 교훈을 정확히 적용한 것이다.
- **N-66/N-67 의 근거 서술이 모범적이다.** 부록 C-3 의 실측(570KB) → localStorage 5MB →
  UTF-16 실효 여유 2.5MB → 슬롯 4개 → 300KB/1.2MB 로 **계산 과정이 문장에 드러난다.**
