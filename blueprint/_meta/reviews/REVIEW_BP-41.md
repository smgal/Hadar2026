## 중요 결함

### F-01 D-08a 가 폐기한 필드명 `updatedAt` / `at` 을 사용한다 (4곳)

- 위치: `41_journal_ui_spec.md:241`, `:242`, `:216`, `:231`, `:728`, `:904`
- 문서 주장:
  - §41.3.5 "진행 중 | `QuestProgress.updatedAt` **내림차순**" / "`updatedAt` 은 벽시계가 아니라 `WorldState.step` 스냅샷이므로(D-08a)"
  - §41.3.3 / §41.8.4 "`WorldState.journal` 을 `at` 오름차순"
  - §41.11.1 "정렬은 `updatedAt`(= `WorldState.step`) 내림차순"
- 실제: **D-08a 는 그 이름들을 명시적으로 폐기했다.**
  > D-08a: "D-08 초안의 `startedAt`/`updatedAt`/`at` 은 D-01(결정론)과 정면 충돌한다. … 퀘스트/저널의 시각 필드는 전부 이 `step` 을 기록한다(**`startedStep`, `updatedStep`, `atStep`**)."
  D-08 본문의 `WorldState` 스키마도 `{state, stage, counters, startedStep, updatedStep}` / `journal: [{questId, stageId, entryKey, atStep}]` 이다.
- 왜 중요한가: BP-41 은 각주에서 **D-08a 를 근거로 인용하면서** 그 개정이 폐기한 이름을 쓴다. 구현자가 이 문서대로 `journalRow.at` 을 읽으면 `WorldState` 에 없는 필드다. 정렬 규칙(결정론 보장)이 걸린 자리라 조용히 넘어갈 항목이 아니다.
- 요구 조치: `updatedAt` → **`updatedStep`**, `at` → **`atStep`** 전수 치환. §41.3.5 각주는 "`updatedStep` 은 `WorldState.step` 스냅샷이다(D-08a)" 로.

### F-02 `window_key_dispatcher.dart:41` 인용이 틀렸다

- 위치: `41_journal_ui_spec.md:390` (§41.5.3 코드 블록 주석)
- 문서 주장: `// hadar2026_app/lib/presentation/input/window_key_dispatcher.dart:41  (현행)` 뒤에 `bool _dispatch(HDWindow window, dynamic event) { … }`
- 실제:
  ```

  :35   bool _dispatch(HDWindow window, dynamic event) {
  :38     if (window is HDSelectionWindow) return _handleSelection(window, event);
  ```

  `_dispatch` 는 **35행**이다. 41행은 `_handleMessage` 본문(`if (event is! KeyDownEvent) return false;` 부근)이다.
- 부가: 인용된 **코드 내용 자체는 정확하다** — `HDMessageWindow → HDMagicSelectionWindow → HDSelectionWindow` 순서와 `return false` 까지 실제와 일치.
- 요구 조치: `:41` → `:35`. 같은 오기가 BP-40 §40.2.1 영향표에도 있다.

### F-03 §41.6.4 추적 바 예산이 **ASCII 도해와 표에서 서로 다르다**

- 위치: `41_journal_ui_spec.md:516-528`
- 문서 주장:
  ```
  [눈여겨 봄 ][·][공백][목표 문구 …………………][공백][(2/3)]
      10       2   1           37              1     5     = 56칸  (여유 4칸)
  ```
  바로 아래 표: `눈여겨 봄`(5자)+공백 = **11**, `·`+공백 = **3**, `(2/3)`+앞공백 = 6, **목표 문구 예산 40칸 = 20자**
- 재계산: 11+3+6+40 = **60**, 10+2+1+37+1+5 = **56**. 두 계산이 4칸 차이 나고 문구 예산도 37 vs 40 으로 다르다.
- 왜 중요한가: 바로 다음 표가 "추적 바 목표 문구 권고 ≤16자 / 경고 17~20 / Hard >20자" 를 **40칸(=20자) 기준으로** 확정한다. ASCII 의 37칸(18.5자)을 따르면 Hard 상한이 18자여야 한다. 린트 JV 규칙 값이 걸린 자리다.
- 요구 조치: 둘 중 하나로 통일. 표 쪽(60칸/40칸/20자)이 §41.4.4 의 "추적 바 1줄 Hard >20자" 와 정합하므로 ASCII 도해를 표에 맞춰 고칠 것.

## 개선 제안 (선택)

### S-01 §41.10.5 헤딩과 표 행 수 불일치
- `41_journal_ui_spec.md:854` — 헤딩 "기존 파일 수정 (**5곳**)" 인데 표는 **6행**(`window_view.dart`, `window_key_dispatcher.dart`, `input_panel.dart`, `selection_window_data.dart`, `ui_host.dart`, `menu_flows.dart`).
- §41.11.1 은 "기존 수정 **6곳**" 으로 올바르다. 헤딩을 6으로.

### S-02 ASCII 목업의 우측 테두리가 행마다 최대 3칸 어긋난다
- 측정값: §41.8.1 에서 행4 = 58, 행3 = 62, 행16 = 61(테두리 포함 기준). 내용은 전부 60칸 이내라 **스펙상 문제는 없으나**, 목업을 눈으로 검산하는 사람이 "이 행은 넘치는 것 아닌가" 를 매번 다시 세게 된다.
- 각 행을 정확히 60반각으로 패딩해 `│` 를 세로로 맞출 것을 권고.

### S-03 추적 바 20px 은 한 행(19.2px)에 상하 패딩 0
- §41.6.3 은 높이를 512×**20** 으로 확정하고, §41.6.4 는 폭을 "512 − 2×16(패딩)" 으로 계산한다. 좌우 패딩은 전제하면서 상하는 0.8px 만 남는다.
- `HDDescriptionPanel` 의 `ListView` 는 `vertical: 8` 패딩을 갖고 있어 시각적으로 어긋난다. 24px(=19.2 + 상하 2.4) 또는 `Padding(vertical: 2)` 명시를 권고. 24px 로 올려도 로그 영역은 120px → 6.25행이라 §41.6.3 표만 갱신하면 된다.

### S-04 "대화 진행 중에는 저널을 열 수 없다" 를 불변식으로 못박을 것
- 검수 지시 §7 의 심문: *저널 화면이 콘솔 영역을 점유하면 진행 중이던 대화는 어떻게 되나?*
- 현재 답은 §41.5.1 의 "`showMainMenu` 이 이미 `beginNarrative()`/`endNarrative()` 로 감싸므로 … 별도 처리 불필요" 뿐이다. 이는 "저널은 메인 메뉴에서만 열린다 → 메인 메뉴는 `HDInputMode.map` 에서만 열린다 → 대화 중에는 도달 불가" 라는 3단 추론을 독자에게 맡긴다.
- 실측으로는 참이다: `input_dispatcher.dart:117 _handleMap` 만 Space/Esc/Q 로 메뉴를 열고, `currentInputMode` 는 `window > menu > dialogue > map` 우선순위(`hd_game_main.dart:159-164`)라 대화 중에는 `dialogue` 가 잡힌다.
- **한 줄 불변식으로 명시하고 §41.10.7 테스트 계획에 회귀 1건을 추가**할 것. 티어 0 의 비동기 대화 그래프가 들어오면 이 전제가 깨질 수 있다.

### S-05 목록 커서 이동 시 미리보기 2행 재계산 규칙 부재
- §41.3.2 는 "미리보기 2행 — 커서 이동에 즉시 반응" 이라 하고, §41.4.5 는 "빌드가 wrapped 행 수를 미리 계산해 번들에 굽는다(`_wrapJournal`)" 고 한다.
- 그러면 미리보기 2행은 **어느 단계의 산물인가**? 잘라내기(`…`)를 런타임이 하면 `TextPainter` 재측정이 필요해 §41.4.5 의 "런타임은 재측정하지 않는다" 와 충돌한다. 빌드가 굽는다면 "첫 2행" 이 아니라 "미리보기용 사전 잘라낸 2행" 이라는 별도 산출물이 필요하다.
- BP-35 로 넘기기 전에 어느 쪽인지 한 줄 확정을 권고.

### S-06 `journal_view.dart` 라는 같은 파일명이 두 계층에 있다
- §41.10.2 `domain/content/journal_view.dart`(DTO) 와 §41.10.4 `presentation/panels/journal_view.dart`(위젯). 계층 규칙상 문제는 없으나 IDE 탭·import 별칭에서 혼동이 잦다. DTO 쪽을 `journal_rows.dart` 로 권고.
