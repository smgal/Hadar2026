그럼에도 **수정 필요**인 이유:

   G-05 는 2줄 수정으로 끝나는데 치명이고, 부분집합 관계인 G-07(치명) ⊂ G-27(높음) 은 등급이 역전돼 있다.

### F-01 부록 A-2 에 대응하는 결함이 28건 중 없다 — G-22 의 증상 서술이 실제와 다르다

- 문서 주장(G-22): “`TOWN1` 을 로드하면 조용히 **이전 맵 위에 TOWN1 스크립트만 얹힌** 어긋난 상태가 된다.”
- 실제: `hadar2026_app/lib/application/scripting/script_engine_adapter.dart:92`~`:99` 는
  자산 로드 실패 시 **`clearRuntimeState()` 에 도달하기 전에 `return` 한다.**
  ```dart
  } catch (e) {
    print("ScriptEngine: [ERROR] Failed to load $assetPath: $e");
    return;                      // ← 103행의 clearRuntimeState() 미도달
  }
  ```
  `MapInfos.json` 의 15개 이름 중 페어 cm2 가 실제로 존재하는 것은 `LORE_EP`·`MAP003` 둘뿐이므로,
  나머지 13개 맵으로 이동할 때마다 **직전 맵의 파싱된 스크립트·`variables`·`_contexts` 가 그대로 살아남는다.**
  동시에 `currentMapCm2Path` 는 non-null 이라 `_dispatchScripted` 는 **티어 2(cm2)** 를 고른다.
  따라서 실제 상태는 “이전 맵 타일 + **이전 맵 cm2 핸들러** + TOWN1 네이티브” 의 3중 혼합이다.

### F-03 “등록된 커맨드가 범위 밖 인자를 조용히 삼킨다” 는 침묵 실패 계열이 통째로 빠졌다

- 요구 조치: **G-30(신규)** — “등록 심볼도 범위 밖 인자를 침묵 no-op 으로 처리한다”. 심각도 **높음**.

## 7. 잘된 점

- **§0 의 구성이 이 기획서에서 가장 잘 설계된 도입부다.** 결론 → 축별 판정 → 반대 근거 → D-16 역추적 순서가
  의사결정자용 문서로서 정확한 순서다.
- **G-15 의 발견은 이 장의 독자적 성과다.** `map_event.dart:58` 이 `"NPC"` 타입을 만들지만
  `map_loader.dart:57` 의 4분기에는 `NPC` 가 없어 `ixEvent = 0` 이 되고, 결국 `NPC*` 이름을 붙인 이벤트는
  **대화가 아예 발화되지 않는다** — 두 파일을 대조해야만 나오는 결론이고, 실측으로 재현했다.
- **G-21 의 expTable 21개/20개 길이 불일치**도 실제로 세어 보지 않으면 못 잡는다. 정확했다.
- **G-17 의 `battle.dart` 무시드 난수 14곳 줄 번호가 전부 정확하다.**
- 28건 전부가 `근거 / 영향 / 심각도 / 관련 결정 / 해소 위치` 5필드를 빠짐없이 채웠고,
  **추측으로 쓴 항목(△)이 0건**이다. 근거에 실제 코드가 없는 결함은 하나도 없었다.
- §2.4 “지금 당장 고칠 수 있는 것” 은 아키텍처 문서에서 흔히 빠지는 절인데 있다.
  “지금 골든을 뜨면 버그가 정본이 된다” 는 우선순위 논거가 특히 좋다.
- 링크 검증: 본문·매트릭스의 상대 링크 **전부**가 `_meta/OUTLINE.md` 에 계획된 파일을 가리킨다.
  실존하지 않는 장을 지어낸 곳은 없다(BP-20/21/22/23/24/25/26/27/28/33/34/35/36/41/42/43/50/51/52/53/90/91/12 전수 대조).
- 식별자 검증: D-05 의 op(`flag`, `var_cmp`, `has_item`, `quest_state`, `npc_state`, `chance`, `time_of_day`),
  do(`give_item`, `take_item`, `start_battle`, `heal_party`), D-06 의 `Objective.kind`(`acquire`, `deliver`, `talk_to`, `defeat`, `reach`),
  D-07 의 `entry`/`Choice.when`/`lines: [stringKey]`, D-08 의 `WorldState.seed`, D-16-1~6 —
  **임의 추가·오탈자 0건.** 이 장이 쓰는 식별자는 전부 DECISIONS.md 에 실재한다.
- 중복 검사: 다른 장이 담당할 스키마(Quest/Dialogue/WorldState 구조)를 재정의한 곳이 없다.
  전부 “D-nn 이 정한 X 가 착륙할 곳이 없다” 형태로만 참조한다 — SSoT 를 지켰다.

## 10. 결정 재검토 요청

DECISIONS.md 의 결정을 바꿔야 한다고 판단한 것은 **없다.** 아래는 기록만 남긴다.

- **D-10(디스패치 티어 재정의)** — “Content tier 가 처리했으면 아래 티어로 내려가지 않는다.
  기존 3티어의 동작은 앵커가 없는 맵에서 **그대로 보존**된다 → 무중단 점진 이관” 이라는 전제가,
  N-1(엔진 누수) 앞에서는 **“보존할 기존 동작이 비결정적”** 이라는 문제에 부딪힌다.
  결정 자체는 유효하다고 본다 — 다만 BP-27/BP-28 이 “티어 판정 정상화” 를 D-10 구현의 **0단계**로
  명시해야 결정이 실행 가능해진다. 결정 변경 요구가 아니라 **구현 순서 요구**다.
- **부록 B-1 vs BP-10 §7.5** — 부록은 “74종(id 1~74) 기준” 을 지시하고 BP-10 은 “75종 기준” 을 선언했다.
  부록이 규범이므로 본문이 따라야 한다. 부록 B-1 자체에 결함은 없다(`battle.dart:44` 의 `<= 0` 가드를 직접 확인).
