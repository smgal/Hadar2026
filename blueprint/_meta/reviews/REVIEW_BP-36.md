## 1. 치명 결함

### F-36-01 §5 의 region 200~255 트리거가 **현행 런타임에서 동작하지 않는다는 전제**를 밝히지 않았다
- **위치**: §5 전체(§5.1~§5.3), §3.4 표의 `V-MAP-017`, §10.1 "실측으로 정정한 것" 2번
- **문서 주장**: region 200~255 를 콘텐츠 트리거 예약 구간으로 삼고, 팔레트·`validateMap`·캔버스 해칭으로 지원한다. §5.3 의 경고 문구는 "region {v} 는 예약 대역인데 **앵커가 없습니다 — 아무 일도 일어나지 않습니다**" 로, **앵커가 있으면 일어난다**는 함의를 준다.
- **실측 (런타임)**:
  - `hadar2026_app/lib/application/map_loader.dart:44` — `map.data[index].ixEvent = _getLayerData(rawData, 5, index, size);` → region 원시값(0~255)이 그대로 `ixEvent` 에 들어간다.
  - `hadar2026_app/lib/domain/map/tile_properties.dart:187-193` — `int eventType = unit.ixEvent & 0x00FF0000;` 로 **상위 바이트만** 본다. region 200(=0xC8)은 마스크 결과가 0 이므로 `event` 가 **나오지 않고** obj/tile 규칙으로 흘러간다.
  - 게다가 `server/ai_api.ts:94` 가 region 값을 0~255 로 강제하므로 `0x00010000` 을 직접 심을 수도 없다.
- **실측 (에디터 자신)**: R-36-11 은 판정 함수가 `src/rules.ts` 의 `unitAction` 과 `anchor_rules.ts` 의 `requiredActionFor(kind)` 한 쌍뿐이라고 확정했는데, **`unitAction(rawGround, ixObj1, eventType)` 은 region 을 인자로 받지 않는다**(`rules.ts:125-137`). 즉 §3.4 표가 `V-MAP-017`(trigger 의 region 200~255)을 **로컬 ✅ / 서버 ✅ "동상"** 으로 표시했지만, 현재 규칙 함수로는 **로컬도 서버도 판정할 수 없다.**
- **파급**: E2 단계(§9.1)가 "region 예약 팔레트·validate" 를 앵커 UI 보다 **먼저** 놓았는데, 그 기능이 게임에서 무효인 데이터를 사람이 열심히 칠하게 만든다. [BP-91 W-04] 가 이미 "서버와 런타임이 다르게 판단한다" 로 같은 뿌리를 적발했다.
- **요구 조치**: ① §5.1 머리에 "**선결: `map_loader` 의 `ixEvent` 승격(`ixEvent = 0x00010000 | region` 류) 없이는 게임에서 발동하지 않는다**(소유: [BP-26 §3.5 T1])" 를 명시. ② §3.4 표의 `V-MAP-017` 행을 "로컬 ❌(규칙 함수가 region 을 안 봄) → `anchor_rules.ts` 가 region 을 별도로 읽어야 함" 으로 정정. ③ §5.3 의 경고 문구에 "**로더 수정 전에는 앵커가 있어도 발동하지 않음**" 을 넣거나, T1 미완료 시 그 경고를 띄우지 않을 것.

## 2. 중요 결함

### F-36-02 [BP-31] 과 "맵 파일 쓰기 경로" 원칙이 정면 충돌
- **BP-36 §9.2 D3**: "**맵 파일 쓰기 경로를 늘리지 않는다.** 앵커 편집이 맵 파일을 건드리는 유일한 경로는 기존 `POST /api/ai/maps/{file}/edit` 다. 신규 쓰기 함수를 만들지 않는다."
- **[BP-31]**: `POST /api/content/anchors`(`tilePlaced`), `POST .../anchors/{id}/move`(`tileOps`), 배치 op `set_tile`(§3.2 13번) 이 **콘텐츠 API 안에서 맵 파일을 쓴다.** [BP-31 Q-31-4] 는 이를 인지하고 **유지**로 결론.
- 두 장이 같은 사실을 반대로 규정하므로 구현자가 판단할 수 없다.
- **요구 조치**: "콘텐츠 API 는 **내부적으로 기존 `applyOps`/`writeMapFile` 을 호출**하고 새 쓰기 함수를 만들지 않는다" 로 통일하면 양쪽이 모두 만족된다. D-18 표에 소유가 없으므로 메인 중재 필요.

### F-36-03 R-36-42 가 기존 응답 스키마를 바꾸는데 그 파급을 다루지 않았다
- **R-36-42**: `GET /api/ai/maps` 응답에 `registeredAs`, `nameResolves` 를 추가.
- **실측 파급**: 이 응답은 (a) MCP 도구 `list_maps`(`mcp/server.mjs:79-81`), (b) 브라우저 `GET /api/maps`(`vite.config.ts:34-42`)와는 별개이나 `listMapFiles`(`store.ts:90-120`)를 공유, (c) **`openapi.yaml` 의 `MapListItem` 스키마**(37KB, 손 관리)가 전부 영향을 받는다. `API_MANUAL.md:91` 이 "스펙과 실제 동작이 다르면 실제 코드가 우선" 이라 적었지만, 스펙 갱신을 태스크로 남기지 않으면 그 경고가 그대로 재발한다.
- **요구 조치**: §10.2 에 "`openapi.yaml` 의 `MapListItem`·신규 `/api/ai/mapinfos` 2종 추가(소유: [BP-35] 문서 게이트)" 를 넣을 것. 현재는 `openapi.yaml` 이 §1.1 표에만 등장하고 확장 계획이 없다.

### F-36-04 §8.3 신규 엔드포인트 2개가 `/api/ai/*` 인데 [BP-31] 의 31 라우트 표에도, `AI_GUIDE.md` 개정안에도 없다
- `GET /api/ai/mapinfos`, `POST /api/ai/mapinfos/repair` 는 **맵 API 표면**에 붙는다(옳은 판단 — 맵 데이터 문제이므로). 그런데:
  - `GET /api/ai` 가 반환하는 `AI_GUIDE.md`(114줄)에 이 두 라우트가 추가돼야 에이전트가 발견할 수 있다. R-36-31 이 `registerAs` 설명 보강만 지시하고 **두 신규 라우트의 가이드 등재는 지시하지 않는다.**
  - MCP 도구도 없다. T-36-2 는 `palette`/`get_event` 2종만 추가해 15→19 라 했는데(15+2=17 이지 19가 아니다 — **산술 불일치**), `mapinfos`/`repair` 를 넣으면 19가 맞는다. 의도가 그것이라면 본문에 적어야 한다.
- **요구 조치**: ① R-36-31 을 "AI_GUIDE.md 에 `registerAs` 보강 + `/api/ai/mapinfos`·`/repair` 절 신설" 로 확장. ② T-36-2 의 "15 → 19" 를 구성 4종(`palette`, `get_event`, `mapinfos`, `mapinfos_repair`)으로 명시.

### F-36-05 R-36-9/10(앵커는 로컬 undo 대상 아님)과 §2.5(빈 칸 클릭 = 이동)의 조합이 위험하다
- §2.5: "앵커 레이어에서 **빈 칸 클릭** + 앵커 선택 중 → 선택 앵커를 그 칸으로 이동".
- R-36-9: 앵커 이동은 **서버 커밋**이며 로컬 undo 불가. 되돌리기는 인스펙터의 `[방금 이동 취소]` 버튼 1개.
- 즉 **오클릭 한 번이 즉시 서버 쓰기**를 일으키고, 되돌림 수단은 버튼 1개(= 직전 1회만). 기존 이벤트 레이어는 로컬 undo 로 보호되므로 **같은 조작이 앵커에서만 위험도가 다르다.** §4.2 다이얼로그는 `[이 칸으로]` 경로에만 있고 클릭 이동 경로에는 없다.
- **요구 조치**: 클릭 이동에도 §4.2 확인 다이얼로그를 태우거나(권장), `[방금 이동 취소]` 를 **스택**(최근 N회)으로 둘 것.

### F-36-06 D-26 미반영 — `PROVEN + UNSUPPORTED` 표시
- `grep D-26` 결과 이 장에 **0건**. §6.2 그래프 창의 "문제 목록" 과 §3.3 상태바가 **하드 게이트 위반만** 표시하는데, D-26 은 "모델 증명은 됐지만 **발행 지점이 없어 실행 불가**(`UNSUPPORTED`)" 라는 제3의 상태를 도입했다. 에디터가 이를 표시하지 않으면 사람이 "통과했다" 고 오해한다.
- **요구 조치**: §6.2 문제 목록에 `UNSUPPORTED` 배지(예: 회색 자물쇠 + "미활성 팩") 1행 추가. 판정은 [BP-34] 소유이므로 표시만.
