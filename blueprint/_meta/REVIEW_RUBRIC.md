# 검수 루브릭 (제작 ↔ 검수 분리 규약)

검수 에이전트는 **제작에 참여하지 않는다.** 문서를 직접 고치지 않고 **검수 보고서만** 쓴다.
보고서는 `blueprint/_meta/reviews/REVIEW_<문서ID>.md` 에 저장한다. 수정은 제작 에이전트가 한다.

## 검수 대상 자료
검수자는 반드시 다음을 먼저 읽는다: `_meta/GROUND_TRUTH.md`, `_meta/DECISIONS.md`, `_meta/OUTLINE.md`,
그리고 **실제 소스 코드**(문서의 코드 주장을 직접 대조하기 위해).

## 7개 평가 축 (각 0~5점, 정수)

| 축 | 이름 | 5점 기준 | 0~1점 기준 |
|---|---|---|---|
| A | **사실 정확성** | 모든 코드 주장이 실제 파일과 일치. 파일:줄 인용이 실제로 그 내용임 | 존재하지 않는 클래스·필드·경로를 사실처럼 서술 |
| B | **결정 정합성** | DECISIONS.md 의 D-nn 을 정확히 따르고, 다른 장과 용어·필드명이 일치 | 확정 결정을 임의로 변경·모순 |
| C | **구현 가능성** | 이 문서만 보고 코드를 짤 수 있음. 스키마·시그니처·순서·예외까지 확정 | "적절히 처리한다" 류의 미확정 서술이 핵심에 남아 있음 |
| D | **완결성** | 담당 절이 모두 있고, 경계 조건·실패 경로·마이그레이션까지 다룸 | 절 누락, 행복 경로만 서술 |
| E | **검증 가능성** | 각 주장에 대응하는 테스트·린트·게이트가 명시됨 | 검증 방법이 없음 |
| F | **비중복·연결성** | 다른 장 내용을 복사하지 않고 링크. 링크가 실제 파일을 가리킴 | 같은 스키마를 재정의해 SSoT 를 깸 |
| G | **문서 규약·분량** | 메타 블록, ID 접두사, 표/다이어그램 비중, 최소 줄 수 충족, 말미 3절 요약 | 규약 무시, 분량 미달, 산문 나열 |

**합격선**: 모든 축 3점 이상 **그리고** 총점 26점 이상(35점 만점). 하나라도 2점 이하면 `수정 필요`.

## 검수자가 반드시 하는 기계적 검사

1. **줄 수**: `wc -l` 로 최소 분량 충족 확인.
2. **코드 인용 검증**: 문서가 인용한 `파일:줄` 을 **최소 10곳 샘플링해 실제로 열어** 대조. 하나라도 틀리면 축 A 는 3점 이하.
3. **링크 검증**: 문서 내 상대 링크가 가리키는 파일이 존재하거나 OUTLINE.md 에 계획된 파일인지 확인.
4. **식별자 검증**: 문서가 쓰는 op/do/필드명이 DECISIONS.md D-05/D-06/D-07 목록과 정확히 일치하는지 대조. 오탈자·임의 추가 적발.
5. **중복 검사**: 다른 장이 담당하는 스키마를 재정의했는지 `grep` 으로 확인.
6. **미확정 표현 검사**: "적절히", "추후", "등등", "TBD" 가 핵심 명세에 남아 있는지 grep.

## 검수자가 하지 말 것
- 문서 파일 수정 (읽기 전용으로 대할 것)
- DECISIONS.md 의 결정을 뒤집는 요구 (결정에 결함이 있다고 판단되면 보고서 말미 "결정 재검토 요청" 절에 근거와 함께 기록만)
- 취향 수준의 문장 다듬기 요구 (축 G 는 규약·분량만 본다)
