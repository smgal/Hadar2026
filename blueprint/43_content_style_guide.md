| **시제** | 현재·미래는 현재형, 회상은 과거형. 지문 시제(§2.2)를 대사에 끌어오지 않는다 |
| **문장 길이** | 권장 28자, 상한 45자 — 수치는 [BP-24 §24.5.5](24_dialogue_model.md) 소유(§6) |
| **한 노드 줄 수** | 권장 6줄 이하 — 동상 |
| **말줄임** | `...` 을 쓴다. `…`(U+2026) 을 쓰지 않는다 — 원작이 전부 마침표 3개다(O-6) |
| **강조** | `@B`(시안)만. 한 문자열에 색 구간 **2개 이하**를 권장 |

- **R-43-3** 한 인물의 화계는 액터의 `_voice` 필드([BP-22 §5.1](22_world_bible_model.md))에 **한 문장으로 적어** 고정한다.
  예: `"로어성 성문 위병. 합쇼체. 문장이 짧고 사무적. 사적인 말을 먼저 꺼내지 않는다."`
- **R-43-4** `?`/`!` **앞에 공백을 넣지 않는다.** 원작 습관(O-7)이지만 이것은 **오탈자 계열**이며,
  줄바꿈이 어절 단위(§6.2)라 `말이오 ?` 는 `?` 만 다음 줄로 떨어질 수 있다. 신규 텍스트는 `말이오?`.
  기존 원작 문자열을 이관할 때는 **공백을 제거**한다.

### 2.2 지문·서술 (`Node.lines` 중 화자 없는 줄, `@7` 회색)

| 축 | 규칙 |
|---|---|
| **주어** | `일행` 또는 `당신`. 3인칭 관찰자를 쓰지 않는다 |
| **어미** | **평서 과거 완료** — `~하였다`, `~였다`, `~았다/었다`, `~보였다` (O-3) |
| **색** | `@7 … @@` 로 감싼다. 지문임을 색으로 표시하는 것이 원작 관례 |
| **감정 서술** | 하지 않는다. **관찰 가능한 사실만.** `무서웠다`(×) → `등 뒤에서 소리가 났다`(○) |
| **길이** | 대사와 같은 상한 |

- **R-43-5** 지문에 **플레이어의 감정·판단을 대신 서술하지 않는다.** 원작 지문은 전부 관찰이다
  (인용 18·19). 감정을 대신 정하면 2인칭 게임에서 이질감이 크다.

### 2.3 저널 (`journal`, `summary`)

| 축 | 규칙 |
|---|---|
| **인칭** | 무주어 또는 `일행`. `나는`(×) |
| **어미** | **평서 과거 완료** — 이미 한 일을 적는 기록이므로 |
| **다음 행동** | 명령형이 아니라 **사실 진술**로 암시. `문지기에게 가시오`(×) → `문지기는 인장을 지닌 자만 들여보낸다`(○) |
| **길이** | [BP-41 §41.4](41_journal_ui_spec.md) 소유 |
| **어휘** | `퀘스트`/`저널`/`미션`/`오브젝티브`/`리워드` 금지([BP-40 R-40-5](40_gameplay_changes.md)) |

- **R-43-6** 저널은 **인물의 목소리를 갖지 않는다.** 누가 썼는지 알 수 없는 기록이며,
  따라서 하오체·합쇼체를 쓰지 않는다. [BP-41 §41.8.3](41_journal_ui_spec.md) 목업의
  `수감소 병사는 인장을 지닌 자만 들여보낸다.` 가 이 규범의 예다.

### 2.4 아이템 설명 (`desc`)

| 축 | 규칙 |
|---|---|
| **구성** | **2문장**. ① 무엇인가(생김새·유래) ② 무엇에 쓰이는가·평가 |
| **어미** | 평서 현재 `~이다`/`~다`. 단 **판매자의 말투로 한 문장을 끝내는 것**을 허용 — `맛은 기대하지 마시오.` |
| **길이** | 한 문장 28자 이하 권장, 2문장 합쳐 2행 이내([BP-42 §5.2](42_item_and_inventory.md) 목록 화면 설명 2행) |
| **성능 수치** | **적지 않는다.** `공격력 +15`(×). 성능은 화면이 따로 보여 준다 |
| **장비 표시명** | 8자 이하([BP-42 R-42-43](42_item_and_inventory.md)) |

원작 유일한 실제 설명문(`books.json` 맨손, §1.2 밖):

> `무기를 장착하지 않은 상태이다. 일반적으로는 무기가 없는 상태라면 전투에 불리하지만 맨손 격투에 자신이 있다면 맨손도 좋을 것이다.`

- **관찰 O-10**: 원작 아이템 설명은 **"상태 서술 + 조건부 평가"** 구조다. `~이다` + `~할 것이다`.
- **R-43-7** [BP-42 §7.4](42_item_and_inventory.md) 의 20종 설명 초안이 이 규칙의 적용례다.
  예: `삶은 가죽을 덧댄 갑옷. 값에 비해 든든하다.` — 유래 + 평가, 수치 없음, 각 문장 15자 이하.

### 2.5 시스템 메시지

**이미 코드가 정한 문체가 있다.** 새로 정하지 않고 **맞춘다**.

| 종류 | 원작 형태 | 출처 |
|---|---|---|
| 메뉴 항목 | **동사형 평서** — `일행의 상황을 본다`, `여기서 쉰다`, `마법을 사용한다` | `menu_flows.dart:36-42` |
| 메뉴 제목 | 명령형 하오체 — `당신의 명령을 고르시오 ===>` | `menu_flows.dart:35` |
| 선택 질문 | `~겠습니까 ?` + `예` / `아니오` (또는 `예, 그렇습니다.` / `아니오, 원하지 않습니다.`) | `ground1.cm2:9-11`, `menace.cm2:16-18` |
| 결과 통지 | 평서 과거 — `무사히 도망쳤다...`, `일행은 식량이 바닥났다` | `battle.dart:270`, `menu_flows.dart:170` |
| 상태 라벨 | 한자어 2~3자 + 콜론 — `체력 :`, `정신력 :`, `민첩성 :`, `## 경험치 :` | `menu_flows.dart:248-273` |
| 오류·거부 | 평서 현재 — `당신은 파티를 떠날 수 없습니다.` | `menu_flows.dart:384` |

- **R-43-8** 신규 메뉴 항목은 **`~한다` 동사형 평서**다. [BP-40](40_gameplay_changes.md) 이 정한
  `소지품을 살핀다` / `임무를 확인한다` 가 그 적용례다.
- **R-43-9** 신규 선택 질문은 **`~겠습니까?`** 로 끝내고 답은 `예`/`아니오` 를 기본으로 한다.
  긴 답변형(`예, 그렇습니다.`)은 무게가 있는 결정에만 쓴다.
- **R-43-10** 시스템 메시지에 **인물의 화계를 섞지 않는다.** 시스템은 하오체를 쓰지 않는다 —
  단 하나의 예외가 메인 메뉴 제목(`고르시오`)이며, 그것은 원작 유산이므로 **바꾸지 않는다**.

| **계열** | 인명은 **고유어 느낌의 무의미 조합** 또는 로마자. 지명은 **한자어 또는 로마자 음차** | 슴갈(고유어형) / 메너스(음차) |
| **금지** | 실존 인물·브랜드·현대 지명, 다른 게임의 고유명사, 한국 현대 인명(민준·서연 등) | — |
| **마법·기술명** | **한자어 2음절 + 한자어 2음절** 구조를 따른다(O-11) | `직격 뇌전` 형 → `역장 차폐`, `광역 마비` |
| **조직명** | `LORE 특공대` 형 — **고유명사 + 보통명사**. 새 조직도 이 형태 | `메너스 광부대` |
| **충돌 회피** | 신규 이름은 ① 기존 고유명사 목록(§4.1) ② 적 74종 이름(+ `enemyTable` id 0 `Orc` 포함 **75엔트리**) ③ 마법 45종 이름 ④ 아이템 카탈로그 이름 과 **완전 일치 금지**. 기계가 검사한다(M-10) | — |
| **혼동 회피** | 기존 **인명·지명·조직명**과 헷갈릴 만큼 닮은 이름을 만들지 않는다. `메너스`가 있으면 `메너드`를 만들지 않는다 | — |

- **R-43-13a** (F-05) **"첫 2음절 일치 금지" 를 기계 규칙으로 만들지 않는다.** 기존 데이터가 이미
  대량으로 위반하기 때문이다 — 실측:

  | 계열 | 첫 2음절을 공유하는 기존 이름 |
  |---|---|
  | 마법 | `마법 화살` · `마법 화구` · `마법 단창` · `마법 불능` (4건, "마법" 공유) |
  | 마법 | `한명 치료` · `한명 독 제거` · `한명 치료와 독제거` · `한명 의식 돌림` · `한명 부활` · `한명 복합 치료` (6건) |
  | 마법 | `모두 치료` · `모두 독 제거` · `모두 치료와 독제거` · `모두 의식 돌림` · `모두 부활` · `모두 복합 치료` (6건) |
  | 적 | `Giant` / `Giant Spider` / `Giant Rat`, `Blood Bat` 계열 |

  마법·기술명은 **"한자어 2음절 + 한자어 2음절"** 구조를 따르라고 이 장이 직접 요구하므로(O-11, §4.3),
  첫 2음절 공유는 **위반이 아니라 정상**이다. 규칙을 명세대로 구현하면 신규 이름 대부분이 WARN 을 받고,
  이 장이 R-43-25 에서 경계한 상황("오탐이 쌓이고 WARN 밀도만 올려 경고 전체가 무시된다")이
  바로 이 규칙에서 발생한다.
- **R-43-13b** 따라서 **혼동 여부는 Critic 의 판단 영역**(§7.4)이다. 기계는 **완전 일치만** 본다.
  판단 대상도 **인명·지명·조직명**(§4.1 의 인물 8 · 지명 8 계열)으로 한정하고,
  적 이름·마법명은 구조상 유사가 정상이므로 혼동 심문에서 제외한다.

- **R-43-13** 신규 고유명사는 **팩 안에서 유일**해야 하고, 표시명(`str.*.name`)과 슬러그(`item.<pack>.<slug>`)가
  **1:1** 이어야 한다. 슬러그는 영문 소문자(D-04), 표시명은 한글/로마자.
- **R-43-14** 생성 에이전트는 신규 고유명사를 **outline 단계(2단계)에서 확정**하고
  draft 단계(3단계)에서 새로 만들지 않는다. 3단계에서 만든 이름은 §4.3 충돌 검사를 못 거친다.
- **R-43-15** 신규 고유명사 개수 상한: **퀘스트 1건당 신규 인명 2개, 신규 지명 1개.**
  넘으면 독자가 이름을 못 외우고, 세계가 넓어지는 대신 **얇아진다**.

## 5. 화자별 톤 — 예문 3개씩

`role` 값은 [BP-22 §5.2](22_world_bible_model.md) 의 닫힌 집합을 쓴다.

### 5.1 병사·위병 (`soldier` / `guard`)

**규범**: 합쇼체. 문장 2개 이내. 사적인 말을 먼저 꺼내지 않는다. 거절이 본업이다.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `물러나십시오. 여기는 들어갈 수 없습니다.` | 21 |
| 2 | `허락받지 않은 자는 통과할 수 없습니다.` | 20 |
| 3 | `인장을 보여 주십시오. 없으면 돌아가십시오.` | 22 |

원작 대응: 인용 7·9·10.

### 5.2 상인·주인 (`merchant` / `innkeeper`)

**규범**: 합쇼체 + 권유형. 첫마디는 환대. 값을 말할 때만 숫자를 쓴다.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `어서 오십시오. 여기는 로어 주점입니다.` | 20 |
| 2 | `마침 좋은 방이 하나 남아 있습니다.` | 18 |
| 3 | `이용해 주셔서 감사합니다. 또 오십시오.` | 20 |

원작 대응: 인용 1, `L1_ep1d0.cm2:29,38,39`.

### 5.3 학자·기록자 (`scholar`)

**규범**: 합쇼체. 문장이 길어도 된다. 단정 대신 **추정** — `~인 듯합니다`, `~라 전해집니다`.
자기가 아는 범위를 명시한다.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `그 문헌은 가라앉은 대륙의 것이라 전해집니다.` | 23 |
| 2 | `제가 아는 것은 여기까지입니다.` | 15 |
| 3 | `기록이 끊긴 해가 언제인지는 확실치 않습니다.` | 23 |

- **R-43-16** 학자는 **모르는 것을 모른다고 말한다.** 지식 범위([BP-22 §5.4](22_world_bible_model.md))를
  가장 자주 어기는 화자이므로, `_voice` 에 "아는 범위를 먼저 밝힌다" 를 명시한다.

### 5.4 농부·촌민 (`commoner`)

**규범**: 합쇼체 또는 반말 혼재. 소문을 옮긴다. 단정하지 않고 `~다던데`, `~라던데` 로 끝낸다.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `요새 무덤쪽에서 유령이 떠돈다던데...` | 19 |
| 2 | `메너스에는 금덩이가 많다던데...` | 16 |
| 3 | `우리는 동쪽 나무에서 식량을 얻습니다.` | 19 |

원작 대응: 인용 2, `lore_ep1.cm2:146,39`.

### 5.5 귀족·성주 (`noble`)

**규범**: **하오체**. 문장이 길고 서사적. 명령이 아니라 위임 — `~해 주시오`, `~부탁하건데`.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `나는 '@BLord Ahn@@' 이오.` | 15(태그 제외 12) |
| 2 | `그 동굴을 중심부까지 탐사해 주시오.` | 18 |
| 3 | `당신들의 잠재력을 증명할 기회가 될 것이오.` | 22 |

원작 대응: 인용 14, `town2.cm2:236,238`.

### 5.6 적대자 (`boss` / 적대 세력)

**규범**: 하오체 또는 반말. **위협하되 욕하지 않는다.** 원작 악역은 예의를 갖춘 채 적대한다.

| # | 예문 | 자수 |
|---|---|---|
| 1 | `다시 돌아오다니, 어리석은 일이오.` | 17 |
| 2 | `이번에는 기어이 네놈들을 해치우고야 말겠다.` | 22 |
| 3 | `당신들과는 결투로 승부할 수밖에 없군요.` | 20 |

원작 대응: `town2.cm2:290,291,294`.

### 5.7 예외 화계 (`allowedRegisters`)

[BP-22 §2.4](22_world_bible_model.md) 의 `allowedRegisters: ["drunk_slur","child_plain","guard_curt"]` 가 허용하는 이탈.

| 화계 | 허용되는 것 | 예 |
|---|---|---|
| `drunk_slur` | 말 흐림, 반복, `...` 남발 | `... 끄~~윽 ... ...` (인용 4) |
| `child_plain` | 해요체, 짧은 문장 | `아저씨, 저기 무서운 거 있어요.` |
| `guard_curt` | 문장 1개, 주어 생략 | `못 지나갑니다.` |
| (광인) | `히히히`, `낄낄낄` 류 (인용 17) | `_voice` 에 명시된 인물만 |

- **R-43-17** 예외 화계는 **액터의 `traits` 에 근거가 있어야** 쓴다(`drunk`, `child` 등).
  근거 없이 이탈하면 Critic Q2(목소리)에서 감점 대상이다.

## 6. 길이 규범 — 문체의 관점에서

### 6.1 수치는 남의 것

| 대상 | 수치의 정본 |
|---|---|
| 대사 1줄 · **공백 없는 어절** · 선택지 · 선택지 제목 행 · 헤더 · `lines[]` 항목 수 | [BP-24 §24.5.5](24_dialogue_model.md) 의 6행 표 (권장/경고/에러 3구간) |
| 저널 각 행 | [BP-41 §41.4](41_journal_ui_spec.md) |
| 위 수치의 린트 규칙 번호·심각도 | [BP-33 `V-L4-027`~`V-L4-038`](33_validation_and_lint.md) |

**이 절은 수치를 옮겨 적지 않는다**(D-18·D-25). 초판이 6행을 전재했고 값은 전부 정확했지만,
BP-24 가 수치를 조정하면 이 장이 조용히 어긋난다 — 전재 자체가 오류원이다(D-20a 의 교훈).
대신 이 절이 다루는 것은 **"그 안에 담는 요령"**(§6.3)이며, 그것이 이 장의 소유다.

**요령을 읽기 위해 알아야 할 것 하나**: 어절 상한이 **줄 상한보다 먼저 터진다.** 공백 없이 이어지는
한 덩어리가 길면 렌더러가 나눌 자리를 못 찾아 잘린다 — 그래서 §6.2 가 어절을 먼저 다룬다.

### 6.2 왜 어절 30자가 치명적인가

```dart
// hadar2026_app/lib/utils/hd_text_utils.dart  splitToLines
final words = text.split(' ');       // ← 공백으로만 어절을 나눈다
...
if (currentLineWidth + wordWidth > maxWidth && currentLineChildren.isNotEmpty) {
  // 줄바꿈
}
```

- 한 "어절"(공백 없는 연속 구간)이 480px 를 넘으면 **줄이 나뉘지 않고 그대로 넘쳐 잘린다.**
- 한글 16pt 전각 ≈ 16px → **30자 = 480px**. 즉 **공백 없이 30자를 쓰면 화면 밖으로 나간다.**
- 한국어는 **조사가 붙어 어절이 길어지기 쉽다.** 특히 로마자 고유명사 + 긴 한자어 복합어 조합이 위험하다.

**실제 위험 사례** (원작에서 계산)

| 어절 | 자수(한글 환산) | 판정 |
|---|---|---|
| `Necromancer에게` | 12 | 안전 |
| `또다른지식의성전이라는` | 11 | 안전 |
| `LORE왕립죄수수용소에서는` | 15 | 안전 |
| `공무집행방해행위로간주하겠습니다` | 16 | 안전 |
| (가상) `초고대문명유산발굴조사단소속연구원이었습니다` | **23** | 경고 구간 |

→ 실제로 30자를 넘기려면 **일부러** 붙여 써야 한다. 그러나 **AI 는 한자어 복합명사를 붙여 쓰는 경향이 있다.**

### 6.3 45자 안에 담는 요령 8가지

| # | 요령 | 전 (자수) | 후 (자수) |
|---|---|---|---|
| 1 | **한 문장 = 한 줄.** 두 문장이면 `lines[]` 항목을 나눈다 | `제 남편이 돌아오지 않습니다. 사흘 전에 메너스로 떠난 뒤로 소식이 없습니다.` (38) | `제 남편이 돌아오지 않습니다.` (15) + `사흘 전에 메너스로 떠났습니다.` (16) |
| 2 | **수식어를 뺀다.** 형용사 하나가 대개 5~8자 | `무척이나 위험하고 어두운 그 굴에는` (18) | `그 어두운 굴에는` (9) |
| 3 | **한자어 복합어를 풀어 쓴다** — 붙여 쓰면 어절 위험도 함께 는다 | `무기고출입허가증명서` (10, 한 어절) | `무기고에 드는 표` (8, 세 어절) |
| 4 | **주어를 생략한다.** 앞줄에서 이미 밝혔으면 다시 쓰지 않는다 | `저는 이 성의 기사입니다. 저는 대륙을 돌았습니다.` (26) | `이 성의 기사입니다.` + `대륙을 돌고 왔습니다.` |
| 5 | **`~라고 하는` 을 `~라는` 으로** | `Necromancer라고 하는 자가` (14) | `Necromancer라는 자가` (12) |
| 6 | **긴 로마자 고유명사는 한 줄에 하나만** | `Necromancer와 Ancient Evil이 대립했소.` (25) | `Necromancer가 있었소.` + `Ancient Evil도 있었소.` |
| 7 | **숫자를 한글 수사로** — 대사 안에서는 오히려 짧아지는 경우가 있다 | `3일 전에 5명이` (8) | `사흘 전에 다섯이` (8) — 자수는 같지만 문체가 맞는다(F-13) |
| 8 | **색 태그는 폭 0이지만 문자열 길이에 포함된다** — 45자 검사는 **한글 환산 길이**를 쓰므로 태그는 빠지지만, `_lintIgnore` 로 넘기려 하지 말 것 | `@B황금의 방패@@를 찾으시오.` (환산 12) | 그대로 안전 |

- **R-43-18** **줄을 나눌 수 있으면 나눈다.** `lines[]` 항목 하나를 45자에 꽉 채우는 것보다
  15자짜리 세 항목이 낫다. 콘솔은 항목마다 줄을 바꾸고, 원작 대사도 그렇게 되어 있다(인용 21·22).
- **R-43-19** **선택지는 18자 안에 끝낸다.** 원작 선택지가 그 안에 있다 —
  `예, 그렇습니다.`(8) · `아니오, 원하지 않습니다.`(13) · `그렇다면 당신을 받아들이지요`(15) ·
  `당신은 이곳에 그냥 있는게 낫겠소`(17). **18자는 원작이 실제로 지킨 폭이다.**
- **R-43-20** 원작 대사 중 400자를 넘는 것이 여럿 있다(인용 5·15·16, [BP-21 §5.5](21_content_pack_spec.md)).
  **이관은 허용**하되(D-17: 원작 이식을 막지 않는다) **신규 생성물에는 적용하지 않는다.**
  신규는 R-43-18 을 따른다.

## 7. 기계 검사 규칙 vs 에이전트 판단 규칙

### 7.1 경계 (이미 확정된 것을 지킨다)

[BP-37 §37.5.2](37_prompt_contracts.md) 와 [BP-32 R-32-22](32_generation_harness.md) 가 확정한 것:

| 확정 | 내용 |
|---|---|
| Critic 은 **Hard gate 판정 권한이 없다** | Critic 이 "이 참조는 깨졌다" 고 해도 5단계가 통과시켰으면 통과다 |
| Critic 의 관할은 **Soft 8축뿐** | `Q1_lore … Q8_integration` |
| **기계는 8축을 점수화하지 않는다** | 루브릭 점수는 LLM Critic 이 매긴다 |
| 문체·톤은 **Soft** — `Critic Q6` + StyleEditor **공동** | 기계 린트는 여기에 **입력을 제공**할 뿐 판정하지 않는다 |
| 길이 상한 초과 0 은 **Hard** — 5단계 `DV-08~10` | 기계 단독 판정 |

- **R-43-21** **이중 판정을 만들지 않는다.** 같은 문체 위반을 기계가 ERROR 로 막고 Critic 이 다시 감점하면,
  통과한 것은 두 번 안전하고 걸린 것은 두 번 벌 받는다. 규칙마다 **판정 주체가 정확히 하나**여야 한다.
- **R-43-22** 아래 §7.2 의 규칙은 [BP-33](33_validation_and_lint.md) 이 **ID·심각도·메시지를 확정**한다.
  이 장은 **검사 내용과 심각도 제안**만 낸다(R-33-8: 원 장이 알고리즘, BP-33 이 심각도).

### 7.2 기계 검사 가능 — BP-33 에 넘기는 후보 12건

**개정 2판이 고친 3건 — 무엇이 왜 동작하지 않았나**

| # | 초판 명세 | 왜 동작하지 않는가 | 개정 |
|---|---|---|---|
| `M-8` | 어미 사전에 **`~다` 포함** | `~다` 는 과거 완료 종결만이 아니라 **현재형 평서 종결의 어미이기도** 하다(`~한다`, `~이다`). 사전에 `~다` 가 있으면 검사가 **모든 평서문을 통과**시킨다 — 참을 반환하는 것이 아니라 **아무것도 걸러내지 못한다.** 예: `등 뒤에서 소리가 난다.` → `~다` 로 끝나므로 통과. 그러나 O-3·R-43-5 위반 | 사전에서 `~다` 를 빼고 **과거 표지가 있는 것만** 남긴다: `~였다 / ~았다 / ~었다 / ~하였다 / ~보였다 / ~있었다 / ~졌다 / ~ㄴ다는 것이었다`. §7.3 의 어미 사전을 **화계 분류용(M-7)** 과 **지문 검사용(M-8)** 두 행으로 **분리**한다 — 한 사전을 두 규칙이 서로 다른 의미로 쓰고 있었던 것이 결함의 뿌리다 |
| `M-10` | 완전 일치 **또는 첫 2음절 일치** | 기존 마법명 45종·적 이름이 이미 첫 2음절을 대량으로 공유한다(§4.3 R-43-13a 실측표 16건 이상). ERROR 로 받으면 **아무 콘텐츠도 커밋할 수 없거나** 기존 이름을 고쳐야 한다. "신규에만 적용" 하려면 "무엇이 신규인가" 의 기준선(`pack.json` baseline 버전 등)이 필요하고 그 필드가 없다 | **완전 일치만** 기계 검사로 남긴다. 혼동 유사성은 §7.4 의 Critic 판단으로 이관하고, 판단 대상을 **인명·지명·조직명**으로 한정한다 |
| `M-12` | `[0-9]+\s*(공격력\|방어력\|점\|골드\|gold)` | 한국어에서 성능 수치는 **라벨 + 숫자** 순서(`공격력 30`, `방어력 5`)인데 정규식은 **숫자 + 라벨** 순서만 잡는다. 이 장 자신의 대표 위반 예시(§8 #17 `강철 검. 공격력 30, 값 600 골드.`)에서 `600 골드` 만 매칭되고 **`공격력 30` 은 놓친다.** F-17 이 제시한 `강철 검. 공격력 30, 값 600.` 은 **완전 미매칭**이다. 또 `점` 은 지나치게 넓어 오탐을 부른다 | **1차 판정을 "숫자 존재" 로 단순화**한다. R-43-7 이 아이템 설명에 성능 수치를 금지하고 F-13 이 대사 안 아라비아 숫자를 금하므로, `desc` 에 숫자가 있을 이유가 없다 — 규칙이 단순해지면서 **동시에 더 정확해진다.** 라벨 매칭은 판정이 아니라 **메시지 상세**로 격하한다 |

**`M-9` 는 왜 아직 못 하는가**(등급 C, S-07)

판정 근거는 "**같은 대상**의 두 표기가 한 팩에 공존" 이다. 기계가 "같은 대상" 을 알려면
`_glossary` 가 **`{정본: [별칭…]}`** 형태여야 한다. `LORE 성` ↔ `로어성` 이 같은 곳임을
데이터가 말해 주지 않으면 검사가 성립하지 않는다.

- **R-43-12a** (S-07) `_glossary` 는 **정본 표기만으로는 부족하다.** 아래 형태를
  [BP-22](22_world_bible_model.md) 에 요청한다(스키마 소유는 BP-22 — 이 장은 **필요한 형태만** 말한다):

  로마자·한글 쌍)이다. §4.2 가 잠정 규칙으로 고른 표기가 정본이 되고 나머지가 별칭이 된다.
  BP-22 가 Q-43-1 을 결정하면 그 결과를 그대로 싣는다.

  "첫 2음절" 은 유사성의 근사치이고, 근사 규칙을 하드 게이트에 두면 이 절이 경계하는 결과가 나온다.
  Critic 프롬프트에는 **§4.1 의 기존 이름 목록**과 **이 판단의 예/반례 2쌍**을 함께 넣는다
  ([BP-37 §37.2](37_prompt_contracts.md) 의 `{{style_guide}}` 슬롯).
- **R-43-25** 위 항목은 **기계 린트 규칙으로 만들지 않는다.** 근사 규칙(예: "형용사 3개 이상이면 경고")을
  만들면 오탐이 쌓이고, WARN 밀도([BP-33 R-33-10](33_validation_and_lint.md))만 올려 경고 전체가 무시된다.
- **R-43-26** StyleEditor 는 **문장을 고칠 권한**이 있고 Critic 은 **점수와 지시만** 낸다
  ([BP-32 R-32-21](32_generation_harness.md)). 이 장은 StyleEditor 의 작업 지시서다 —
  §2·§3·§6.3 이 그대로 프롬프트에 들어간다.

### 7.5 프롬프트에 넣을 압축본 (§3 + §6.3 의 요약)
